# 模块地图

不为模块化重写业务。通过目录、依赖约束、输入输出契约和测试把现有责任说清楚。

| 模块 | 所有者目录 | 输入与输出 | 禁止越界 |
| --- | --- | --- | --- |
| 运动事实 | `FoxTrainingCore` | 关键点/时间 -> 准备、计数、恢复、阶段和报告 | 不导入 UI、相机、音频或网络；不从播报反推动作 |
| 引导策略 | `FoxTrainingCore/Guidance` | 已提交事实/目标节奏 -> 有效期受限的提示 | 不控制计数、数据库或相机；不补缺失测量 |
| 平台适配 | `FoxNative` | Apple Vision/相机/屏幕/音频 -> 核心输入；核心状态 -> UI/语音 | 不用 UI 操作重写运动事实；平台能力不能冒充核心准确性 |
| 记录与附件 | `FoxJournalCore` | 本地记录、照片、完整备份 -> SQLite/私有文件 | 不依赖训练或远端服务；不静默迁移现有训练 JSON |
| 同步传输 | `FoxSyncCore`、`scripts/sync_https.py` | 受限协议帧/可信配对证书 -> HTTPS 资料库接口 | 不拥有 Journal 事务或 UI；传输通过不等于记录已同步，不放宽 TLS 信任 |
| Web 与语音实验 | `apps/api`, `apps/web-runtime`, `packages` | API、人工确认草稿、持久化 | 不依赖真实 Linux 才能测试；不自动更改 workout state |
| Fox Say 原生壳 | `apps/ipad/FoxPad` | 独立 App 的 Web 入口、原生麦克风桥、录音上传 | 不代替 FoxNative；录音/上传/识别/入库是不同的成功条件 |
| 实验与开发证据 | `scripts`, `experiments`, 测试专用 `FoxTestSupport` | 固定输入 -> 可追溯报告/索引 | 不进产品依赖；SQLite 索引可重建，不能替代原始证据 |

完整仓库路径前缀：Swift 模块均在 `apps/ipad/`，引导策略在 `apps/ipad/FoxTrainingCore/Sources/FoxTrainingCore/Guidance/`。

## 文件放置

- `schemas/`：持久化与交换契约。策略参数跟随 Core 的 `Resources/`。
- `tests/verification/catalogue.json`：测试分类，新增/移动/删除测试必须显式审核。
- `docs/development/`：当前开发入口。`docs/fitness/`、`docs/design/` 保留设计与有日期的结果，不再不断往 README 累积状态。
- `.data/`：私人输入、设备记录、实验档案和可重建索引；禁止提交。
- `.tmp/`：构建和运行回执。失败也保留，清理前确认不是唯一证据。不同运行目录不覆盖。
- `.venv/`、`node_modules/`：可重建依赖，不复制到恢复提交。

跨模块改动需写明契约影响，并增加消费者测试。无需建立跨平台抽象层；当前仍采用 Apple Vision，未来平台扩展先复用数据与验证契约。

## 协作入口与职责

一个 Fox 项目、一个现有 Monorepo、三个专业工作线。原协调对话保留历史，用户仍可只找产品与交付。工作线不是审批链，也不是文件夹权限墙；每个任务只有一个主负责人，可以在既定授权内跨模块完成实现、测试和交接。

| 入口 | 主责 | 跨模块接口 |
| --- | --- | --- |
| Fox｜产品与交付 | 优先级、冲突、集成、候选和设备交付；统筹验证脚本、构建入口、测试基础设施 | 工具任务逐项指定实现负责人，不新增第五入口；普通修改不必经过四方审批；推送/合并/安装依各自授权 |
| Fox｜客户端与体验 | 首页、训练布局、可访问性、采集交互、UI 测试及提示呈现 | 消费运动事实与存储结果，不以 UI 修改计数/阶段；摄像头权限与预览呈现归本线，帧/关键点契约变化与视觉线共同确认 |
| Fox｜视觉与训练核心 | 视觉输入契约、准备/计数/恢复、离心测量、动作策略与录像回放；事实驱动引导策略 | 包括 Native 内的 Vision/帧时序接入，不限于 Core 目录；测量、计划节奏和播报分开，报告持久化变化需核对数据消费者 |
| Fox｜数据与服务 | 本地存储、附件、备份/导出、数据契约与服务集成 | 不迁移或重写训练事实来满足导出；采集 UI 与客户端协作，Fox Say/Web 是已有实验边界而非本轮新派工 |

## 接手与资源规则

- [个人资料库同步](../planning/PERSONAL_SYNC_V1.zh-CN.md)：数据与服务维护同步契约与服务核心，客户端后续接入本地 Journal/outbox 和配对 UI。现有 SSH 归档、Python 双副本验证、原生双设备同步分别验收，不相互冒充。
- [SYNC-3A 传输基础](../planning/PERSONAL_SYNC_NATIVE_V1.zh-CN.md)：LAN 服务与 Swift 传输已限定验收，当前尚未接入 Journal 或 App；私有连接 `~/.config/fox/sync-https.json`，不直接访问/编辑远端 SQLite。服务运行与原始资料归档分开管理。

- 共享资料查询/取回见 [Linux 资料库契约与入口](../planning/SHARED_ARCHIVE_V1.zh-CN.md)。同一 Mac 三条工作线共用私有连接配置；先按标签查询，再按稳定 ID 取回，不直接编辑服务器数据库或原件。并非自动授权处理所有私人数据，也不代表全量设备资料已归档。
- [批量资料目录](../planning/ARCHIVE_BULK_20261028.zh-CN.md)：私有 `~/.config/fox/archive-current.json` 指向有效总清单、视觉索引与 iPhone 备份图文索引。视觉先读索引，按组取录像/报告；数据线先区分备份时间与真实读取时间，不把旧快照称为手机当前状态。

- 持久指导放置：AGENTS 只放共同约定/入口；本页放职责/边界；CURRENT 是唯一现状；[原台账](../planning/LIFE_LOG_BACKLOG.zh-CN.md)放任务负责人、状态、验证与交接链接。不为四个聊天各写一份现状。
- 初次三个工作线只读接手，不编辑文档或代码、不跑构建/模拟器、不访问真机；在本聊天返回回执，由协调者读取后统一落档。候选任务不是派工。
- 最小交接内容：任务 ID 与主负责人、基线提交/实际工作区、目标和非目标、涉及模块、验证及回执、未覆盖风险、下一步。指导来源注明自动发现或人工读取，不猜测。
- 单写者覆盖同一工作树中的代码、CURRENT、台账、测试登记、工程生成和 Git 提交。读者可并行；有新写入任务时先核对活动任务，不新增常驻调度系统。需要并行写入再安排独立 worktree。
- worktree 隔离不等于资源隔离：复用 [验证约定](VERIFICATION.md) 的模拟器租约/所有权；本机重型原生构建和测试串行，设备更新由交付协调且需明确授权，不关闭他人会话。
- 跨模块普通任务由主负责人闭环，不要求每改一个文件就请另一个入口审批。只有授权范围变化、共享资源冲突、公共契约影响或集成交付时协调；用户无需搬运三个聊天的上下文。
- 项目迁移分别核对侧边栏归属、默认 pwd、Git 根目录及指导来源；显式设置工作目录仅是临时措施，不能冒充自动迁移完成。

## 归属演练

| 场景 | 主负责人 | 需要时协作 / 验收边界 |
| --- | --- | --- |
| 横屏布局调整 | 客户端与体验 | 保持事实接口；按影响做布局测试，不自动派视觉重构 |
| 弯举首轮漏计 | 视觉与训练核心 | 先事件级回放，保留侧平举及离心不变量；如需 UI 提示再协调客户端 |
| 选定记录与原附件导出 | 数据与服务 | 客户端负责交互协作；导出完整性不等于恢复/同步/AI 分析 |
| 验证脚本或构建入口故障 | 产品与交付统筹、任务内指定实现负责人 | 先区分产品/测试/环境/编排失败；不降低断言、不默认启动全部工作线 |

这四个案例用于核对接手理解，不是本轮开发任务。首个真实跨工作线任务结束后再复盘协调轮次、重复阅读和返工；当前不承诺效率提升幅度。
