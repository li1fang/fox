# 重建与验证

## Duo 布局候选

`npm run verify:duo -- <完整提交号> <新输出目录>` 固定使用 Duo + iOS 27.1，先拒绝脏候选/错误提交，再申请现有模拟器共享会话。只跑公开合成的首页、训练、视觉与自适应测试；退出清理本任务创建的设备，内盘低于 2 GiB 取消并保留回执。它是 `diagnostic/duo-layout` 专项，不代替 `verify:candidate public --component native` 的普通 iPhone/iPad 完整回归，不接收私人输入。

专项复用 `runSuite` 的源码冻结、日志摘要和精确 XCTest 覆盖检查，但不把其回执冒充 `verify:receipt --scope public --component native`。Device Hub 实际开合截图单独记录；窗口注入、旋转、模拟器开合和真机视觉是不同证据。执行路线见 [M0/M1](../planning/DUO_M0_M4.zh-CN.md)。

## 干净环境

使用 Node 22（`.node-version`），然后 `npm run bootstrap`。本地 macOS 另需 Python 3.12、Xcode 27.1 / 27A9275、XcodeGen 2.45.x，以及通用 iOS 27.0 模拟器运行时。CI 的旧版兼容通道显式指定 Xcode 26.3 / 17C529 和既有 iOS 26.4；不改变触发方式，也不把云端旧版通过当成本地新版验收。

初始化安装仓库锁定的 npm 依赖、Playwright Chromium 及 `.venv` 中的 schema 依赖；不安装/切换全局 Xcode、不读取签名账户、不连接物理设备。Python 可通过 `FOX_BOOTSTRAP_PYTHON` 指定 3.12 可执行文件。XcodeGen 使用 [官方 2.45.3 发布包](https://github.com/yonaskolb/XcodeGen/releases/tag/2.45.3)；安装及 SHA-256 校验步骤见 [CI 配置](../../.github/workflows/ci.yml)。可解压到本地工具目录并将 `xcodegen/bin` 加到当前进程 PATH，不需全局安装。不要使用会浮动升级的 Homebrew 最新版本；不匹配时检查应停止。Linux 首次运行浏览器可能还需 `npx playwright install --with-deps chromium` 安装系统库。

`npm run doctor` 输出实际 Node、npm、Python、Swift、Xcode、SDK、XcodeGen 和可用模拟器版本。`DEVELOPER_DIR` 可指向对应 Xcode。模拟器构建 Fox 和 Fox Say 不需要 Apple 账号；实际设备构建另需本地 `FOX_DEVELOPMENT_TEAM`，不能把 Team ID 提交到仓库。

本地默认 profile 为 `xcode-27.1`，只接受 27.1 / 27A9275，默认 runtime 为通用 iOS 27.0。实核 27.1 / 24A94425 只支持 Duo，不能创建普通 iPad/iPhone；它与通用 27.0 不是重复下载。Duo 诊断必须同时显式指定该 runtime 与机型，不冒充完整手机/平板覆盖。未知 profile、错误版本/build 不回退或接受“latest”。CI 在现有 YAML 中显式选择 `xcode-26.3`；仅固定兼容通道，不改触发。进程指定 `DEVELOPER_DIR`；换 profile 不会自动切换全局工具或安装 runtime。首次运行、SDK 和 runtime 可用性仍须实际核对。

profile 与 runtime 在原生预检/实际使用时解析，不在导入模块时提前失败。因此未知配置不能遮蔽正式候选的错误提交/脏工作树拒绝及零步骤失败回执；单独运行原生入口仍严格拒绝未知 profile。

本地新工具链示例（不写入全局配置）：

```sh
FOX_XCODE_PROFILE=xcode-27.1 \
DEVELOPER_DIR="$HOME/Applications/FoxToolchains/Xcode_27.1.app/Contents/Developer" \
npm run doctor
```

隔离构建缓存时，可设置 `FOX_IOS_UI_DERIVED_DATA="$PWD/.tmp/ipad-simulator-271-data"`，模拟器双 App 构建和 UI/App-host 测试共用这个目录。预检从 `simctl list runtimes --json` 读取可用性与 `supportedDeviceTypes`；在申请会话或创建任何设备前核对本批全部机型。安装了某机型类型不等于指定 runtime 支持它。不兼容或运行时不存在直接失败，不自动回退；兼容运行时即使没有永久模板，也可按已安装类型创建临时实例。显式错误 UDID 仍拒绝。

## 开发流程与候选验收

### 失败分类：决定下一步，不自动判断根因

在现有验收说明或 PR 中记录同一份失败信息，不建第二台账，不扩展 [任务契约](task-contract.example.json) 的严格 schema。至少包括运行身份/证据位置、首个有效现象、分类、原因确定程度、下一步假设和重跑范围；这些是人工/Agent 判断，不是自动根因诊断。

在同一份验收说明中使用以下三行模板，条目可随实际情况重复：

```text
候选：完整提交号 | scope/component | 前置测试与审查证据 | 替代哪个旧候选（如有）
失败：运行/证据 | 现象 | 分类/确定程度 | 下一步假设与重跑范围 | 取消原因（如有）
复用：原回执 | 本次用途 | 完整性核验 | 环境适用性 | 采用/仅参考/重跑及理由
```

| 分类 | 典型情况 | 下一步 |
| --- | --- | --- |
| product | 异步结果未通知界面 | 最小产品修复及回归；遵守本轮修改范围 |
| test_fixture | 合成交付延迟被误算为采集缺帧 | 校正测试模型，保留业务断言及原失败 |
| environment | 工具版本不符、模拟器服务异常 | 核对实际版本/状态，受控对照，不直接改产品 |
| orchestration_budget | 外层超时早于内部测试预算 | 修正执行预算或顺序，不延长业务断言来救绿 |
| cancelled_superseded | 人工取消、候选已被新修复替代 | 记录触发者/原因及此前是否已有失败 |
| unknown | 看见失败，尚不能区分应用或自动化 | 补最小必要观测，不以猜测代替结论 |

允许多因素。重复同类问题引用原记录，只有新增证据才更新判断。重跑前说明代码修正、环境恢复、受控复现或新增观测的目的；用于测量偶发性的重复也要预先给出次数与停止条件，不能无限重试直到通过。失败日志、取消和未完成回执都保留，不能被后一次通过覆盖。常规诊断由 Agent 自行推进，不增加逐操作人工批准。

原生命令一旦输出 XCTest 的 `App animations complete notification not received` 超时行，现有执行器以 `native_automation_idle_timeout` 失败并终止自有进程，保留日志和清理，不继续积累每个操作的 60 秒等待。直接原生入口与 suite/design/Duo 使用同一规则。它是明确失效后的停止防线，不是自动根因分类，也不关闭动画/空闲检查。当前独立复现和未采纳的绕法见 [IMP-2 定位记录](../planning/IMP2_IDLE_RECOVERY_20261026.zh-CN.md)；等待问题未解决前，不以完整重跑碰运气。

### 候选冻结：昂贵验证之前固定身份

顺序为实现/定向测试 -> fast -> 必要审查及已知阻断处理 -> 固定干净提交 -> 完整验收 -> 按授权交付。工具链/输入预检沿现有入口执行。定向跨环境检查可以在冻结前帮助定位；不把候选冻结解释成禁止早期云端诊断。

新入口在读取私人输入、扫描测试、检查工具链和创建模拟器之前检查完整提交号及干净状态；未暂存、已暂存、未跟踪和删除文件都会拒绝，不自动提交、删除或还原文件。Git 忽略的证据目录不阻塞。拒绝时保留 `failed` 回执、`candidateCommit` 和零执行步骤；非法命令参数直接退出，不创建运行回执。

```sh
# 完成提交后固定此值；它不会随着后续 HEAD 自动更新。
candidate=$(git rev-parse HEAD)
npm run verify:candidate -- public --commit "$candidate" --output .tmp/verification/candidate-public-unique
# 私人完整验收另需既有 FOX_PRIVATE_INPUT_MANIFEST。
npm run verify:candidate -- private --commit "$candidate" --output .tmp/verification/candidate-private-unique
```

`public` 可加 `--component web` 或 `native`；分片仍只证明对应范围。`private` 不允许分片，`fast` 不能冒充正式候选验收。所有选项拒绝未知、重复和缺值，不能把拼错的候选参数静默变成普通运行。`verify:fast`、`verify:public`、`verify:private` 和 `test:trial` 保持原迭代/CI 用途，不强迫日常测试先提交；正式交付使用新入口，而不是普通迭代结果冒称冻结验收。

冻结只影响被验证的工作树，不阻止其他工作树开发。运行中源码变化继续由既有指纹检查拒绝，完成前再次核对候选与输入。日志及验收补记写入忽略的运行目录，冻结期间不要更新仓库内 CURRENT 或其他文档。新问题需要修改时，显式替换候选并保留旧结果，依据剩余诊断价值决定停止还是继续旧作业，不机械全部取消或全部等待。

目前不改变 GitHub CI 触发规则：PR 更新仍会触发检查，包括草稿 PR。先通过本地迭代、定向诊断和合理批量推送减少重复；不以取消所有旧作业替代原因判断。正式入口只验证机器可核对的提交/清洁度，不声称已经自动证明审查完成、无已知阻断或工具链适合本次目标；前置证据由任务说明记录。

### 验证复用：先核对已有证据，再执行

| 结果 | 可以怎样复用 | 不能代表什么 |
| --- | --- | --- |
| 同提交/源码/输入/范围的成功回执 | 用 `npm run verify:receipt` 核对完整性及覆盖，再判断环境是否满足交付要求 | 本地不能代替明确要求的云端或真机验收 |
| 历史失败、定向通过、其他候选结果 | 复用定位线索和已完成调查，引用原件，不重复解释成新结果 | 不作新提交的完整通过证据 |
| 依赖/构建缓存 | 加快执行 | 不是测试结果 |

现有核验器不自动判定当前环境与旧环境等价，工具版本/运行时适用范围须另行核对。提交、源码（含文档）、输入、日志或选择范围变化均不能直接沿用旧通过；相同文件树的合并提交也不改写旧回执身份。本轮不支持跨提交拼装、按猜测影响面少跑测试、私人套件分片或宽松断言。旧失败与最终成功在同一说明中关联，取消/缺测/跳过不能拼成成功。

### 本轮改善的验收标准

- 失败/取消均能找到分类依据、未知项及下一次执行理由；现有历史复盘作为起点，不重跑历史 CI 来补齐记录。
- 正式入口对错误提交和脏工作树在零测试、零模拟器分配前失败；干净匹配提交及忽略目录中的证据允许继续，原件不变；普通脏树迭代仍可进入原预检。
- 现有缺测/跳过/取消/运行中变化等反例继续通过；回执复核不执行套件，不放宽输入、日志和提交绑定。
- 下一次真实开发观察完整运行次数、取消理由、无新依据重跑次数、复用结果和新增维护劳动。流程已落地不等于节省时间已被证明，不以不同复杂度任务总耗时直接比较提速。

## 层级

### IMP：先收束，再完整验收

见 [IMP 路线图](../planning/IMPROVEMENT_IMP_0_4.zh-CN.md)。日常循环不要求三个设备每次全跑：脚本先 Node 反例；共享状态/存储先 host；布局先受影响的原生场景，再交互反例。最终冻结候选仍运行完整 public，Duo 布局相关改动另运行现有 Duo 专项。不以更少执行冒充相同质量，不跨提交拼接。

设计采集统一使用 `npm run design:review -- --device ipad --group training-feedback --output <fresh-directory>`，与完整套件共用 doctor、runSuite、原生命令、会话租约和退出清理；它不是第二套验收系统。无 UI 修改时不要为了生成更多截图重跑全设计集；已有同候选完整结果包可只导出，不重复执行。

`npm run verify` 顺序为 typecheck → build → test。API 的真实 CLI 集成测试通过 workspace 导出的 core 构建产物启动，不能依赖旧 dist；干净候选必须在测试前由同一候选源码生成它。此顺序修正不改变 CI 触发或测试集合。

挂起预算保留在现有外层进程管理中；实际定向诊断先设 5–10 分钟问题预算，正式批次沿用既有上限。原 4/12/15 秒交互断言不改，超时/取消必须失败并释放自己拥有的资源。每个原生步骤显式保存独立 `<step>.xcresult`，不依赖可能被后续构建清理的默认结果目录。

本轮试验的 XCTest 方法级超时模式未采纳，命令明确使用 `-test-timeouts-enabled NO`，挂起仍由外层预算处理。启用时备份取消出现重复 60 秒动画等待；关闭后一次定向对照通过，但后续完整候选仍复现等待，因此该开关不是已确认根因，也不宣称关闭它已解决问题。不关闭动画、不使用私有 XCTest 开关、不因此放宽产品断言。参见[实施结果与尚未通过的完整验收](../planning/IMPROVEMENT_EXECUTION_20261026.zh-CN.md)。

只读成本入口：`node scripts/verification-timing.mjs <suite目录> [...]`，输出 JSON 到 stdout。统计成功/失败/取消、各步骤/方法、累计执行时长、区间合并占用时长和首尾窗口；缺结束时间标未知。日志逐份核对哈希与字节数，未验证日志只作定位；警告与慢方法只记录相关性，不自动归因。此命令不执行测试、不读取训练数据、不生成验收通过声明。

每批记录：预期验证问题、首次有效失败、下一假设、重跑范围、是否替换候选。连续同类失败没有新假设时停止扩大执行范围。完整候选是收尾门槛，不是开发循环。成本目标是减少重做/等待，不能通过降低覆盖、断言期限或保留记录标准来换取。

| 入口 | 覆盖 | 明确不覆盖 |
| --- | --- | --- |
| `npm run verify:fast` | 类型、Web/API 单测、脚本/边界、核心/存储、合成 wire、Python 映射 | 全量 UI、私人录像、真实语音、设备 |
| `npm run verify:public` | fast + Fox/Fox Say 模拟器构建、App-host、iPad/iPhone UI、浏览器闭环 | 私人录像、真实系统语音、物理设备 |
| `npm run verify:private` | public + 固定私人语料、真实控制器、逐事件历史、后期标签核对、真实系统语音 | 新真人准确率、听感、签名/安装/物理性能 |
| `npm run test:trial -- <fresh-directory>` | 与 private 相同的严格兼容入口 | 不再依赖某个历史缓存目录；不自动完成设备门槛 |

可加 `-- --output .tmp/verification/<unique-run>`。公开层可用 `--component web` 或 `--component native` 分工，CI 必须两者都通过；单一 component 不代表完整 public。private 不允许分片绕过公开覆盖。

完整原生运行默认创建专属临时 iPad/iPhone 模拟器，固定本地通用 iOS 27.0、云端显式兼容 profile，以及 iPhone 17 Pro 与 iPad Pro 11-inch M5 12GB。Duo 27.1 单独选型，不用于 iPad 回退。目标缺失直接失败，不按列表顺序回退；`FOX_SIMULATOR_RUNTIME` 可显式选运行时。完成、失败或正常套件取消后仅清理本次创建的实例。已有模拟器和真机不删除。回执记录实例、运行时、所有权及清理状态；清理失败也不能通过。`doctor` 只读，fast/Web 不创建实例。诊断时可用 `FOX_TRIAL_IPAD_SIMULATOR` / `FOX_TRIAL_IPHONE_SIMULATOR` 指定已有 UDID；它们不会被清理，但其原有状态会影响结果，不属于干净环境证明。

套件、诊断及直接 UI 入口共享本用户的模拟器会话，跨工作树争用立即失败。每步若有外部启动实例则停止，不自动关闭。直接 UI 默认也使用临时实例；继承套件目标时核对 token、工作树、工具链和 UDID，不另抢锁。强制终止与异常创建/清理保留 owner 待核查，恢复步骤及工具链并存的退出条件见 [过渡计划](TOOLCHAIN_TRANSITION.zh-CN.md)。人工 Xcode 操作和旧脚本不受互斥约束。

原生批次执行前，只关闭本次拥有的其他模拟器，避免 iPad 测完后继续与 iPhone 同时运行；不清除数据，切回系统语音批次时重新启动原 iPad。回执的 `environment.simulatorIsolation` 逐项记录目标和已停止的同批实例。显式指定的已有实例不会被这一步关闭；关闭错误使检查失败，不重试或吞掉非“已关闭”错误。这是资源隔离措施，不等于已证明此前超时的系统根因，也不改变交互断言期限。

模拟器创建/停止/删除使用异步命令，单次上限 60 秒；取消信号在清理及最终报告准备期间仍被处理。最终状态只在一次原子重命名时提交，此前正式回执保持 running；写满/取消不依赖事后把绿色改红，提交之后到来的取消不再属于本次运行。强制终止（如 SIGKILL/主机掉电）无法执行清理，应把仍为 running 的回执视为未完成；人工处置时只针对回执中本次拥有的实例 ID，不能批量删除其他模拟器。

原生每个测试方法、其他测试每个文件都有明确分类。新增/删除/移动须更新目录并审核原因；文件内的全部 JS/浏览器/Python 用例会执行。公共层按分类不选择私人/语音/设备测试，并在回执中列出未覆盖，不通过 XCTest skip 假装成功。已选测试缺失、失败、重复或 skip 均失败。

每项分类还必须给出兼容的执行平台：App-host/UI 使用 `ipad` 或 `iphone`，主机测试使用 `host`。缺失或错误平台在运行前失败。套件组装时独立核对本层、本 component 应覆盖的原生方法集合，任何应执行但未选中的方法都失败，不能仅列为“未覆盖”而继续通过。

Swift 方法扫描包括修饰符/属性后的 `test...` 声明，不认识的命名或多 XCTestCase 文件会明确失败；实际原生运行再次核对每个方法。Python 按分类清单逐文件加载，嵌套目录不依赖 `__init__.py`，任何空测试文件、skip 或 expected failure 都不能借其他文件的通过而变绿。

## 私人输入

设置 `FOX_PRIVATE_INPUT_MANIFEST` 为本地清单的绝对路径，再运行 private。没有默认私人路径，也不从另一份 checkout 借缓存。清单格式：

```json
{"schema":"fox.private_inputs.v1","assets":{"logical.id":{"path":"/absolute/private/file","bytes":123,"sha256":"64-hex-digest"}}}
```

## 回执与失败

`npm run diagnose:native-ui -- <fresh-directory>` 在下列三个 iPhone 用例之前，先运行 iPad 的侧平举保存/重启/切回弯举场景。CI 使用此四用例入口，完整回归仍保留原覆盖。计数探针记录原 12 秒等待中的标签与查询耗时；失败后的八秒只读观测不能改变原失败结果，不点击、不补输、不重试。12 秒是 XCTest 配置期限，不保证正在阻塞的 AX 查询恰在墙钟 12 秒被中止。专项只证明本次场景，不解释所有历史超时，也不作为运动性能指标。命令入口拒绝未知/重复选项和多个输出路径，不能因 `--vision` 拼错而静默只跑 iPhone。

专项的批次预算包含工程生成、构建、模拟器冷启动和测试进程启动，不是交互断言的等待。每台设备批次上限 25 分钟，外层任务为两批合计再加 10 分钟初始化/清理，共 60 分钟，测试检查两层预算一致。此前扩展为两批却保留 25 分钟任务上限，云端 iPad 专项通过后，iPhone 尚未完成便被外层终止；保留 running/allocated 回执为未完成，不声称那次云端已清理。四秒界面准备、12 秒精确计数等用例条件不变，也没有自动重试。

`npm run diagnose:phone-ui -- <fresh-directory>` 固定运行三项测试：反馈输入、四角像素判定反例、计数中旋转与报告操作；旧 `diagnose:phone-feedback` 是兼容入口。它不代替完整层级，拒绝私人清单，复用专属模拟器及失败/清理回执，严格核对三个用例和对应观测。云端固定失败时的 iOS 26.4 / iPhone 17 Pro，不存在时失败、不换版本；本地记录实际环境。四次按钮检查测量主窗口并拒绝零尺寸，保持原四秒总期限与单次点击。旋转后三个朝向分别在四秒内等待四角完整渲染、相同几何与采样值持续至少 250ms，保持每个 RGB 通道误差小于 20 的原标准，不改计数/预览身份/报告断言。这是自动化观测稳定性，不是真机帧延迟测量。失败时仅合成观测与 AX 文本进入公开日志；截图留在本地结果包，不上传整个 xcresult。完整原生 CI 依赖诊断通过，仍执行全部原覆盖。一次定向通过不能解释所有历史失败，也不能作为完整验收。

输入探针 v2 明确将时间契约从“首次 AX 读取即完整”改为“单次输入后四秒内精确完成”。期限从 typeText 返回、首次查询之前开始，查询跨过期限仍失败。保留首次值、每次只读观测及耗时，独立阅读器拒绝错误文本、乱序/重叠时间、超时、缺字段和全部旧 v1 信封。键盘收起后另行断言精确内容不变，不能救活先前失败；不补输、清空或重试。私人运行只抑制日志，照常执行相同断言。这个变更依据一次未再次输入却自行变完整的云端观测，不声称能区分应用更新与 AX 快照延迟，也不重解释历史失败。

反馈用例先单次启动 Fox，沿用十秒首页就绪检查，再单次请求竖屏并以原四秒方向检查确认主窗口有正尺寸，然后才点击。启动与方向操作分行，便于定位失败。新增“横屏历史后的准备”用例进入完整公开/私有手机覆盖；它不声称系统在第二次启动时一定继承横屏，也不证明冷启动朝向或此前系统超时的根因。另七条手机启动路径不在此次调整范围。源码顺序反例只检查准备契约，不替代冷模拟器中的实际反馈流程。

每次运行独占目录，输出 `suite.json` 及实时追加的逐步日志。包含 scope/component、commit、源码指纹、dirty 状态、工具版本、输入哈希、选择/未覆盖用例、时间、结果和明确的 `deviceVerified: false`。开始、完成、失败、取消都保留。禁止复用旧目录；源码/提交/输入变化会使运行失效。源码指纹覆盖全部非忽略文件，包含 docs 和 Git commit 身份。

不得重试到绿后隐去失败；修正必须说明原因并新建运行。GitHub 使用无重试的浏览器与原生批次；上传范围仅公开 suite/log，不上传 `.data`、私有 xcresult 或用户截图。

本轮遇到一次旧模拟器旋转后窗口仍为竖屏：同一原断言在旧实例复现失败，在同型号/运行时的新实例通过。这证明结果受实例状态影响，尚未证明系统根因。因此增加实例隔离而不修改产品或放宽横屏断言；原失败、对照运行及最终完整运行分别保留。

iPhone 旋转后的交互不能只依赖 `isHittable`：反馈字段须完整露出且不被固定提交区遮挡，点击前须稳定，点击后验证仍在反馈页、键盘出现和实际输入值。多行输入框可能接收自身滚动手势，表单滚动按当前可见边缘计算路径。分段选项保持每项一次点击，并单独验证选中结果。两项失败用例修正后连续三轮通过，原结果断言和产品代码保留；这验证测试路径可达，不等同于所有人工触屏手势可用。

再次使用回执前运行 `npm run verify:receipt -- <suite.json> --scope public`（分片加 `--component web` 或 `native`，私人回归用 `--scope private`）。它重新核对当前提交/源码、输入、所有步骤、日志哈希、所选测试覆盖和历史事件；跨提交的旧绿色不能复用。

完整旧套件约 38 分钟，其中 UI 约 31 分钟。这是历史基线而非性能承诺。fast 从结构上移除 UI，未从完整 public/private 中删掉原覆盖；最终以本轮回执的计时和实际用例核对。

首次完整云端 iPad UI 在 45 分钟总时限前已通过 49/52 项，没有已完成用例失败，剩余流程被总时限终止。基于这份耗时将 iPad UI 整批上限设为 60 分钟，其他步骤仍限 45 分钟；不修改用例断言/单步等待，不加重试。原超时仍保留，不能算作通过。

## 发布边界

真实设备测试、联网状态、签名期限、安装前后记录哈希与正常启动另行验收。默认不运行、不调网络。本轮只保留已有试用候选。日志中的锁屏/开发者验证/签名过期属于环境问题，不归因于视觉算法。

公开 PR 只携带已审计源码和合成资料。新鲜 reviewer 用仓库入口核对数据保护、兼容性、断言改动和证据说法；本地通过不等于 GitHub CI 通过，CI 通过不等于真人试用通过。

提交后、推送前运行 `npm run verify:history -- origin/main`，扫描每个新增提交的变更内容，而不只检查最终目录。仍需人工/独立上下文核对公开权限。旧远端已经公开的历史不被本轮重写。

本轮初始化发现旧开发依赖告警；使用范围内修复并将 Vitest 定到 4.1.12，保留 Vite 6 系列与既有测试配置，随后重新跑原测试及依赖审计。依据：[Vitest 官方安全说明](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)。不使用强制升级到所有最新主版本的方式。
