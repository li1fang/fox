### 现在会发生什么

1. 首页保留记录与训练，仅在工具栏新增“同步资料库”。本地训练档案先读取，不等待同步网络。
2. 用户经可信渠道取得一次性配对 JSON，选择文件、核对服务器与资料库，再点“确认配对并同步本机图文”。凭据保存在本机 Keychain，不进入备份或 Git。
3. 首次配对将现有 Journal 的文字、照片与历史修订入队。前台打开、保存/更正/删除后及手动“立即同步”触发推拉；本地保存不等待服务器。未实现持续后台或实时保证。
4. 两端同改不会覆盖：界面显示本机/服务器文字与照片，用户选择保留哪一侧作为当前版本；另一侧历史仍保留。没有取得完整远端版本时不能进行选择。
5. 同步失败保留原件及队列；过大内容显示 blocked 原因，其他记录仍可同步。普通首页/训练不因服务器离线而停用。

这里只同步 **Journal 图文记录及其历史**，不是训练 JSON、诊断录像、系统相册、语音便笺、HealthKit 或 AI 分析同步。已有 Linux 归档仍独立；正式同步库是否已有真实数据必须查新回执，不依据合成实验推定。

### 持久化契约

详见 [存储 v2 扩展](../journal/RECORD_STORAGE_V1.zh-CN.md#2026-10-28-同步扩展当前契约)。本地写入/outbox 原子提交、幂等操作 ID、顺序游标、冲突所需远端版本校验、单调事件头、逐张照片落盘/重启保护都由确定性契约约束。

配对的单次 claim 先保存 Keychain 再启用本地队列；若后者失败，重新打开时从凭据恢复，不再次消费邀请。同步、配对与冲突选择在首次 await 前占用唯一 UI 操作状态，直到列表/状态刷新结束；本地记录录入仍可进行。恢复备份不能与同步同时进行。

删除已配对记录保留墓碑、历史与照片；无自动源端清理。v2 备份携带原始同步证据，但不克隆设备身份/凭据/游标，仅允许恢复到空且未配对库。超限历史的人工拆分/解除 blocked、换服务器/换证书和远程账号恢复不在这一版内。

### 配对交接与运维

已有私有配置及证书锚由协调者通过固定 SSH 来源核对。准备设备后运行：

```sh
python3.12 scripts/sync_pairing.py /private/new-device-pairing.json
```

每台设备一个新文件；输出必须不存在，权限 0600，五分钟有效、只能领取一次。命令不打印邀请秘密。通过可信本机交接/AirDrop 等送到预期设备，再由 Fox 的文件选择器导入；**文件本身包含领取权限，不上传 Git、聊天附件或公共文件服务器**。过期重新生成，不放宽服务端校验。不要提前批量生成等待安装。

正式设备步骤：完整备份及清单/SQLite/照片核对 -> 验证签名与设备覆盖 -> 覆盖安装（不卸载）-> 尚未配对时核对 v1 到 v2 的原记录/历史/照片保全 -> 用户配对和系统局域网授权 -> 服务端查询/附件字节及两端记录关联核对。新版本按内容比较数据库，不以 schema 升级后的文件摘要变化判作丢失，也不能只以 quick_check 代替内容比较。

迁移后旧 App 不认识 v2，不能把直接覆盖旧安装包当作数据回滚。需要回退时先保存新增资料，再制定使用迁移前快照的恢复步骤并另行授权；本轮不降级、不自动恢复旧库。

真机操作已由用户在本轮追加授权；若锁屏/信任/系统权限或手工文件导入需要配合，明确通知。当前未完成的设备步骤不冒充成功，也不通过开发启动参数绕过配对确认。

## 运维与接续

同一 Mac 的私有 `~/.config/fox/sync-https.json` 提供 endpoint、vault、独立保存的公有证书路径/摘要及服务名称；不含设备令牌。SSH 连接沿用原共享配置。不要把该配置或 TLS 材料提交仓库，也不能把从不可信网络下载的证书自动当作锚。

服务端依赖通过 `python -m pip install -r scripts/sync-https-requirements.txt` 安装到隔离 venv。Uvicorn 以 `sync_https:app --factory` 启动，`FOX_SYNC_ROOT` 必须是绝对路径。实际安装的 user unit 固定 release、LAN 地址、端口及 TLS 文件；查看/停止用 `systemctl --user status/stop fox-sync-https`，更新须先验证新 release，再切换 unit 并保留旧证据，不能覆盖运行中的源码。邀请/撤销仍遵循 [同步契约](PERSONAL_SYNC_V1.zh-CN.md)。

证书本次为 90 天测试证书，自动续期、换锚分发和地址改变尚未实现；到期/身份变化应失败并明确提示，不回退明文或跳过验证。配对凭据将存 Keychain；本轮没有向设备分发任何凭据。暂停服务不删除资料；若未来停用 linger，应先核对同账号其他后台服务，不随意全局回退。

下一步 SYNC-3B 的验收门槛：旧 Journal 升级保留全部历史/照片；写记录与 outbox 原子提交；断网连续修改、重复上传、冲突保留、删除墓碑及备份恢复不损失附件。之后才做配对/前台同步 UI，再安排有备份的双设备验收。上述未完成项不是本阶段的通过项。
