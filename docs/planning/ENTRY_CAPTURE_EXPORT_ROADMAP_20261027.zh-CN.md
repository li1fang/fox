# 记录首页、直接试练与多模态采集路线

日期：2026-10-27（Asia/Bangkok）。状态：计划已建立，P1–P4 未实施。总台账沿用 [LIFE_LOG_BACKLOG](LIFE_LOG_BACKLOG.zh-CN.md)，不再建立第二套任务系统。

## 1. 本轮契约与判断

本轮只做两件事：将已经实现的当前版本保留数据更新到 iPad/iPhone；记录讨论，设计下一阶段的里程碑、测试和验收。不把计划当实现，不顺手增加入口、录音、导出、权限请求或新算法。

产品承诺：Fox 帮用户完成训练、留下生活事实，并把选定资料交给用户自己的 AI。保持一个 Fox App，记录首页与最近记录方向不推倒；训练进入后专注训练。既有 Fox Say 实验 App 不在本轮更新或删除，也不因本计划再拆分产品。

试用反馈来自有限样本，且部分设备此前不是最新版本：可以据此确认入口难发现、术语不自然、反馈方式有落差，不能据此断言所有用户都需要健身首页、实时 AI 或两个 App。上一轮 UX 改进优化了进入训练后的路径，未充分证明第一次打开的人能找到价值。

已决定：

- 首页保留记录卡与时间线，但训练是首屏直接入口，不再要求普通用户选择“视觉实验”。
- 用户选择动作，系统根据已验证能力提供相机辅助或节奏引导；自动观测、跟练进度、人工确认仍明确区分。
- 用“试练一组”展示有限能力，不称体能测评，不承诺由一次动作判断姿态标准性或生成个性化计划。
- 系统输入法听写继续作为文字输入方式；语音便笺是原始音频，不等于转写或对话理解。
- 采集、持久记录、分析、反馈分层。保存回执即时提供；不虚构后台理解、夜间自动整理或次日建议。
- 第一阶段外部智能路径是用户主动导出，不接实时 AI/ASR，不自动上传、不自动把语音里的重量改进计划。
- HealthKit 沿用 INPUT-01，独立排期；TRX 适配、数字人、双机协作、屏幕时间、实时对话暂不开展。

不变量：现有记录、照片、录像、来源和失败回执保留；不修改计数/准备/恢复/离心策略，不补造返回阶段，不将节拍推算当实际次数。备份恢复与面向 Agent 导出不同，不拿整库备份替代用户可选的数据分享。正式 M2 数据与算法路线独立推进，挑战样本不作为必须识别的验收目标。

## 2. 顺序与阶段门槛

| 阶段 / 台账 ID | 用户结果 | 主要工作类型 | 状态 |
| --- | --- | --- | --- |
| P0 / ENTRY-00 | 两台设备体验同一已有候选，原记录可回看 | 交付流程，不改业务代码 | 本轮执行，见交付记录 |
| P1 / ENTRY-01 | 从首页直接试练，或进入原有计划；不理解“视觉”也能用 | 产品 UI、路由、能力呈现、测试 | 下一实施项，未启动 |
| P2 / CAPTURE-01 | 文字/照片快速留下，保存结果明确，训练留言有上下文 | 采集 UI 与有限存储接入 | P1 后，未启动 |
| P3 / CAPTURE-02 | 可录音、试听、保存语音便笺，知道尚未转写 | 原生音频、附件与备份扩展、测试 | P2 后，未启动 |
| P4 / EXPORT-01 | 选择记录，导出人和工具都能理解的资料包 | 选择 UI、导出契约、文件与兼容测试 | P3 后，未启动 |
| H1 / INPUT-01 | 用户授权后，读取可信的步数/活动汇总 | 独立能力与授权评估，再实施 | 另行排期，不阻塞 P1–P4 |

未来获准连续实施时，每阶段先写失败测试，再实现、定向验证和复审；软件通过即可继续不依赖人工的后续工作，真人体验项保持待验，不冒充通过。只有目标变更、数据风险、权限或签名人工门槛才停下来请求配合。本轮授权仅覆盖 P0 和计划，不自动开始 P1。

## 3. P0：更新既有候选

先复核干净提交与匹配回执，分别盘点/备份两设备的 Documents、Application Support、Preferences，再构建一个覆盖两设备的同 bundle/team 安装包。只为区分交付增加构建时版本元数据；记录源码提交与命令，不改已经验证的业务源码。

验收：签名完整且未过期、包含目标设备；覆盖安装而非卸载；正常入口启动、已安装版本与进程一致、首页截图可见；安装前后文件 SHA-256 与 Journal 内容核对。SQLite 若仅发生 WAL/检查点变化，须单独比较语义内容，不把所有字节差异都视为丢失或默认忽略。

停止：备份不完整、签名不匹配、磁盘不足、记录无法解释的变化。锁屏或信任门槛请用户处理，不撤销共享证书、不改设备网络、不卸载。交付 smoke 不等于完整原生回归、真人计数或首次使用验收；旧 iPad 动画等待与 Duo 欠项不因此关闭。

## 4. P1：统一训练入口，直接试练

故事：我因自动计数而来，打开 Fox，看见试练入口，选择一个已支持动作并就位；不先制定完整计划。看不清或不开相机也有路可走。结束后确认结果，选择继续训练或回首页。

范围：

- 保留首页卡片/记录方向，训练卡提供直接试练、既有计划/未结束训练的清晰去路。默认首屏可发现；大字号允许合理滚动，不通过缩字挤入首屏。
- 首页默认动作试练入口一次点击进入准备页，系统授权和可选动作切换另计；不自动开启相机，不要求先进入实验室或填个人资料。
- 复用现有训练会话、能力声明和状态机。试练不能覆盖既有计划/未结束训练；冲突时提供明确继续或退出选择，不能静默新建替换。
- 同一套动作、组、节奏、休息、核对流程。视觉只是一种观测能力，支持动作也允许用户关闭相机。不支持的动作直接使用计时/节奏/手工路径，不索取无用相机权限。
- 显示当前究竟在自动计数、跟随节奏还是需要人工确认。短暂缺点沿用既有恢复策略，不频繁弹窗；长缺失显示手工退路，已有自动事实保留，不暗中继续计数。
- 复用已有节奏叠加组件。画面弱化只作后续可选显示实验，不降低识别输入质量、不声称画面模糊即匿名，不加入数字人。实验页保留为二级开发入口。

先写测试：空数据首次进入、已有计划、已有在途训练；有视觉/无视觉/关闭视觉；相机拒绝/不可用；短缺点/长丢失/手工回退；暂停退出恢复；核对保存与重开。固定录像/数值回放逐事件比较三个既有动作的次数与离心数据，而不只比较最终总数。

自动验收：主页可直达准备；用户流程没有必须选择“视觉”的步骤；试练与原记录不互相覆盖；跟练进度不落为实际次数；权限失败仍能完成手工训练；既有三动作计数、恢复、末次返回缺失语义不退步。手机竖/横与平板主布局的主操作可达，相机保持完整比例。

真人验收：邀请至少 2 位未参与开发的人，不口头指路，分别找到试练、经历一次相机不可用的退路、核对并回看。记录耗时、犹豫点、提示次数，不预设“所有人都懂”。任一人把节奏进度误认为识别次数、以为完成了体能测评或无法安全退出，均为需修复项；样本通过也不泛化为普遍可用。

## 5. P2：文字、照片与训练留言

故事 A：拍饭或小票，加一句话，立即知道资料已保存，可以重开、更正；不先选饮食/财务分类，不等待 AI。故事 B：做完一组说感受，输入法听写生成文字，留言自然属于这次训练或本组。

范围：复用现有 Journal/相册/拍照，不另造通用记录库。允许只有文字、只有照片或组合；普通记录、整场训练留言、某组留言明确归属，不让用户重复输入动作/组数。界面区分“已存本机”和“理解完成”，没有分析服务就不显示正在分析。

先写测试：输入合成/长文本/中文数字/换行与系统听写结果的文本接收；拍照取消、相册选择取消、权限拒绝、图片读取失败；纯文/纯图/组合保存、重复点击、旋转/后台中断、失败重试、重开修改；训练关联 ID 不串组、不把留言中的 15kg 自动变成计划重量。保存失败时保留仍可恢复的输入，失败状态不能变成成功卡片。

自动验收：原文、照片原件及时间保留；只生成一次记录；上下文指向正确训练/组；历史照片及修订不丢失；现有备份恢复测试继续通过。软件用听写结果注入验证文本接收，不冒充真机系统听写体验。

真人验收：一次相册导入、一次实际拍照、一次输入法听写训练留言，保存重开能看见并辨认归属；取消不丢旧内容。看得懂“已存本机”，不会等待当前不存在的营养或计划建议。

## 6. P3：语音便笺，不做 ASR

故事：不想打开键盘时，点击录音留下感受，停止后试听，可重录、删除或保存；之后能回听，也能和照片/文字一起导出。

范围：原生本地录音，明确时长和录音状态，手动开始/停止；触发时才申请麦克风。默认在记录/组后核对采集，不在承重动作中要求交互。显示“未转写”，不假装已理解；不引入实时流、声纹、唤醒词或 Fox Say/Linux 依赖。保留输入法听写路径，不将录音按钮伪装成系统键盘听写。

附件契约在本阶段实施前补齐音频类型、关联、原件、校验、删除与原子保存；只作必要迁移。旧照片库和现有备份格式必须有显式版本兼容路径；未知新版包拒绝并保留原库，不静默丢弃音频。本轮不预写整个分析数据库设计。

先写测试：拒绝权限、零时长、编码/存储失败、空间不足、连续点击、录音中后台/来电/音频会话中断、扬声器与耳机路由变化、试听/删除/重录、保存重试、重开及备份往返。明确每次中断保留多少录音，不把部分片段显示为完整；不会停止或修改既有训练事实。

自动验收：音频可解码、时长可核对、附件哈希往返一致；失败不产生空成功记录；录音停止后麦克风释放；不自动申请语音识别/联网、不发模型请求；“这次 12kg，下次想试 15kg”的音频不会更改结构化重量。

真人验收：在两种设备实际录一条、听一遍、重开回听；覆盖一次拒绝或中断。音频听感与麦克风权限不能用模拟器假音频替代。完成后仍不宣称具备对话能力。

## 7. P4：面向用户自有 Agent 的导出

故事：选择今天或某次训练相关的记录，预览将包含的文字、照片、语音和训练事实，导出到文件/系统分享。外部 Agent 可读并追溯，不需要访问整个数据库。

范围：一个资料包，包含人可读摘要、版本化 JSON 清单、原始附件；默认不包含诊断录像、全库、无关历史或健康数据。关联到具体训练/组的留言随所选上下文一起预览，用户可排除；引用未包含材料时明确缺失，不暗中扩展导出范围。保留实际/目标、自动/人工、未知/零、原文/后续解析的区别。支持文字、照片、音频单独存在；依 MIME 与版本说明音频未转写，接收方可能不支持音频。

只导出，不做自动传给 Codex、模型选型、定时任务、结果回灌或建议自动入库。导出成功指包完整并已交给系统保存/分享流程，不等于对端收到、解析正确或分析完成。完整备份/恢复入口独立保留，不承诺资料包可直接恢复整库。

先写测试：按时间/训练选择、排除附件、跨组关联、无数据、时区边界；版本/schema与附件校验、路径安全、Unicode/长文件名、重复导出、取消/空间不足/缺附件、旧记录。用独立只读解析器打开资料包，逐条追踪事实来源，不仅检查 ZIP 能打开。

自动验收：导出范围精确，缺件明确失败且不报完整；同一选择的语义内容一致；所有附件可定位/解码/核验，源库不变；“当前12kg、希望下次15kg”不会被导出器改写成实际15kg。系统分享失败可重试，不生成第二条源记录。

人工接收验收：用户将一个包含文字/照片/语音/训练事实的明确样本交给其自有 Agent，检查是否看懂关联及未转写边界。该次接收单独授权并记录结果，不发送私人数据到未知服务，不要求所有 Agent 支持所有模态。解析器通过不是模型理解质量的证明。

## 8. HealthKit 独立排期

沿用 INPUT-01，不成为 P1–P4 的依赖。启动前复核账户/签名 capability、设备支持与数据来源，优先只读步数、步行距离、活动能量及已有训练；不默认请求全部健康数据或写回。

先设计无权限/不可读/无样本/真实零值、部分历史授权、来源重复、跨时区/夏令时、旧样本修改或删除、训练能量重复计入等测试。接口无法区分的拒绝与空数据统一呈现为不确定，不声称精确知道授权原因。汇总须能追到来源，不能把活动能量理解为纯步行或全天总消耗。

睡眠仅在存在真实样本和独立需求时增加；首次解锁/首次走动不当起床事实。屏幕时间访问不纳入当前计划。验收包括授权拒绝时正常使用、撤销后不显示过时确定结论，以及实际样本与来源核对；本轮不请求这些权限。

官方边界参考（本轮讨论依据，实施前复核）：[HealthKit 授权](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[活动能量](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/activeenergyburned)、[设备活动报告隔离](https://developer.apple.com/documentation/deviceactivity/deviceactivityreport)、[按上下文请求权限](https://developer.apple.com/design/human-interface-guidelines/privacy/)。

## 9. 验证成本、停止条件与发布边界

- 沿用 catalogue/runSuite/receipt/模拟器租约和分层验证，不新增框架或改变 CI 触发。新测试登记到现有清单。
- 流程/文档变更做链接、范围与台账一致性检查；产品改动先纯逻辑/存储/状态契约，再跑受影响原生故事，最后冻结候选走既有完整验收入口。不是每改一句文案就跑三端全量。
- 共用导航/布局变更覆盖手机竖横与平板；Duo 在适用时补已有布局/状态连续性用例，模拟器或迁移阻塞单列，不拿普通手机通过替代。无折叠真机不宣称悬停能力。
- 发现已知动画等待时记录并暂停受影响组，继续独立工作；保留原完整用例和断言，不重复盲跑、重启或恢复采集器支线。
- 算法回放、计数/离心事实、记录持久化是硬不变量；视觉呈现通过不等于新真人准确率。任何事实混淆、数据丢失、无法恢复保存或权限误导都不接受为发布欠项。
- 后续真机安装仍需明确授权，先备份后覆盖，不因本轮两台更新而获得持续自动部署授权。旧设备证据保留，新反馈记版本、设备和场景。
- 本路线不宣布生产版或上架就绪；真人独立使用、辅助功能、完整回归和商店要求分别验收。
