# 训练传感器存储 V1

日期：2026-10-28。负责人：产品与交付。先给生产方明确目的地，再以真实样例校准；本轮只接受合成验收，不宣称任何厂商格式或融合已适配。

## 目标与边界

- SEN-0：明确投递、时间、单位、来源和保留契约；先写反例测试。
- SEN-1：实现训练时间窗、三类规范流、SQLite 时间索引、原件关联和可重试查询；Linux 合成闭环。
- SEN-2：外置盘承接新的缓存、验证输出和下载；离线不静默回落内盘。保留已有文件。
- SEN-3：真实样例到达后再做厂商适配、时钟误差评估与容量测试，本轮不启动。

不做：设备更新/采集、实时同步、融合、自动标注、算法改动、清理原件、新服务端口、完整账号或调度系统。不会等待所有 Agent 停止；本包不使用模拟器或重型原生构建。维护树保持单写者。

## 两层资料，两个承诺

1. **待验收投递区**：既有 Linux 资料库的 `incoming/training/<capture-id>/`。`reserve` 生成 controller_6dof、depth、resistance、video、reports 子目录和草稿。生产方可直接上传原格式，不必先等适配器。未知单位/时间的数据停在这里，不成为可分析的训练样本。
2. **已接收训练库**：`metadata/training.sqlite` 保存会话、流、时间索引、规范小数值和证据引用。只接收训练时间窗内、时钟可映射、字段有效的样本。原始大文件继续使用已有 `originals/` 内容寻址归档，不塞进 SQLite。

投递区不是备份，也不是训练数据库。原文件可能含窗外数据；本轮保留它们、不删除既有原件。新训练数据库不保存窗外行或被排除字段的值，只保留排除计数。未来采集端只录训练区间另行实施。服务器仍无独立备份。

部署位置保存在私有 `~/.config/fox/training-store.json`；不把主机、设备标识或原始资料路径提交到 Git。沿用归档库的固定 SSH 主机身份、摘要校验和本机 SQLite，不让 Mac/手机跨网络直接打开 SQLite。

## 时间与关系

- `start_us <= captured_us < end_us`，UTC Unix 微秒，半开区间避免相邻段重复归属；开始/结束必须明确，不以文件修改时间或上传时间代替。
- `received_us` 仅表示服务器接收时间。离线晚传依然按实际采集时间筛选。
- 每条流保存原始 `tick`（十进制字符串，避免纳秒整数在 JavaScript 中失真）、序号、时钟原点、频率、映射依据和不确定度。映射只做整数有理数换算，不自动估计漂移。
- 时钟复位、新时钟原点、坐标系或校准变化需要新流；映射修正需要新流 ID。不得修改旧证据。误差范围跨边界的样本暂不接收，单列 ambiguous 计数。
- `capture_id` 关联同一采集任务，不声称不同流空间对齐。坐标轴、左右手系、测量部位和校准归档 ID 明示；没有校准可以为空，不伪造坐标转换。
- 视频/报告可通过归档 ID 与会话关联；时间偏移未知时保持 null。关联成功不等于时间已同步，更不等于 6DoF 手部数据代表肘关节或离心肌肉负荷。

## 最小字段白名单

| 流 | 接收的样本字段 | 不推断 |
| --- | --- | --- |
| controller_6dof | 米制位置、xyzw 单位四元数、tracked/lost、A/B/X/Y/trigger/grip 原始按键 | 不把按键自动解释为顶峰；追踪丢失不沿用旧位置 |
| depth | 已校验归档帧引用、宽高、uint16_le/float32_le、米制比例、fx/fy/cx/cy | 不假定已对齐 RGB，不实现深度算法 |
| resistance | force_n、position_m、velocity_m_s、power_w 中实际提供的项 | 不推算卡路里、组数、阶段或实际重量 |

值必须有限、单位必须由字段名及规范描述保证；上游单位未知不得猜测。未知传感器类型拒绝，`values` 内非白名单字段剔除并报告数量，不保存其值；顶层未知字段拒绝，避免把拼错的时间或单位静默吞掉。丢失状态本身可保留，不伪造姿态。

## 存储与并发

会话/流/关联不可覆盖；相同 ID 同内容可重试，不同内容报冲突。流逐行读入，有行长/文件长上限；摘要、完整性与所有样本通过后一次事务提交。中断、异常、磁盘不足不得留下半份可查询流。深度大文件先经过既有归档入口校验，再引用；失败时允许留下未关联的原件，不自动清除。

SQLite 只由服务器进程打开，复用 SSH RPC，不新增守护进程。索引键为 session/time/stream/seq，分页使用稳定复合游标；查询结果附流描述和接收统计。返回结果不是融合或训练质量结论。

## 外置盘策略

私有 `~/.config/fox/storage.json` 指定已挂载卷与 Fox 专用目录。新 SwiftPM 缓存按工作树摘要隔离，新验证/设计回执、原生包装日志进入 evidence；另有 incoming 和 downloads。未配置时维持仓库兼容默认，已配置但卷缺失/标记不符则明确失败，不悄悄写回内盘。已有环境变量显式覆盖仍可用。

不移动正在运行的产物，不删除历史 `.tmp`、`.data` 或回执。本轮不改变真机签名构建路径：既有外盘签名失败根因尚未解决。其他工作树须集成本包代码后才自动采用这些入口，不能宣称所有 Agent 已迁移。

## 验收与停止条件

先跑红灯测试，再实现：时间边界/晚传/时钟精度与不确定度、三类字段、缺失与坏深度帧、重复/冲突、坏摘要/中断/事务回滚、相邻采集与分页、来源关联；路径隔离、外盘缺失/标记/符号链接、无配置兼容。保留失败日志。

通过后运行已有归档回归、脚本回归与仓库检查，Linux 在独立 synthetic 会话重跑同一合成用例并查询回读。没有真实录像、传感器格式、空间融合、采集容量或真机验收；不跑完整 UI。发现原件变更、共享树并发修改、目标盘身份不符或需要未知权限时停止相关动作，不覆盖旧证据。

依据：[SQLite 关于同主机和网络文件系统的限制](https://sqlite.org/wal.html)；[MCAP 消息区分记录时间与发布时间](https://mcap.dev/spec)。本包借鉴时间来源分离，不引入 MCAP/ROS 或新数据库服务。
