## 目标与边界

- 目标是缩短机器/Agent 的反馈与收尾周期，不是减少用户值守时间。保留自动执行、失败证据和严格验收。
- 不改产品 UI、算法、数据格式、CI 触发，不更新采集设备，不操作签名/网络，不做跨提交回执复用。
- 原记录、原片、未提交内容和旧回执保留。测试只用隔离合成数据；只管理本任务模拟器，结束或取消释放资源。
- 当前采集版本不变。M2 可多轮接收，每次补采有具体问题；真实训练复核先于对外首发。Duo 悬停/真机边界保留。

## 先失败测试清单

1. 设计命令拒绝未知/重复/缺值参数和未知组；组合组去重且保留完整场景。
2. 设计执行的私人输入、错误分类和环境失败发生在模拟器分配前；借用现有协调器而不是按名称挑设备。
3. 实际 native log 必须精确包含选中方法；缺方法、skip、失败均保留失败回执；取消和释放失败不返回绿色。
4. 设计收集检查每个方法与场景，截图缺失不可冒充完整设计证据。独立 collect 不冒充源码已验证。
5. 场景划分无重复、无漏项；完整与 smoke 入口含义清楚，正式套件仍执行所有保证。
6. 截图 AX 查询批处理保留相同标识、frame/label/hittable/enabled，不将点击替换成内部状态操作。
7. 有界诊断不改变原单次输入、次数、方向断言；超时/取消保留失败与进程退出证据。XCTest 方法上限经对照未采纳，保留外层预算，不以私有开关或关闭动画换通过。
8. 耗时统计对失败、取消、重叠窗口、缺失时间明确处理，不把未完成当零成本或自动成功。

## 验证与效率指标

复用 `tests/verification/catalogue.json`、`verify:fast`、`verify:candidate`、`verify:receipt`。先脚本与宿主反例，再定向模拟器；定向收束后冻结候选，执行完整 public 与 Duo 专项。各步不是每次都跑全量。若保留原工作树的未提交内容，使用独立候选副本，不能将原树称为干净候选。

历史 public+Duo 约 58.22 分钟只作背景。日常温缓存定向 5–10 分钟、完整 40–45 分钟是目标而非放松断言的理由。比较注明候选/执行器、输入、环境和缓存；无受控对照不报告因果提速百分比。同一未知失败无新假设不重跑完整套件。

覆盖迁移逐项列出原保证、承接方法和保留的反例。纯静态检查若无法证明等价，本轮继续保留 UI 路径，不强行下沉。

## IMP-3 选择门槛

以当前源码为基线、合成内容为候选，不向云端上传采集材料。三节点分别回答：现在处于什么状态、下一步是什么、此前结果保留了吗、操作影响哪份数据。Product Design 辅助审查；Figma 仅在画布有增益时使用，不维护第二份 App。

当前设备上的可读性、持重触控、真实丢点恢复和听感不由模拟器证明。无本轮画面或操作证据的判断标为设计推演，不能冒充已发现缺陷。

## 停止与交付

停止条件：原件/本地改动风险、其他任务占用模拟器、工具链缺失、容量低于既有安全线、候选或输入漂移。取消保留现场，不无限重试。正常技术子步骤自动推进，不逐项请求同意。

交付包含台账、测试/失败记录、候选绑定回执、实际耗时边界、设计候选与推荐。最终停在 UI 方案选择，不自动推进 IMP-4、算法、新动作或上架。
