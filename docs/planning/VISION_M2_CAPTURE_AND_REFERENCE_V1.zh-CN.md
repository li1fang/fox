# 视觉 M2：两部分采集与统一评测 V1

日期：2026-10-25（Asia/Bangkok）。状态：计划已建立，采集、时间对齐及新评测尚未执行。

本文的 M2 指 [Duo 后回归视觉路线](DUO_M0_M4.zh-CN.md) 中的 M2，不是已完成的旧 FIT-M2 端侧回放任务。新任务使用 `VIS-M2-*`，避免复用历史编号。

## 1. 目标、范围与不变量

目标：先验证现有弯举、侧平举、高位下拉，再用更宽的候选录像判断后续适配价值。Part One 使用 Fox；Part Two 只录像。统一接收与分析，不混淆证据等级，不要求两部分同一天完成。

- 本轮面向个人使用，不为首发动作数量扩展算法；记录能力、视觉计数、返回测量和动作质量判断分别成熟。
- 手柄是独立参考采集工具，不是 Fox 的控制器或计数输入。用户负责提供可访问的 6DoF/时间数据；复用现有读取成果，不重建 Quest 链路。
- iPad 与手柄接收端分别保存，事后时间对齐。不实时向 iPad 转发，不做传感器融合、深度、双机实时控制、ASR/LLM 或全身动捕。
- 握持手柄模拟属于 `controller_simulation`，不是负重训练验收。实际器材/哑铃样本另记 `loaded_exercise` 或 `bodyweight_exercise`，未知则明确未知。
- 不改已确认训练记录、不把模拟运动冒充正式训练、不把手柄候选标签当成已审核真值。没有完整返回，不补造离心时长。
- 本轮交付文档和测试设计，不实现导入器、改算法、部署 App、操作设备或读取 HealthKit 数据。

## 2. 基线与采集前准备

开发基线为本地提交 `7691d80f0305eb36577b77de91844e3cfc963e80`，含已接收的 API 边界修复；公开 Web 回执不是视觉/原生验收。Duo M0/M1 的原生/专项证据保留原提交身份，不能冒充此提交重新运行。

目前 CURRENT 记载已安装试用候选为 0.6.8/build 26。本轮不核查设备；采集时记下实际 App/build/参数，不把开发 HEAD 当作已安装源码。精确源码关联不可得时保留未知，不要求为此次采集升级到最新开发代码。

采集前只需完成一次短探针：

1. 确认 Fox 正常启动、动作/观察侧可选择、录像核对与保留入口可用。若需续签，另行保留记录后处理，不卸载 App。
2. 设备固定，使用日常实际倾角和光线；不要求垂直。记横竖屏、前摄、倾角（可读时）、身体朝向与画面范围。每段不旋转屏幕或改机位。
3. 用户启动手柄记录，确认左右侧、位置与姿态、来源时钟及追踪状态确实保存；丢追踪或重新定位后先恢复，再开始新段。
4. 做一段约 20 秒的探针，确认 Fox 保留包有可播放视频、姿态/事件日志，手柄文件可访问，并能找到两个共同时间锚。先核对文件，不把收发 ACK 当采集成功。

探针不通过时只停用该样本的参考标签资格，不阻止正常运动或 Part Two 录像。不能因为参考通道尚未接好而无限延后训练。

## 3. Part One：用 Fox 验证既有三动作

优先使用现有独立视觉试验入口，保留报告和诊断包，不确认成正常负重训练。若使用训练入口，须明确这是独立测试会话，不能覆盖真实历史；采集元数据的模拟标记先保存在外部清单，不假设 App 已有该字段。

第一轮直接握持手柄，不同时握哑铃，不绑到器材，也不制作固定装置。以可控、舒适的小幅探针确认追踪，再做下面的动作模拟；这不是个体训练处方，不追求疲劳或力竭。

### 必采清单

| case ID | 内容 | Fox 设置与画面 | 计划运动（实际以录像复核） |
| --- | --- | --- | --- |
| P1-CURL-L | 左臂手柄模拟弯举 | 侧面，明确选择左臂；肩、肘、腕尽量可见 | 约 5 个完整抬起/放回周期 |
| P1-CURL-R | 右臂手柄模拟弯举 | 转向另一侧，明确选择右臂；单独开始一段 | 约 5 个完整周期 |
| P1-LATERAL | 双手柄模拟侧平举 | 正面，记清 Fox 实际选择的观察臂 | 约 5 个完整举起/放回周期；分别保存双手参考，不假设 Fox 独立双臂计数 |
| P1-PULLDOWN | 双手柄模拟高位下拉 | 背面上半身，优先沿旧样本的坐姿/构图；肩、肘、腕可见 | 约 5 次收缩端到达；前几次有返回，最后一次收缩后结束 |

P1-PULLDOWN 是模拟拉动，不要求在持手柄时抓真实把手。它只能验证该运动几何下的准备/计次/阶段链路，不能验证真实器械遮挡与负重疲劳。真实器材使用另放 Part Two。

每段建议 45-90 秒、独立保留，含就位、动作前后短暂停留。约 5 次只是组织录制的目标，不凭目标填参考次数；不必为了凑数重录。先四段基本样本，再决定是否补挑战，不先做大量负例。

### 可选挑战（基本样本完成后再选）

- 弯举：在正常放低处自然停留，观察首轮是否漏计；或一次短暂腕部遮挡后继续，避免靠奇怪姿势迁就计数。
- 侧平举：中途停顿或一次自然的短缺点后继续，检查恢复是否丢掉后续完整动作。
- 高位下拉：清楚留下最后一个收缩端，随后结束，不为让软件发布数据额外虚做下一次。
- 结束/准备阶段留少量普通摆手或静止画面作为非动作对照；不故意做危险幅度或快速甩动。

每种挑战独立记明，不把未知的自然遮挡时长写成精确故障注入值。基本样本和挑战样本分别出结果。

### 使用与保留

1. 先开始手柄记录；进入 Fox，核对动作/观察侧，点击就位后走现有准备/启动流程。
2. Fox 的诊断录像从视觉尝试时临时开始，普通预览不录；保留准备失败、首轮和恢复画面，不等成功启动才留证。
3. 在视频确实录制的时间范围内留首尾同步窗口；同步段不算训练，评价窗口另行标注。同步动作若触发了次数也保留原始结果，并在准备/非运动误计项单列，不悄悄抹掉。
4. 完成或取消后，核对报告并点「保留诊断」，再结束本段手柄记录。成功段、失败启动段都可保留；不要求开始前决定是否有问题。
5. 不剪裁或覆盖原件。每段记录 case ID 与实际诊断 UUID/手柄文件，忘记次数也没关系，回放再核对。

现有 Fox 诊断包是无声的 H.264 视频，通常上限 5 分钟/200 MiB；方向/尺寸变化会结束该段，临时缓存还可能过期。不要录成一整场长片，也不要靠音轨或后期击掌对齐。流程以[诊断录像约定](../fitness/VISION_DIAGNOSTIC_CAPTURE_V1.zh-CN.md)和实际构建为准。

## 4. Part Two：候选动作只录像，不强行套现有计数器

可以本轮覆盖较多动作，但只扩展采集，不承诺同时适配。视频不必有 6DoF；没有手柄参考仍是有效观察素材，不为卷腹/平板支撑强行握持手柄。

每个动态动作先一段、约 4-6 个舒适完整周期；静态动作一段约 15-25 秒即可。时长和次数是拍摄组织建议，不是训练量要求；可分日完成，真实次数以回放为准。只做用户已经会且愿意做的动作，不因采集学习新难度。

| 顺序 / case ID | 动作与首选视角 | 采集价值与边界 |
| --- | --- | --- |
| 1 / P2-CRUNCH | 卷腹，侧面 | 肩、躯干、髋、膝尽量完整；留自然放回及结束，不混淆普通头动/坐起 |
| 2 / P2-PLANK | 平板支撑，侧面 | 拍进入、维持、正常退出；首先评估可见性/持续时间，不计算「次数」或承诺腰背标准性评分 |
| 3 / P2-TRX-ROW | TRX 划船，斜侧面 | 拍锚点/带方向、手臂与躯干；记录身体倾角，观察拉近/放回与绳带遮挡 |
| 4 / P2-TRX-PRESS | TRX 胸推，斜侧面（可选） | 仅已有熟练动作时采集；与划船分段，不把所有 TRX 动作当一个模型 |
| 5 / P2-SQUAT | 自重深蹲或坐站，侧面二选一并注明 | 从头到足；看髋/膝/踝连续性；若构图需要更远才移动设备，不强求原上半身机位 |
| 6 / P2-HINGE | 熟悉的髋铰链，侧面（可选） | 已会哑铃罗马尼亚硬拉则用轻负重并记每只重量；否则可选臀桥并明确名称，不能把二者当同一策略 |
| 7 / P2-PULLDOWN-REAL | 真实高位下拉，背面上半身（可选） | 不持手柄；与 P1 模拟构成器械遮挡/负重的域差异对照，重量未知则留未知 |
| 8 / P2-DUMBBELL | 真实弯举/侧平举（可选） | 延续 P1 视角、记录每只重量，观察握持、遮挡及动作轨迹变化；不同时握手柄 |
| 9 / P2-BENCH | 已熟悉的哑铃卧推（额外候选） | 保留已讨论头端/背后视角及可见范围；不挤占前述优先项，不宣称只见头手即可可靠适配 |

基本目标为前五项（TRX 胸推为可选），其余是精力允许时补充。优先卷腹、TRX 划船、平板支撑和一个下肢动作，不为一天录齐透支。TRX 先确认现有锚点稳固，保持日常保守用法；出现不适就停止该段，数据无需凑齐。

建议用日常 iPad/iPhone 原生相机录制；能用与 Part One 相同的前摄和实际机位最好，不把「最佳灯光、无杂物、设备垂直」设成条件。每种新构图开始静止几秒，结束后也留几秒；保持机位不动，失败或路人经过不必全部剪掉。记录设备、前/后摄、方向、是否镜像；看不到的关节保留为不可见。

## 5. 时间对齐与数据契约

### 最小交接清单（设计，不代表导入器已实现）

每个 case 关联以下信息；尽量由文件提取，仅补机器无法知道的内容：

- `collection_id` / `case_id` / `part` / 实际动作与观察侧；`planned_reps` 与 `reviewed_reps` 分开，后者可先未知。
- `source_kind`、每只负重或无负重、机位/视角、用户说明；Part One 的 App/build、报告/诊断 UUID 与配置身份。
- 视频原件路径/字节数/SHA-256、时长/帧率/旋转/镜像、实际视频时间轴；起止墙钟只作辅助关联。
- 手柄原始文件路径/SHA-256、左右侧、样本序号、原始来源时间及单位/时钟域、位置与四元数、参考坐标系和重置/重定位事件。
- 原接口可得的 position/orientation valid/tracked、pose_active 状态、按键，以及原生/推算/预测时间语义；原接口未提供则标未知，不能凭坐标存在就补成 tracked。
- 同步锚、映射方法/版本、偏移与漂移、残差/不确定性和可用时间范围；轨迹候选标签、人工核对版本与未定窗口独立保存。

第一轮不改用户数据库，不新建第二个任务系统。优先将 sidecar 放在私有素材旁；收到真实文件后才确定适配现有手柄字段的最小解析契约，不要求用户手工改 JSONL。

### 同步方法与退出条件

1. 每段开始、结束各留一个短、独特、画面中可辨认的手部运动序列，例如三个幅度不同的小摆动；它与手柄轨迹对应。可同时记录按钮事件作为辅助，但不把按钮时刻自动等同于画面事件。
2. Fox 无声音，故默认采用可见运动锚；Part Two 即使有音轨，也不把事后补声当现场同步时钟。同步段、训练段和休息段有独立时间窗口。
3. 将来源时钟映射到原视频秒数，短段先检验固定偏移是否足够，再检查首尾漂移。保留原时钟，不使用文件修改时间或「同时点击开始」冒充精确同步。
4. 对齐应独立于 Fox 的次数/阶段结果；不能按每次运动单独拉伸/平移到吻合。手柄断流、重定位或更换时钟必须分段，不能盲插值穿过缺口。
5. 对齐误差不确定性目标为不超过 100 ms（本次拟定目标，不是已达到）。两锚恰好可拟合不代表误差为零；还要用中间可见事件交叉核验，记录视频帧量化、人工选帧及来源采样的不确定性。达不到或无法估计时，不报告精确阶段误差；保留粗周期/可观察性结论和需补采说明。

当前 Fox 实时推理约限 12 Hz，实际间隔以包内数据为准。约 72 Hz 的手柄参考不让视觉自动拥有同等精度；比较时报告两端采样间隔和对齐误差。

### 原件与路径

- Part One 继续使用 `vision:pull` / `vision:import`，将已保留包校验落入 `.data/vision-diagnostics/inbox/<UUID>`；原设备文件不自动删除。
- Part Two 通过现有 `vision:corpus` 接收至 `.data/vision-corpus/<collection-case-id>`；先探测真实编码/时间轴并核对 SHA。默认复制并核验，不自动使用 `--move`；需要移动时再明确处理。
- 手柄原件保留用户提供的位置及摘要；需集中副本时放在对应私有 corpus 目录的参考子目录，记录来源，不伪造为 Fox 原生包的内部文件。
- 保留全画面。分段先用原时间轴上的虚拟窗口；派生剪辑另存并记录裁切偏移，不覆盖唯一原件。真实 MOV/MP4 后缀与编码按原件保留；现有 corpus 脚本固定命名 `.mov`，遇非 MOV 输入先核对/做有限接入，不直接把改后缀当转码或宣称导入已支持。
- 复用 `.data/vision-evidence/runs/` 及可重建索引。既有运行档案并不自动支持手柄输入；需要的最小 sidecar/输入摘要扩展先测试后实现，不修改或重封旧原生包。私人素材、时间戳及逐样本元数据不进入 git/公开 CI。

## 6. 统一分析，分别作结论

两部分共用接收、完整性、媒体检查、主体选择、关节连续性、动作周期及证据分级流程；Part Two 可在接收后由现有端侧 observation-only 入口重新推理。外部相机录像的回放不等于 Fox 当时实时处理；模拟器画面不证明真人准确性。

| 维度 | Part One：既有能力回归 | Part Two：候选可观察性 |
| --- | --- | --- |
| 主体与关节 | 核对选择对象、左右侧、缺点长度、可见关节及恢复前后连续性 | 找必要关节/代理量，区分不可见、误配、躯干平移和真实周期 |
| 准备/启动 | 记录就位到启动时间、首次是否成功、是否必须迁就姿势；失败包也是有效输入 | 不适用，不能因没计时就算识别失败 |
| 逐次计数 | 匹配每次完整周期/收缩端，单列首轮漏计、重复与误计，不用总数抵消 | 先人工核对周期，评估是否有足够观测设计策略；不套既有动作名凑次数 |
| 恢复 | 缺口类型、时长、保留的已完成次数、恢复后下一次，禁止跨长缺口补动作 | 只判断可恢复的观测范围，不宣称尚不存在的恢复策略已通过 |
| 阶段/节奏 | 视觉角度返回与手部返回分开报告；仅边界含义一致、同步可信的区间才比较 | 先定义周期/静态维持区间；平板支撑不按峰谷/重复计分 |
| 提示体验 | 留是否报数过早/重复、阶段提示是否及时、是否影响使用的简短反馈 | 不验收不存在的提示，不生成标准性或总分 |

弯举/侧平举是完整周期计次；高位下拉是收缩端计次，前次返回在下一有效收缩端发布，末次不发布自身返回。可参照[三动作策略](../fitness/VISION_STRATEGY_AND_EVIDENCE_V1.zh-CN.md)，不把高位下拉最后少一段时长判为漏洞。

6DoF 只覆盖手柄参考点，不自动给肘/肩标签。手部峰谷是候选相位，不等于关节角度阈值或肌肉离心起止；手柄模拟没有真实哑铃负荷，更不声称测得肌肉离心控制。边界不一致写 `not_comparable`，不以两个无同义时长之差计算「离心准确率」。

接收、同步、时间匹配窗口及阶段定义先冻结，再看算法分数；不根据结果反复调评测规则。先完整报告本次结果，再按独立片段保留开发集/留出集；同一段裁成两半不能宣称是独立新条件验收。只有一个独立片段的动作只作探索，后续补新段再谈泛化。

最终每个动作分别给出：继续现状、有限修复、进入适配、需要指定补采、暂缓。允许一个动作有好结论、另一个仍不可用，不将全批处理完成写成全批可靠。更多动作的决定在分析后做，不在本轮一并开发。

真实采集由用户完成；可自动完成的文件校验、索引、回放及汇总不逐步请求人工批准。若对齐/接入代码需要补开发，先完成 focused tests，再按当前变更选择公开/私人分片；冻结候选后不改树，不为纯工具/文档修改全跑模拟器。设备回放若需要前台/解锁，再一次性协调，不开启断网实验。

## 8. 个人健身后续与发行边界

- 个人使用方向：现有三动作 -> 核心/TRX/下肢的可观察性 -> 按证据选择适配。计划/手动记录可以先覆盖，不能可靠视觉跟踪的动作仍可正常记录，不承诺每个动作自动计数。
- 有氧视觉不在本轮目标。后续 `INPUT-01` 优先评估 iPhone 只读 HealthKit 的 `stepCount` / `activeEnergyBurned`，再决定是否需要步行距离等；不是抓取「健身」App 界面。
- 活动能量不等于仅走路的消耗，也不等于含静息代谢的总消耗。保留来源、时间区间、时区、单位、去重与缺失语义，不将设备/训练/全天重复相加。无法读取不能直接显示零，也不能保证区分拒绝读取与没有数据。
- HealthKit capability/账号/签名/用户授权、真实数据可得性在该任务启动时再核对。M2 不申请权限、不写入健康数据，不把它设为采集依赖。
- 发行版/Beta 共用代码和证据，按动作的计数/阶段/提示能力分别开放；本轮不做商店发布、TestFlight 配置或两套长期分叉实现。录得更多动作不代表全部进入发行版。

官方依据（2026-10-25 核对）：[步数](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/stepcount)、[活动能量](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/activeenergyburned)、[健康数据授权](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)。

## 9. 给采集者的短清单

1. 先做一段短探针，确认视频和手柄文件都留下了；普通预览不是录像。
2. Part One：侧身左弯举、另一侧右弯举、正面侧平举、背面模拟下拉，各一段，约 5 次，Fox 实际观察侧要记清。
3. 每段视频内留首尾同步动作；动作完成后核对并「保留诊断」，成功或失败都可留。不要凭计划次数补参考。
4. Part Two：卷腹、平板支撑、TRX 划船、深蹲/坐站优先；其他项有精力再录。原生相机即可，不用 Fox 假装支持新动作。
5. 给开发者原视频/诊断包、手柄原始文件位置、每段动作和实际负重、异常说明；不需要手工标骨架或剪辑，不需要设备实时互联。

本轮文档验收：相关入口/台账一致、相对链接与仓库公开边界检查通过、`git diff --check` 通过。未运行采集、算法、设备、同步或 HealthKit 验收；未来实现的测试与结果另行归档，不能将本节设计当已执行。
