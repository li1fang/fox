## 保护边界

- 原 main、未提交源码和 15 个本地提交保留；交付分支不直接推送这 15 个未经公开审计的提交历史。
- 第一笔提交是一次如实整理的现有功能基线，不伪造过去开发的逐步提交；后续提交分开开发方式改进。
- 0.6.8/build 25 的设备及其历史证据不被新工作流覆盖。计数、训练及存储行为不改；除测试输入和开发工具外，按用户授权补一处诊断收尾状态的页面通知，不改变布局或锁定策略。
- 恢复点是本机副本，不声称完成异地备份。新源码、视频和业务记录仍分开存放。
- 第三方 UI 原稿的公开分发权不明确，仅保留本项目的实践分析和引用说明；私人动作标签由输入清单读取。

## 自动继续规则

每层通过后继续下一层，无需逐步用户批准。失败先保留回执、定位、修正，再新建运行；不删断言、不自动改历史答案、不把环境失败解释为算法退步。输入改变、公开权限不明、设备数据风险或需求冲突时停在具体边界。

## 审查带来的修正

独立上下文审查指出验证器也会误报成功。先加入失败反例，再修复：超时子进程退出 0、最终输入复核时取消、日志无法打开/写满、嵌套测试漏发现、Python expected failure、固定私人文件与实际消费的相邻文件错配。对应脚本测试 20 项通过；三段私人可观察性分析继续通过。第一次完整 private 运行在 UI 阶段主动取消，保留取消回执，不当作完成；最终完整结果必须与 PR 当前提交匹配。

第一轮远端 CI 揭示 Homebrew 最新版 XcodeGen 已变为 2.46，doctor 按契约拒绝。改为下载官方 2.45.3 并核对发布 SHA-256，不放宽版本检查；公开日志上传显式允许 `.tmp` 中的精确白名单文件。此类环境修复也需新提交、新回执，不复用旧提交的本地绿色。

第二次审查补充覆盖未来测试布局：带属性/访问修饰符的 Swift 方法必须登记，Python 按清单逐文件执行而非依赖目录包发现。新增嵌套失败、空文件、嵌套通过和 expected failure 反例，防止新测试被静默遗漏。完整执行以最终提交为准，中途为修正而取消的运行全部保留。

完整 private 首次跑到 iPad UI 时，51 项通过、1 项横屏断言失败。同一未修改用例在原实例再次失败，而同型号/运行时的新实例通过；这是环境敏感性证据，不声称已确定系统根因。验证工具改为默认创建和清理专属模拟器，先增加所有权、部分分配失败、清理失败及取消反例；原断言和产品源码不改，也不自动重试。最终交付仍要求新提交的完整运行，而不是拿单测通过代替整套验收。

模拟器隔离的独立审查进一步复现了系统取消信号被同步清理延迟处理的情况。增加真实子进程 SIGTERM 反例，改为有超时的异步模拟器操作，并在最终回执落盘后再释放信号处理；仅用进程内 `emit` 不足以证明该边界。为修复而中止的候选仍保留取消回执。

最终状态改为单次原子提交：取消碰上磁盘写满时，正式回执仍是 running，不会留下需要事后修正的绿色。对应故障注入先复现了旧回执被错误接受，再验证新提交点；这不等于承诺断电时仍有终态报告。

首次完整云端原生运行在 iPad UI 通过 49/52 项后被整批 45 分钟时限截断，没有已完成用例失败。按实际执行耗时将该批次预算改为 60 分钟，保留原超时证据及全部用例，不放宽断言、不加重试。仍须完整新运行证明通过。

随后完整 private 的 iPad 52 项全部通过，iPhone 14 项通过、2 项失败，真实语音尚未执行。诊断发现反馈输入框与固定提交区重叠，另一项连续单击未应用第一次选择。测试增加旋转完成、目标完整可见/位置稳定、单击后选中状态、键盘及输入值检查；滚动改用实际表单边缘，避免手势落入多行输入框。首次准备条件修正仍未滚到目标，继续保留失败；修正滚动路径后，两项用例连续三轮通过。生产 UI、训练逻辑和原结果断言未改，也不声称已经证明所有触屏/滚动体验可靠。独立审查通过，最终仍须当前提交的完整 private 与 CI，不用局部成功替代。

该提交的完整本地 private 随后通过，但云端 iPad 50/52 通过、2 项失败：诊断未观察到两次计数，训练测试单击后仍停在休息页。先补测试准备条件与单击后的状态验证；诊断保留原始 15 秒共享期限及精确两次断言，并将失败状态写入公开合成测试日志，不导出录像。当前证据不能确定是未启动、运行调度间隙还是其他问题，不修改样本时钟或动作逻辑来猜测修复。两项针对性用例连续三轮通过，独立审查无阻断；新提交仍须完整验证。

再一轮完整本地 iPad 51/52 通过，另一项“走入画面后自动开始”在已启动后只计到 1 次，画面显示发生过一次重置。受控回归随后复现了生成器缺陷：固定帧序列使用主机交付时间作为 capture PTS，主机暂停会被解释为素材断档，正常两次变为零次。先保留失败，再仅将 UI 合成输入改为固定样本 PTS；真实接收时间、相机、回放和计数器均不改。新测试逐项比较两侧弯举/侧平举的计数和阶段事实，并确认真实采集断档仍拒绝不完整周期。新测试由失败转为通过，四项 UI 用例（诊断、走入画面、弯举/侧平举切换、高位下拉）连续两轮通过。这证明生成器的缺陷及修复，不声称已获取此前每次失败的原始帧时间，也不以此替代完整验证。

最后核对执行数量时发现两项新增 App-host 测试漏填 `surface`，定向运行通过但整套未选择它们。该候选本地与 CI 主动取消，不能作为验收。补上平台登记，并先用反例证明旧校验器接受缺失/错误平台、组装器会静默漏选；修复后 29 项验证工具测试通过。现在分类检查和整套原生选择集合分别兜底，不用单项通过代替完整覆盖。最终仍须新提交的完整回执。
