# B 方案实施与分组验收

日期：2026-10-26。用户授权连续实施 B0～B3；暂停动画采集器，不再将其根因修复作为产品开发前置条件。

## 工作契约

- 目标：稳定主画面与操作位置，以任务区解释准备、恢复、核对与保存。
- 范围：独立视觉页、训练内视觉状态、结果核对、录像状态，以及对应自动化。
- 不变量：计数/恢复/离心算法和存储契约不变；人工参考不冒充视觉事实；未观察返回不补时长；录像取舍不提交或删除训练报告。
- 不做：动画采集器继续取证、CI 修改、新环境、采集设备安装、签名、网络变化、新动作。
- 保留：现有本地改动、记录、原失败与测试回执。先写失败测试，再改行为。
- 停止条件：数据风险、所有权冲突、环境缺失。已知动画等待只停止当前受影响测试组，不启动调试器、不重试到绿；新产品失败必须定位修复，不能归并为旧故障。

## 先设计的测试

1. 状态表：空闲、等待、倒计时、短暂缺点、主体丢失、恢复准备、暂停、已保存。恢复提示保留原自动数，不用预测阶段或未观察时长。
2. 独立视觉故事：点击后离开屏幕、自动开始、丢失后次数保留、主要操作完整可见。准备与活动均截图；旋转不能创建第二个预览。
3. 训练内故事：同组恢复后继续计数，结果与原观测区分；不以独立视觉页通过替代训练入口。
4. 核对保存：结果先于录像、参考次数可空但非法值拒绝、明确保存回执；真实键盘输入后保存重开另组执行。
5. 数据反例：保存失败保留在途报告，恢复后一次保存，重复保存不重复；旧录像不冒充本次录像，保留/丢弃失败不改为成功。
6. 回归：既有核心、真实控制器合成回放、诊断、布局/预览身份；私人录像若输入未提供则列为未覆盖，不声称真实准确率。

## 验证纪律

复用 catalogue、runSuite、doctor、模拟器租约与清理。定向分组只作为 scoped verification，不改 public/private 的全覆盖要求，不删除或跳过原断言。新增方法登记到现有目录。

- 无键盘组和真实输入组分开；首次日志出现既有 `native_automation_idle_timeout` 即保留失败回执，暂停该组。没有相同证据的失败保持独立分类。
- 每台设备串行运行，只有自有模拟器可停止/清理；不重启系统、不管理他人的实例。构建缓存使用既有外置目录，回执仍在本地忽略目录。
- 不在验证过程中编辑受测源码。源码/测试变化后旧通过仅为定位证据；最终结果绑定源码指纹，不能跨提交复用。
- 本轮允许完成实现和分组验收，但若关键输入仍受阻，不标记完整 B/完整原生/发布验收通过。真机远距离可读、真实训练、Duo 铰链/镜头仍需另验。
