# N3 本地记录闭环

日期：2026-10-17。状态：0.5.1/build 12 软件候选及本地自动验收已就绪，真机签名构建/校验、更新安装与解锁后的启动均通过，运行进程已核对。后续两条真人照片记录已核验落库；更正和系统文件备份仍待实际验收，仍非生产版。

## 本轮目标

在同一个原生 Fox 中接通照片、文字、修订与本地备份。沿用 FoxJournalCore，不迁移训练 JSON，不增加 AI、分类估计、HealthKit、ASR、设备互联或新训练动作。只部署明确的 iPhone，iPad 保留原候选。

- 纯文字、纯照片、图文记录；原生相机与系统相册选择。相册使用 PhotosPicker，不申请整个照片库读取权限。
- 图片在后台验证真实格式并生成限尺寸预览；选择器交付的原始编码字节保存到核心，不以裁剪缩略图替代原图。相机 UIImage 交付则编码为 JPEG 后作为该记录照片，不宣称 RAW/传感器原图。
- 点击保存才成为记录；加载图片、写入或备份失败不清文字、已有照片。保存中避免并发修改；原样重试复用稳定 ID、时间及照片内容。
- 详情可更正文字、添加/移除当前照片；保留历史和不可变登记时间，不自动把留言变成事实。修订冲突不覆盖新版本，载入新版本须确认放弃当前更正。
- 删除需确认，使用 expectedRevision；逻辑删除与照片清理结果分别反馈，不承诺取证级擦除，也不删除旧备份。
- 通过系统“文件”选择器导出/导入现有完整备份目录（manifest.json + attachments），不自研 ZIP 格式、不默认上传。恢复以核心完整校验与事务为准，冲突整份拒绝，重复恢复不重复记录。
- 列表按页浏览，不用原来的 1000 条界面上限冒充完整档案。

安全边界：备份包含敏感原文和照片，没有额外加密；只有用户主动选择目标后才导出。系统相册中的未下载照片、第三方文件提供器可能需要网络；获取失败明确保留输入，本机保存不依赖网络。当前未保存输入仅在页面存活期间保留；跨强制退出草稿恢复、发生时间编辑、完整搜索、独立训练卡投影后置。

## 自动验收

1. 新增 App 层 XCTest：使用独立临时目录和真实 FoxJournalCore，覆盖图文/纯照片/重开、图片错误、保存失败及重复点击、过期更正、原历史/照片字节、删除、完整备份导出/恢复/重复恢复/损坏与冲突拒绝。实际系统“文件”拷贝成功和真实相机不靠 fixture 冒充。
2. Simulator XCTest UI：保留原 Home/训练用例；新增测试照片经过同一验证/保存路径、照片与文字失败保留、更正/重开、权限拒绝可纯文字、备份入口/取消。测试输入严格 gated 到 FOX_UI_TESTING，存储目录与正式资料分离。
3. 训练核心、记录核心、Schema、完整既有原生 UI 回归。新媒体/备份不改计时和视觉算法。
4. 原计划在 iPhone 安装前处理输入并保留快照；后续用户明确当前为测试数据、可直接升级，本次按授权直接覆盖安装，不卸载、不清空。生产版后的保留与升级验收仍需另行确定。iPad 不升级。

## 实施决策

用 UIKit 相机和 UIDocumentPicker、SwiftUI PhotosPicker/原生卡片；媒体处理与文件操作离开主线程。需要的 Apple/XcodeGen API 以 [PhotosPickerItem](https://developer.apple.com/documentation/photosui/photospickeritem)、[ProjectSpec](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md) 为接口参考，不引入第三方同步/图像/压缩服务。

本文件随实际测试结果更新，不将计划勾选成验收。

## 已实施

- `JournalStore` 通过后台 actor 调用原存储核心，图片校验/缩略图和文件处理不阻塞主线程；照片移除只影响当前版本，不抹掉历史修订。
- Home 的拍照、相册、保存接真实存储；详情接更正/删除；工具栏接完整备份目录导入/导出。原训练入口保留，不迁移原文件、不改计数门槛。
- 新增 `FoxAppTests` 与 `npm run test:home`；默认 `test:ipad:ui` 仍跑 UI 包，需要完整 App + UI 时显式选择两个包。GitHub Actions 增加 App 测试入口，但本轮未推送、未运行云端 CI。
- 普通设备 `open` 不再强制终止既有进程；有显式环境参数或 `FOX_IOS_RELAUNCH=1` 才重启。安装升级仍可能结束进程，须先处理用户未保存输入。
