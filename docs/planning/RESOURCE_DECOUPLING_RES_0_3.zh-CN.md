# RES-0 至 RES-3：资源准入与独立验证

2026-10-28。负责人：产品与交付；用户已授权连续实施。沿用既有脚本、测试目录、回执与模拟器租约，不建立调度服务或第二套台账。

## 目标与边界

让日常模块验证不必启动整套 App，并防止直接 Swift/原生构建绕过现有模拟器共享占用。减少的是不必要的资源依赖，不是断言或最终覆盖。

保留所有工作树改动、设备原件、记录和历史失败。客户端当前候选在独立树验收；本树不修改其源码或终止其进程。视觉线的 Linux 公开核心入口优先复用，不另造远端执行器。数据与服务仍负责信息处理，不因新增验证入口回到基础设施全包责任。

不改 CI、产品行为、数据库或算法，不部署/操作真机，不追查动画框架，不自动回收来源不明的锁，不跨提交复用验收。

先写脚本反例并保留红灯，再实现；所有新测试登记到原 catalogue。原生窗口不可用时先做 Node/Python 无模拟器验证，不为得到回执重启/停止他人任务。内盘容量不足时不启动新重型批次；构建缓存可使用显式独立外盘目录，不删除证据。

## 流程与代码的区别

- 流程：一树一个写入者；任务声明验证范围；先轻量契约，后必要的平台集成；未知占用先协调；候选冻结后不再编辑树；独立工作线候选与已安装版分开。
- 工具代码：补准入入口、有界取消、选择/审计与资源回执，拆开验证阶段依赖。
- 产品代码：仅当测试证明必须局部提取才能独立验证才改；不为目录整齐重构。

已证明的是：这几类确定性修改能不启动 App、不创建 iPhone/iPad、不访问真实数据而得到原断言结果；数据工作不需要等待原生资源，客户端/视觉不必搭建 Apple App 宿主。没有用一次任务对比另一种任务宣布百分比提速。新客户端分支的 store/布局尚未进入本树，当前 client lane 不能代替它们的验收。

视觉投影复用独立工作线已提交的 `667abd3c996e607ebafcb0468a3fab0fc5b435a5`；其 Linux 同源 41 项结果及 PA 模型运行属于该线证据。本轮扩展类选择/check 入口并在 Mac 验证，不重写算法、不宣称重跑了 Linux 或新增模型准确率。

### 仍需保留的边界

- 完整 public 的原动画欠验未关闭，真机、UI、Keychain、实时视觉和实际语音没有由本轮重新验收。
- 其他树正在冻结验收时不热改脚本；应在其下一候选集成本轮提交后使用新准入。旧租约兼容不等于所有旧原生命令都已自动受控。
- SDK 默认检查与 public/private 精确选集保留；低耦合先体现在编译/验证路径，不为目录整齐拆产品包。
- 暂无常驻队列、FIFO 保证或自动过期回收。资源未知、残留进程与低容量先协调；外盘缓存不解决系统盘容量的所有问题。
- 进程观察不是容器隔离：确认自有进程组与已观察到的后代停止，无法观察或写回执失败时不释放不确定租约；不承诺回收在采样前已脱离父关系的后台 daemon。Linux 直接投影 runner 只清理自己的进程组，仍须由既有容器生命周期约束。
