# 个人资料库同步 v1

负责人：产品与交付；核心与服务归数据与服务，后续客户端协作。2026-10-28。

## 范围与不变量

本轮连续完成 SYNC-0 契约、SYNC-1 持久化同步核心与双副本测试、SYNC-2 Linux 最小闭环。不建注册/密码系统，不改训练算法或 UI，不更新真机，不迁移真实数据，不自动删除原件，不改 CI 触发。未知库版本、身份失败、来源变化、损坏附件或空间不足时停止对应操作。冲突保留双方，不覆盖为成功。

现有 Journal 及训练格式不变，采用独立同步库和参考副本测试。第一批是文字/照片，语音、训练结果和诊断录像另外接入。iOS 业务保存与 outbox 原子衔接在下一阶段实施，不声称本轮已可手机同步。

## 契约

- 单资料库有稳定 vault ID。管理员签发高熵、短期、单次配对码，配对成功给设备独立凭据；服务端只保存凭据摘要。每次请求检查撤销状态，不因同一局域网放行。
- 操作为 `op_id, record_id, base, deleted, payload`。op ID 是幂等键和成功修订标识；base 是此前已知修订 ID，首次为空。payload 保留原 CaptureRecord；本地整数 revision 不是全局修订。
- 同操作重传返回原回执；同 ID 不同内容拒绝。过期 base 保存冲突提案及当前 head，不自动按时间覆盖。解决冲突需明确新操作。
- 照片使用原描述符的 SHA-256/大小及 UUID，先归档核验再提交记录。未传完整不发布记录；已有附件但未提交只是中间态。
- 服务端序号为增量游标；客户端先验证并持久化附件，再原子写入远端镜像与游标。本地提案独立保留，pull 不覆盖待发送内容。
- 删除为 tombstone，不物理删除历史或附件。旧版本编辑冲突；恢复须显式基于删除修订。源端清理后置。
- 分析结果独立保存，不改写原始记录。

## 里程碑与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| SYNC-0 | 契约、台账、测试先行 | 冲突、删除、认证、附件与版本边界明确 |
| SYNC-1 | SQLite 核心、持久化参考副本、归档附件复用 | 双副本离线新增、照片往返、重复、丢响应、并发、删除、损坏、游标原子性、重启、认证撤销 |
| SYNC-2 | Linux 隔离合成库与管理/RPC | 两个合成设备实际 SSH 往返、远端测试及持久化；真实资料不变 |
| SYNC-3 后续 | iOS 适配、网络服务与配对界面 | 先确定 TLS 信任与 Keychain，再备份/更新真机并验证真实双端；需要通知用户 |

本轮 Linux 复用 pinned SSH 加密通道，无监听端口；不把 SSH 私钥嵌入 App。不是 iOS 可直接访问的生产网络服务。后续前台同步优先，不承诺后台实时。测试只用合成数据，私有证据进忽略目录；不跑无关相机/UI 全量回归。

## 实现与接手入口

- `scripts/personal_sync.py`：`Store` 保存已配对设备、配对码摘要、操作及冲突回执、提交事件和 head；`Replica` 是持久化 Python 参考客户端，不是已接入 FoxJournalCore 的模块。
- `scripts/personal-sync-smoke.py`：只在新的独立合成资料库运行真实 SSH 双副本测试，绝不拿现有手机记录作为夹具。
- `npm run test:sync`：同步专项。测试已登记到原有 catalogue，现有 Python 验收入口自动发现，不改 CI 触发。
- 管理命令 `python3 personal_sync.py init ROOT`、`invite ROOT`、`revoke ROOT DEVICE` 仅在服务器管理通道运行。`serve ROOT` 为每进程一次 RPC；客户端通过已有 `archive.remote` 的 pinned SSH 传输调用。
- 服务端每次事务串行核对身份、head 和提交；变更历史不覆盖。照片复用 `Archive` 实现，但放在独立同步库附件子目录，不修改既有归档索引。

当前限额：每张照片 25 MiB、每记录最多 20 张，操作连同完整认证 envelope 不超过 64 KiB，每页最多 50 条事件。record key 规范小写，原 payload 的 UUID 不改写。照片保真校验字节与摘要，不保证 MIME 对应可解码图像；原生接入需保留既有图片输入验证。

参考副本同一记录仅允许一个待发送提案；未发出时再次编辑明确拒绝，保留原提案，不静默合并。冲突另存并返回当前远端 head，解决需明确新操作。正式 UI 的连续离线编辑/冲突选择待 SYNC-3 完成，不能把这个参考限制隐藏给终端用户。

配对成功响应丢失时不自动重放一次性配对码；管理员撤销不再使用的设备凭据、重新签发。当前 SSH 同账号可管理磁盘，是可信管理边界，不宣称抵御同账号恶意修改或公开网络攻击；生产 HTTPS、配对限流/生命周期、Keychain、TLS 验证属于设备接入门槛。

## 本轮结果与接续

SYNC-0–2 已在上述限定范围完成。Mac/Linux 同一源码各 46 项通过（同步 20、原有归档 26）；独立审查无阻塞。Linux 真 SSH 双参考副本完成照片往返、并发冲突、删除标记、重启持久化、撤销拒绝，保留 3 个提交事件及 1 个冲突提案。旧首轮验证也保留，最终接受的是带完整 envelope 和数据库身份修复的第二个发布包。

测试先行发现并修复：记录键大小写可能分裂、无关 version-1 数据库被接管、仅计算内层操作大小导致入队后无法传输。每项保留红到绿过程，没有放宽断言。独立复核另外做了 7 项临时合成检查，不把它们算入已登记的 46 项正式回归。

服务端已初始化独立空资料库，未导入或合并真实手机数据。连接描述保存在 `~/.config/fox/sync.json`，不含设备凭据；既有 `archive.json` / `archive-current.json` 不变。源码版本化部署并逐文件 SHA-256 校验，不覆盖旧发布包。私有回执 `.tmp/verification/personal-sync-20261028/accepted.json`，真实 SSH 验证 `smoke-2/receipt.json`；重新核验了上轮 iPhone 8 个原始归档文件与 Mac 原件摘要一致。

当前可用的是服务器核心与参考客户端，不是终端用户同步功能。**下一步必须完成 SYNC-3 原生接入和安全网络入口，再通知用户安排真实配对/覆盖安装**。现有手机、平板无需解锁或操作；本轮未安装、未续签、未删原件、未推送或修改 CI。原生队列原子提交、后台生命周期和真机照片展示尚未验证。
