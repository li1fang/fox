# 原生 Home：实施选择与真机门槛

日期：2026-10-17。状态：N1 手机准备与 N2 的 build/install/launch smoke 已通过；Fox 0.5.0/build 11 在用户信任开发者账户并解锁后成功启动，进程已核对，用户确认首页两张卡片显示正常。真实手机保存、照片、更正与备份仍待后续，iPad 不升级。本文同时保留实施前只读检查与分阶段验收要求。

实施补记：同日已开始 N1/N2。iPhone 13 Pro Max 已经通过有线连接并完成 CoreDevice 配对；首次详情检查显示 Developer Mode 为 disabled。正在准备 Fox 0.5.0/build 11 的通用设备候选、原生 Home 和纯文字记录；照片、更正、备份和完整 N3/N4/N5 尚未验收。以下原始检查记录保留作为实施前基线，最新结果见 [手机候选实施记录](HOME_IPHONE_CANDIDATE_V1.zh-CN.md)。iPad 保留旧安装，不随手机候选升级。

N3 续轮：0.5.1/build 12 已接通照片、更正/删除、分页与文件备份界面，App 层测试和跨尺寸 UI 回归分开执行。最新结果以 [N3 本地闭环实施记录](HOME_LOCAL_CAPTURE_N3.zh-CN.md) 为准；不将软件实现直接标记成 N5 真实拍照/备份验收。

## 1. 推荐选择

选择“训练基线先保留，iPhone 准备与 Home 小步实现并行”，不等全部首页做完才找手机，也不先重写训练或加新动作。

配对/开发者模式可以提前做；对实际 App 的签名、描述文件与信任检查，仍要经过第一份兼容 iPhone 的 Fox 构建及安装。用同一个 Fox，不新建第三个空壳 App 来过一次与真实目标不同的签名门槛。

已有 [交互设计方向](../design/HOME_CARD_FEED_V0.zh-CN.md) 和会话内三稿预览：iPad 双列/三列、iPhone 单列；这不是原生实现、Figma 文件或手机验收。下一轮可直接进入有限原生验证，不把引入 Figma 设为必经门槛。

## 2. 当前能做什么

2026-10-17 实施前检查结果：Mac 有 Xcode 26.3、XcodeGen 2.45.3 和 1 个有效签名身份；iPad 已配对、开发者模式开启。当时 iPhone 未出现在开发设备列表；同日后续已连接并完成配对，但仍需开发者模式与实际构建/安装检查。

实施前另有两个软件门槛，不能靠手机信任来解决；N2 已开始处理它们：

- 原 Fox 的 `TARGETED_DEVICE_FAMILY=2`，为 iPad-only；N2 源码已改为 `1,2` 并开始手机布局测试，但旧 iPad 安装不因此自动变成新候选。
- `scripts/ipad.mjs` 默认仍选择 paired iPad；新 `iphone:*` 命令明确只选择 iPhone 和 Fox，使用独立构建目录，不让旧命令的多 App 默认影响手机链路。

有效本机身份不等于新设备的 provisioning profile 已经生成、证书与账号始终可用，或免费签名永不过期。实际安装时再校验签名/描述文件、设备支持和账号能力，不在此阶段购买或开通云服务。

## 3. 人工操作分两次，不需要所有开发者开关

### 可以提前：让 Mac 看见手机

1. 用数据线把目标 iPhone 13 Pro Max 接到 Mac，解锁；若系统询问，用户选择信任此电脑并在手机输入密码。首次准备优先有线，后续无线不是本轮先决条件。
2. 通过 Xcode 开始设备配对，按实际提示处理。Developer Mode 可能要启动配对之后才出现在设置中，不要求用户提前寻找尚不存在的条目。
3. 手机“设置 -> 隐私与安全性 -> 开发者模式”如需开启，则用户确认重启，重启后再确认开启并解锁。此设置与信任电脑、信任某个开发 App 是不同事项。

Apple 官方说明：[Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)、[运行与设备配置](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)。本轮不自动更改用户设备的安全设置。

### 第一份手机候选安装时：处理实际提示

先构建并核验兼容 iPhone、正确 Bundle ID 和 Team 的 Fox，再明确选择手机安装/启动。若手机确实显示未信任或需要验证开发者，则按实际提示在“通用 -> VPN 与设备管理”中处理；没有对应条目时不要求提前凭空添加。已在 iPad 信任同一账号不能代替 iPhone 上的检查。

信任不能修复无效签名、到期描述文件或未包含目标手机的 provisioning profile；这些错误由开发侧分别诊断，不能全部交给用户反复点“信任”。企业分发信任流程也不能直接当作 Personal Team 开发签名的完整说明。

首次使用相机/照片时再由用户授权，拒绝权限必须有可用回退。无需预先开启 UI 自动化、性能跟踪、网络调节器、快速 App 终止等全部开发者选项。UI 自动化默认放在模拟器，真人手机只做必要的实际能力验收。

## 5. 实现范围选择

- 继续 SwiftUI 和现有原生包，不把会话中的网页预览直接塞回 WKWebView。
- Home 是圆角卡片瀑布流：iPhone 一列，iPad 按可用宽度采用两列/三列；比例是视觉参照，不硬编码屏幕 10% / 5%。卡片内容与导航的 Liquid Glass 材质分工沿用设计记录。
- 先把记录卡固定在容易找到的位置作为原生候选，原生预览再确认细节；默认不开键盘，不自动推荐或刷新打断输入。新相机页、键盘与大字体都在实际可用窗口下验证。
- 只实现文字/照片、本机浏览、更正和必要的备份入口，不要求 AI 回复、营养估算、消费归类、HealthKit、ASR/TTS 或任何设备同步。
- 训练页、状态机、计数算法和持久化保持原边界；保留独立视觉诊断入口，避免把试验工具变成全 App 的主导航。
- Fox Say 不随 Home 发布顺便改动；首次只安装 `com.whipa.fox` 到明确的 iPhone。iPad 保留现有候选，满足回归与数据保留条件后另行升级。

## 6. 自动测试与真人测试分别验收

自动测试：

- 新 Home 的界面 store：存储成功才清草稿，写失败/磁盘不足/图片读取失败保留输入；稳定 ID 重试及双击保存不重复，更正冲突有反馈。
- 真正接入 `FoxJournalCore` 的临时目录集成测试，不只对假接口点一次保存；重启能读回照片字节和原文，测试不得用个人档案。
- 模拟器 UI 同时覆盖 iPhone 和 iPad，长文字、横竖屏/窄窗口、键盘、空状态、相机拒绝、保存重试、打开详情/更正以及原训练入口；不能只跑旧 iPad 测试后声称手机通过。
- 原训练核心、记录核心和旧原生 UI 分别回归；Home 上训练卡是展示适配，不创造第二套训练状态机。当前构建脚本的默认 iPad 选择需补测试，不靠猜设备名。
- 验证测试标志/fixture 不进入真机正常启动、样例卡不写入正式数据库；检查无网络时核心仍可用。

真人检查：实际信任/签名启动、相机拍照与相册权限、系统键盘/听写产生文字、前后台/重启、手持输入和真实窗口布局。相机权限通过不等于视觉计数通过；旧训练四动作的真实可靠性仍按 [训练视觉路线](../fitness/FITNESS_VISION_BASELINE_AND_NEXT.zh-CN.md) 单独验收。

“一口气完成”应指同一条实施链路可运行到实际人工门槛，并在用户处理后继续验证，不承诺绕过安全确认，也不因发布日临近而把未测项目改为通过。

## 7. 本轮选择结论

建议先执行 N1/N2，再完成 N3/N4/N5。最新一次训练的复盘可与 Home 开发并行；仅当它暴露会丢数据、错误推进或无法继续训练的缺陷时，才作为升级前必须修复项。普通算法漏计进入独立复盘，不在真实训练现场大改。

实施前一轮完成计划、训练基线与只读检查。当前已改变源码中的设备支持范围和原生 Home，并首次安装到 iPhone；未更新 iPad、未改相机算法或个人训练数据。详细执行结果以 [手机候选记录](HOME_IPHONE_CANDIDATE_V1.zh-CN.md) 为准。后续互联与分析仍见 [任务台账](LIFE_LOG_BACKLOG.zh-CN.md)，本轮不启动。
