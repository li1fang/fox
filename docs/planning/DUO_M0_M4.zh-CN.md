# Duo 基础适配与回归视觉路线图

日期：2026-10-25。M0/M1 软件与模拟器验收已完成；M2 已进入两部分采集/评测计划设计，尚未开始新采集或算法实现。M3/M4 不自动启动。

| 阶段 | 目标 | 状态与退出条件 |
| --- | --- | --- |

## M0/M1 测试先行

1. 空间策略：紧凑手机、大屏展开、横屏短窗口、大字号；保留 iPad 行为，不按 `.phone` 将展开布局锁为单列。
2. 实际 View 宿主：变化 size class/尺寸时保持预览 UIView 身份、控制器与会话身份；不重复初始化训练或清除次数。
3. 相机画面：完整等比、关键点投影与预览一致；相机中断后沿既有恢复流程处理，不制造跨缺口运动事实。
4. 交互：记录输入保存、训练准备/活动/暂停/休息/反馈/总结，以及视觉设置和报告；主要操作在可见区，辅助功能允许滚动。
5. 折叠安全：针对系统预留区域做保守避让，不新增悬停工作流；合成区域/尺寸测试与真正模拟器开合分别记录。
6. 回归：原 iPhone/iPad 公开原生套件、三动作核心及控制器合成回放；保持计数/阶段算法及记录存储源码不变。私人录像未重新推理时明确注明。

## 执行与验收

- 复用 `runSuite`、测试目录、候选冻结和回执检查，不另造验收系统。新增测试显式登记 catalogue。
- 本轮输出放独立 `.tmp/verification/duo-m0-m1/`。旧外盘构建缓存出现签名及预编译模块损坏后，保留失败证据，改用独立内盘可重建目录；不据此推断原片或其他归档损坏。
- 使用固定 runtime/model 和现有共享租约；只串行启动一个模拟器。其他任务设备占用时停止，不关停/删除用户设备。结束及取消都释放本任务设备。
- 内盘低于 2 GiB 或外盘低于 5 GiB 时中止本任务测试并保留失败回执；正式验收前再次检查容量。
- 先聚焦测试，稳定后冻结提交，再完整原生回归与 Duo 专项验收。不同提交的通过记录不能复用成当前验收。
- 无 Duo 真机：交付是模拟器布局候选。真实镜头切换、识别准确率、持续帧率/温度、悬停可读性及训练收益均待真机；合成相机不等于真镜头。
- M1 通过后已回到视觉讨论；用户随后要求设计 M2，按链接计划继续，不自动开展 M4。

## 可重复入口

普通 iPhone/iPad 使用 `verify:candidate` 的 `public/native` 分片；Duo 使用 `npm run verify:duo -- <完整提交号> <新输出目录>`。两者必须串行，且候选提交干净、全过程源码不变。Duo 入口复用共享模拟器会话和回执审计，固定 27.1/Duo，不访问私人录像。

Duo 自动化包括空间策略、预留区域、相机/会话身份、首页记录及训练/视觉交互；真实 Device Hub 开合另附截图记录。注入尺寸或旋转不是实际开合证据，模拟器镜头也不代表真实镜头切换或识别准确率。

设计参考：Apple 的 [自适应布局](https://developer.apple.com/videos/play/tech-talks/111461/)、[预留区域](https://developer.apple.com/videos/play/tech-talks/111463/)、[相机切换](https://developer.apple.com/videos/play/tech-talks/111465/)。SDK 接入使用版本保护，保留旧系统兼容路径。
