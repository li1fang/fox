## 阅读摘要

**交付单位是一次完整训练体验，里程碑只是内部检查点。** 用户不需要先体验一个只能报数的版本，再等待节奏、反馈、记录逐项补齐。

- 试用前：保护三动作计数，完成统一视听引导、组间确认和可复盘记录；同步落实模块边界，自动测试通过便继续。
- 试用中：冻结同一个版本，自然训练；记录是否听清、提示是否合时、是否打扰，以及算法失败片段，不在现场改规则。
- 试用后：先对齐录像、事件和反馈，再决定修复或扩展动作；不能因语音播得流畅就认为动作判断正确。

### 五类语音需求如何进入三阶段

| 用户需求 | 试用前交付 | 试用时判断 | 试用后可能扩展 |
| --- | --- | --- | --- |
| 报数与剩余进度 | 真实提交次数、剩余三个/最后一个；无确认目标时不编剩余数 | 是否漏听、过密、与动作感觉一致 | 根据真实时序调整合并与频率 |
| 节奏 | 已确认计划节拍、可观察阶段提示、组后返回区间；证据不足时弃权 | 提示是否来得及、方块是否有帮助 | 有定义一致的测量后再做“太快/稍微加快” |
| 鼓励 | 少量通用鼓励与真实训练进度，不把“很好”包装成姿势达标 | 语气、密度和打扰程度 | 个性化文案及更自然音色，不改事实判定 |
| 询问 | 组间重量、感受、继续休息，用既有触控确认 | 是否减少操作、问题时机是否合适 | 再决定是否值得接 ASR/对话 |
| 监督 | 仅播已确认的观察状态，如暂时看不清；不承诺身体纠错 | 是否存在误报或令人困惑的提示 | 专项证据足够才做耸肩、幅度、躯干稳定性提示 |

外放和耳机不分产品路线。首批复用本地系统中文语音并保留输出替换接口，不把音色选型、自动音量或蓝牙研究设为交付前置。自然有魅力是试用评价维度，不是本轮未验证的承诺。

### 连续执行的三个收口点

1. **A0–A2：事实和边界稳定。** 已完成部分核对输入/源码变化后复用，补齐失效的验证；计数与测量不因增加声音而改变。
2. **A3–A5：完整体验闭环。** 声音、叠加、确认、记录和导出一起接入并自动演练，不拆成多次人工功能验收。
3. **A6：真机候选可启动且原数据保留。** 尽量一次集中完成设备准备；只有解锁、信任或权限提示等确需人的操作才打断。到此停止开发，等待自然试用。

测试失败先在责任模块修复；不把每次失败变成用户决策。只有范围取舍、不可恢复的数据风险或必需证据缺失，才提出具体问题。现有自动化不足的门槛应补测试，不直接改成一长串人工测试任务。

## 1. 一个交付目标，三个阶段

目标是交付一份可以正常训练、获得基本视听指导、记录真实反馈并带回可分析证据的**完整候选版本**。不是把整个历史台账一次做完，也不是只有报数的演示。

| 阶段 | 核心工作 | 结束标志 |
| --- | --- | --- |
| A：下次采集与试用前 | 模块边界、计数/阶段事件、语音与画面引导、组间确认、诊断/反馈、集成自动验收及设备候选 | `trial_ready`，交付一个冻结的候选与简短试用清单 |
| B：下次数据采集与试用 | 自然训练三动作；按意愿补卷腹/卧推；核对后保留诊断与体验反馈 | 原始数据安全保留、已取回部分可校验，真人感受与软件结果分开记录 |
| C：试用后 | 事件级复盘、失败用例回流、有限修复；据新证据评估新动作/监督能力 | 复盘和下一候选范围明确，不在训练现场持续大改 |

### 试用前必须新增的用户价值

- 正式训练与独立视觉试验均可报数，准备、恢复、休息有一致的状态提示；声音可关闭，不依赖服务器。
- 相机完整画面内有可关闭的半透明节奏方块，使用同一引导状态驱动画面与口播；不再为不同方向复制训练逻辑。
- 提供计划节奏与可观察阶段跟随的明确区别；有效时可作“控制哑铃/把手放回去”的阶段引导，观察不足时暂停这类提示，不影响实际记录。
- 组后可查看实际观察到的返回区间及未测原因。重量、感受和继续休息通过短问题加现有触控输入确认，不引入 ASR。
- 同一次尝试的录像、阶段、报数/提示和用户反馈可以对齐复盘，失败启动也能留下诊断；不要求训练者当场记住每一次。

不承诺本批实现：完整动作标准评分、自动“不要耸肩/站直/再高一点”、根据疲劳自动改处方、LLM 自主教练、常开语音对话、数字人、深度/多机/跨平台。

目录名为计划落点，不表示已经移动。A1 先提取节奏显示/计算与新引导代码；既有动作分析文件的纯路径迁移放在独立改动中，先验证资源引用、测试/脚本路径与构建。相机大类不为了目录整齐整轮重写；历史 `CurlRepetition` 命名暂时保留，避免旧格式连锁迁移。

### 最小依赖与契约

```text
Perception -> MotionObservation
                 -> WorkoutCoordinator -> committed TrainingSession
                 -> GuidancePolicy <- session / confirmed preferences
                        -> GuidancePresentation + CueCandidate
                        -> renderer / scheduler / SpeechOutput

recording + evaluation 读取各层有来源的事实；播放回调不驱动训练状态。
```

需要落地的有限契约：`MotionObservation`、`SessionGuidanceContext`、`GuidanceCue`、`GuidancePresentation`、`TrialBundle`。名称可按现有类型调整，但字段语义与测试必须保留：会话/组/观察段 ID、单调时刻及视频时钟映射、算法/策略版本、来源、有效/缺点/过期状态、取消原因。

### 模块边界的完成标准

- 一个数据真值：实际次数和组状态归训练/动作层；声音播了几次不能反推训练做了几次。
- 一个引导决策入口：图形与声音消费同一状态，但可以有不同呈现频率；不能由两个 View 各自推断当前运动阶段。
- 一条可追溯链：同一次尝试能关联姿态观测、计数、阶段测量、提示决策、播放结果和用户核对；不要求合并进一个数据库。
- 可替换的输出：系统中文语音以后可以换音色或驱动，不改动作策略；本轮不实现远端语音平台。
- 有实际守门测试：禁止反向依赖；静音、关叠加、播放失败不改变运动事实；旧记录继续可读。只画模块图不算完成模块化。

开发顺序为 A0 基线 -> A1 边界 -> A2 策略 -> A3/A4 集成 -> A5 全流程 -> A6 候选交付。A3 与 A4 可分别开发，但必须以同一版本一起验收，不能将其中一半留给试用者补测。

训练结果仍是业务真值，声音与画面是只读输出。配置与话术可以 JSON 化，行为由受测代码实现；不做任意 JSON 状态机解释器。新业务字段采用可选、版本化与旧档案解码测试，不要求迁移原训练/生活数据库。

### A2：这次真的增加哪些节奏能力

1. **计划节奏**：以已确认的 `TempoPhase` 为参照，方块与短提示表达发力、停留、回程。不能把它播成已完成次数，也不宣称与真人相位同步。没有确认目标就不擅设训练节奏。
2. **观察跟随**：使用当前仍有效的动作阶段，触发一次“控制哑铃放回去”或下拉的“控制把手放回去”。这是一般动作引导，不是因为判定用户做得太快而发出的纠错。高位下拉不能复用“抬起/放下”的字面方向。
3. **可见区间反馈**：组后呈现有效返回区间、测量覆盖次数与未测原因。可比较定义一致的观察区间，但不把 `fullEccentricComparison=false` 的量与完整离心目标硬评分；旧兼容评分也不作为新语音依据。
4. **缺点处理**：跟随画面与阶段口播在过期、宽限/缺点、主体歧义时退为不确定；恢复需要新鲜稳定观测，不重复上轮指令。引导暂停不等于计数器暂停；静止/慢动作不能一律当作休息。

计划与观察是明确选择的模式，不能自动从“看不清”切成仍在催动作的计划节拍。视觉默认用观察跟随，非视觉用计划节奏；设置中可显式选择/关闭，均显示来源状态，不生成第二套次数。

条件性启用，不是条件性开工：A2 必须实现并测试因果出口/弃权路径，逐动作检查已有样本的提示时间。现有观察到达较晚时，取消当前阶段指令，保留组前指引与组后区间报告；不人为前移时间。若某动作不能证明当前阶段可用，则该动作标为 `summary_only`，仍继续其他模块，并在交付清单列出。若三动作全部无法得到一个可用的跟随示范，视为集成目标明显缩水，应说明证据与调整建议，不能默默把 A6 改成仅报数交付。

“稍微加快”“你放得太快”“很平稳”“不要耸肩”不因增加了播放引擎就开放。可观察区间目标定义、姿势专门评测和疲劳上下文不足时，它们属于 C 阶段后的条件任务。

### A4：问答不需要先建对话系统

- 组前需要确认时问“这组用多少 kg”，预填值只表示计划/上次记录，用户确认后才是本次输入；组后问“这组感觉怎么样”，复用现有多选与补充文字。
- 休息到点给“开始 / 再休息一会儿”操作，延长由显式命令修改现有休息截止时间；语音本身不代替点击，不自动推进。
- 无回答就是未回答，不猜重量、感受或恢复程度。当前组与下一组的值绑定不同 context；重复提交幂等，保存失败不能说已确认。
- 不新建常开麦克风、ASR 或自由对话 agent；用户可以使用系统键盘听写。询问不发生在承重动作中，有限提示不抢报数。
- 试用意见用独立 `TrialReview` 附件/记录引用保留三种来源分类；信息补充不自动改 profile，软件问题不写成身体症状，训练感受不自动变成处方。相关界面只在核对/结束时出现，不占训练主画面。

## 5. 自动验收、降级和人工门槛

### 必须通过的发布检查

- **行为回归**：冻结输入的计数、每次时间、返回测量、缺点弃权与重置原因逐事件一致。引导 on/off 不改变原运动事实；不能只对总数。
- **因果性**：同一帧前缀输出与整段回放到该时刻相同；不能利用未来峰、后期打点或最终结果决定当时说什么。下拉末次计数无自身返回测量。
- **语音正确性**：正常速度脚本无非预期重播/漏播/跨组；故障/延迟场景按规则丢弃过期提示。提示在开播前及状态变化时都校验有效性。
- **UI 可用性**：设备×横竖屏×准备/训练/缺点/休息/键盘/核对场景；完整取景、主要按钮可达、不增加 95% 首屏缺最后按钮问题。复用现有场景审查，不另造一个截图验收体系。
- **记录兼容**：只对隔离测试库做失败注入；原档案可读，计数自动值/用户修订/建议分开。生活图文记录、照片、备份与删除的既有测试仍通过。
- **设备集成**：真实相机+无声诊断录像+口播+叠加同时运行，不用缓存测试冒充采集性能。相同场景/设置开关引导各跑三轮，记录帧间隔、处理耗时、掉帧和热状态；工程初值为帧间隔 P95 不恶化超过 20%、掉帧率绝对增幅不超过 5 个百分点，无法控制条件则记未评估而非通过。阈值改变须留理由，不按结果临时放宽。
- **输出与延迟**：外放/耳机共用逻辑与自动测试，不让用户先选择路线。短报数延迟预算沿用 1 秒的工程初值，观察阶段提示另受“当前阶段仍有效”约束。记录 API 回调与路由信息即可，不新建蓝牙专用研究项目，也不把播放回调等同于人耳听见。
- **发布与数据保留**：覆盖安装而非卸载，安装前后校验实际记录与附件；签名到期时间重新读取写入交付单。临时文件/WAL 等按数据库一致性方式核对，不强求易变缓存字节相等。

可复用命令：`npm run test:native:all`、`npm run test:vision:controller`、`npm run test:vision:flow`、`npm run test:home`、`npm run test:ipad:ui`、`npm run verify`、`npm run test:e2e`，以及策略/报告 Schema 检查和 `vision:batch` / `vision:evidence`。这些是现有入口，不代表本轮已经执行。A0/A5 应形成一个明确的集成验收入口，复用这些命令、报告缺失私有数据/设备条件，不能用 Web Playwright 替代原生 UI 验收。

### 自动继续规则

每个里程碑保存范围、代码/输入摘要、命令退出码、报告路径、能力 verdict、剩余限制。状态为 `planned -> implementing -> verified`；独立的条件能力可记 `degraded_with_evidence`，不把失败的计数回归记成降级。

A0 建立并由后续验收脚本更新 `trial-readiness.v1.json`，至少含 `candidateBuild`、源码/输入摘要、`requiredGates[]` 的状态与证据路径、`capabilities[]` 的动作/模式/启用或降级原因、`deviceCheck`、`recordPreservation`、`pendingHumanActions[]`。汇总状态由门槛计算，不能手填一个总的 passed：必需门槛缺证据即不满足；设备缺席与软件失败分开；恢复开发先核对摘要，不重复等待已通过阶段的人工确认。文件与检查器的当前实现情况见执行记录，存在 manifest 不代表所有门槛已通过。

- 普通失败：自动修复并重跑受影响及关联测试，然后继续，不请求阶段批准。
- 某条阶段口播不可靠：关闭该动作的当前阶段指令，保留其他已证明能力，记录原因；不能为了口播放宽动作阈值。
- 计数退步、数据损失/损坏、依赖关系失控、无法启动/无声却标成功：阻止 A6，先修复，不能作为“已知问题”带去正常训练。
- 执行范围明显扩大、需要付费/账号/数据迁移、原数据必须删除、所需素材无法取得且没有等价测试：提出具体选择；其他不依赖的工作继续。
- 设备解锁、信任、系统权限等 OS 人工操作：集中到必要窗口请求，不重复询问技术路线；本地准备和模拟器工作先完成。

### 下一轮如何连续执行

| 情况 | 执行者处理 | 是否打断用户 |
| --- | --- | --- |
| 当前检查点通过 | 记录源码/输入/结果关联，直接进入下一项依赖已满足的工作 | 否 |
| 可定位的软件失败 | 固定失败用例，修复，重跑受影响检查及整体验收 | 否，不请求每次修复批准 |
| 单个动作的当前阶段提示不可靠 | 保留计数与组后测量，按前述条件关闭该条即时提示，交付时明确列限制 | 通常否；若整体能力明显缩水则讨论 |
| 设备暂不可用 | 继续本地未完成项目；汇总一次设备操作请求，保留 `software_ready_device_pending` | 仅必要时 |
| 必须补新录像才能证明核心行为 | 说明具体缺哪种观察和判定，不要求泛泛多拍；先完成不依赖该录像的项目 | 是，不能用合成用例冒充真人证据 |
| 需要新付费服务、破坏性迁移或改变既定范围 | 写清取舍，停止该项依赖操作 | 是 |
| A6 达标 | 冻结版本，给简短试用清单和数据取回方式，停止开发等待 B | 不再自行开启新功能 |

每个检查点产物保持轻量：目标/改动范围、失败测试、修复后结果、证据位置、剩余限制。持续维护现有执行记录和验收 manifest，不为每个小步骤新增一套台账。

`trial_ready` 只代表软件和设备候选准备好，不代表新真人计数、节奏体验或姿势纠错已经通过。A6 后停在 B 门槛，等待用户正常使用；不自动安排训练、提醒或继续以合成数据宣称 B 完成。

## 6. B 阶段：一次自然试用，产生多模块证据

实际动作/重量/组数在训练前确认，不从开发录像推断处方。这里是采集覆盖清单，不要求额外疲劳、不追求固定次数、不人为制造危险动作。

| 覆盖项 | 采集内容 | 不要求用户做什么 |
| --- | --- | --- |
| 弯举与侧平举 | 现有侧身/正面视角，自然的一组或几组；首轮、短缺点、疲劳后、正常结束的事实与观感 | 不需一边举一边记次数或日志；不强迫设备垂直，不为制造丢点改变到危险姿势 |
| 高位下拉 | 正常背面上半身，核对峰端计数与返回提示；末次可以正常收尾或录像到顶峰结束 | 不补拍只为凑末次离心，不用上一轮测量代替末次 |
| 视听与交互 | 听清/过密/时机/错误提示、方块可见性、重量/感受/休息确认是否顺手 | 不强制外放和耳机分别跑两套训练；实际用哪个就记哪个 |
| 卷腹、卧推 | 用户本来打算做时才拍；卷腹侧面尽量能见躯干，卧推保留原头端探索视角或自然可用机位，手动记录事实 | 不为了进入适配额外强练；无正式计数也能采集，不强套弯举算法 |
| 生活记录 | 有自然记录需求时继续照片+文字，软件回归护航 | 不为本轮安排饮食/财务全量录入，不启动 AI 自动判断 |

新增动作录像可继续用系统相机。若 A4 增加 Fox 内纯采集，必须无需运动准备门控、明确“未计数”；不能为方便采集给未适配动作制造有效次数。优先复用诊断录制器，不建剪辑器或峰谷标注 App。

每次结束后选择保留/丢弃；启动失败也可结束并保留。视频不需要原始人声，提示事件用时间线记录，不为“听见播了什么”打开麦克风。用户后期机械打点/手工峰标签作为待核对标注，不能视为现场同步真值或精确离心边界。

交付包关联：原片摘要、相机/屏幕倾角及来源、动作/观察臂、帧与算法/配置版本、准备/计数/阶段事件、提示候选/实际启动/取消、用户可选参考次数/三类意见。没有填写的参考数据保留未知，不写 0；也不把像素尺度变成米制距离。

正常训练当天冻结候选，不远程热改动作规则。配对设备可用时采用已有取回工具自动接收；不可用则支持现有手动文件导出/导入。接收失败保留 iPad 原件，不把导出成功当成 Mac 已收到；这不是 CON-01 通用同步。

## 8. 路由与声音的共同约定

接受用户的产品判断：外放与耳机不是两种产品模式，不需要先选择，也不要求佩戴某种耳机才能试用。尊重系统音量与路由，不自建自动音量算法。

[Apple 的 Personalized Volume 说明](https://support.apple.com/en-us/104979)支持在适用型号和设置下根据环境调整媒体音量；这不构成所有耳机行为完全相同或提示零延迟的保证。产品上统一体验，工程上保留静音、中断、断开和过期取消即可，不以耳机专项研究阻塞本批。

工程上仍保留过期提示取消、系统中断和耳机断开处理，这些是普通音频生命周期，不是蓝牙研发里程碑。Apple 提供 [路由变化通知](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes)和 [outputLatency](https://developer.apple.com/documentation/avfaudio/avaudiosession/outputlatency)；不据此宣称所有设备端到端延迟为零。真正优先修的是应用自己积压、重复、说错阶段的提示，而不是先做耳机选型。

最终交付必须给出：安装构建与签名到期、保存数据核对、已启用/降级能力、自动测试与设备证据、已知限制、一次试用清单和报告取回方法。不得只交付一组代码改动或“下一步再接 UI”。完成 A6 后暂停在采集/试用门槛，不自动执行需要人的 B 阶段。
