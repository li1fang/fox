# iPhone 视觉旋转与快捷选择 V1

日期：2026-10-17。接续 [iPhone 训练布局 V1](IPHONE_TRAINING_LAYOUT_V1.zh-CN.md)。用户确认竖屏布局符合预期；横屏保留左控制、右完整画面，适量提升常用选项，不重做首页或训练状态机。

## 本轮目标

- 横屏视觉页直接选择动作、追踪手臂；前后相机、机位、参数与诊断仍在二级设置。训练内只允许在既有规则允许时选择追踪手臂，不在组中替换动作。
- 旋转只改变同一组视图的位置和大小，保留相机预览实例与采集会话；不能靠黑屏、销毁重建或隐藏数秒来完成切换。
- 骨架刷新不重复写入相机预览方向/镜像；真实方向变化才更新，并保留原有追踪连续性保护。旋转不自动增加次数，不沿用方向变化前的半次动作。
- 不加入呼吸方块、智能暂停、数字人、新动作、AI 或同步，不更新 iPad 真机和 Fox Say。

## 开发和验收

1. 在正式 View 的宿主中复现横竖屏切换，分别核对视觉页、训练内相机的 UIView 身份；先保留旧版失败结果。
2. 用稳定布局容器安放信息、相机、主要操作，支持系统旋转过渡和减少动态效果；只把选择项加到横屏。
3. 单测验证重复帧刷新不重复方向通知；UI 测试检查竖横双向和两种横屏、快捷项可操作/锁定、画面四角及既有训练路径。
4. 真机签名构建、保留数据覆盖安装仅更新 iPhone；安装、启动与用户实际旋转流畅度分别记录，模拟器耗时不能冒充真机卡顿已解决。

## 基线和实现记录

初版测试宿主没有绑定 UIWindowScene，未产生预览，保存在 `.tmp/iphone-rotation-v1/baseline`；这是测试准备失败，不算 App 缺陷证据。修正宿主后，旧版正式视觉页和训练内相机在 compact / regular / compact 三次转换中均更换 UIView，两个测试都失败，证据在 `baseline-hosted`。

实现采用一个 PhoneCameraLayout 的固定信息、预览、操作槽位。横竖屏改变布局，不改变相机子视图身份；常规训练也复用同一套尺寸分配。训练相机不再因旋转在两处 TimelineView 分支之间移动。过渡时长为 0.25 秒，开启减少动态效果时不加额外动画。

PosePreview 把屏幕方向通知、采集方向请求和预览方向/镜像配置按实际变化去重；新连接仍会重新配置。图像和骨架的完整等比投影、方向变化后的连续性中断规则保持原状。DEBUG 的 UI 测试值额外带预览 UUID，用于独立核对真实页面路径的视图身份，不是用户界面内容。

回归另发现二级设置选择不稳定。仅移动说明行不足以解决，空闲态打开设置时暂停被遮挡预览后，原失败路径通过。动作说明放在选择项后，避免可变行高移动后续点击目标；空闲设置内的前后相机切换不立即重启预览。关闭设置/分享后按既有可见性和前台条件恢复；就位/计数中打开设置不停止采集。各中间结果及最终回归以 [发布记录](UI_RELEASE_0.6.2.zh-CN.md) 为准。
