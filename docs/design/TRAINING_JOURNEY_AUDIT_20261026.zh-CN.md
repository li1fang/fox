# 完整训练故事：审查、比较与选择

## 证据和范围

本轮在 B 收口源码上新采集 iPhone 27.0 模拟器画面，使用隔离的公开设计样本和真实原生页面。不是历史截图，不是新真人试用。原始 xcresult、截图和失败回执位于 `.tmp/verification/product-journey-20261026/`。

- `baseline-phone-clean`：8 个状态截图，全部打开核对，包括准备、等待、活动、暂停、休息、总结、横屏、大字号。
- `baseline-entry-local`：首页→计划→实际开始/完成本组→反馈的 4 张截图；走查通过。另两条新增要求分别因缺少次数步进、实验草稿未收起而正确失败。
- `baseline-phone`：旧外盘对象文件链接失败；`baseline-entry-red`：新增测试查询 API 编译错误，修正后保留；`baseline-entry-red-02`：生成 dylib 的签名页校验失败，独立 codesign 验证也失败。它们都不是产品功能红灯。改为本机临时缓存后入口正常；没有换工具链或关闭校验。

## 逐步审查

| 步骤 | 当前证据 | 状态与发现 | 本轮处理 |
| --- | --- | --- | --- |
| 1 首页 | daily-01-home | 记录卡与训练入口清楚；空档案可进入训练 | 不推倒首页，不改变记录/照片 |
| 2 确认计划 | daily-02-plan | 计划/训练/记录/视觉并列，草稿生成图标直接出现；逐组重复信息使长计划的开始操作依赖滚动 | 普通导航与实验工具分层；动作摘要及逐组展开；开始常驻底部 |
| 3 准备与等待 | training-ready / waiting | 当前组、目标和主操作可见；相机样本黑区是无图像 fixture，不据此判定真实相机故障 | 保留 B 的准备与手工退路；相机准确性不在本轮判断 |
| 4 运动与暂停 | training-active / paused / active-rotated / large-type | 数字、节奏及主要按钮有层级，横屏分栏有效；暂停的节奏块仍写“待开始”，与暂停标题不够一致 | 保留布局与节奏算法；仅让非运行节奏标签遵循当前暂停状态 |
| 5 休息 | training-rest | 下一组信息在顶部，休息计时清楚；没有明确的上一组保存回执，手机“+ +30秒”重复符号 | 明确上一组已保存/跳过已记录；主操作“准备下一组” |
| 6 每组核对 | daily-03-feedback / daily-04-feedback-details | 实际次数空白时保存禁用，未伪造次数；但输入依赖键盘、反馈选项单列，三类可选文本与诊断默认铺开 | 次数加减与原输入并存；感受双列自适应；可选反馈和诊断展开查看 |
| 7 总结 | training-summary | 完成/部分/跳过/未执行区分清楚，保存按钮固定；详情可滚动 | 保留事实与修订入口，不新增总分 |
| 8 保存后返回 | 当前源码的 confirm→history 路径；后续交互测试补齐 | 目前直接返回记录列表，没有本次成功回执与明确返回首页动作 | 成功写入后显示本次回执、查看记录与返回首页；失败仍留核对页 |

截图能支持布局、层级和文字判断，不能证明远距离可读、VoiceOver 操作、真正首次使用者能独立完成或视觉准确率。未覆盖内容必须保留为试用门槛。

## 两种完整故事比较

两条方向都保留最近记录首页、训练状态机和保存格式；不重新设计计数，不把未识别当作动作错误。

| 环节 | 方向一：分步向导 | 方向二：连续训练主线 |
| --- | --- | --- |
| 确认计划 | 独立目标、重量、相机选择步骤 | 一页动作摘要，编辑/逐组设置按需展开，底部确认 |
| 开始一组 | 每组经过设置→摆放→确认 | 当前组页面设置与主操作稳定，既有就位逻辑接管 |
| 识别失败 | 进入专门恢复页，再返回训练 | 原画面保留次数，重新就位/手工退路仍可达 |
| 组间反馈 | 依次填写次数、重量、感受 | 先核对实际结果，感受任选，可选长反馈不阻断 |
| 保存结束 | 完成向导最后一页 | 总结→真实保存回执→查看记录或返回首页 |
| 重复使用代价 | 首次结构明确，但每组多页切换 | 步骤少，沿用已有空间布局；依赖明确标签及状态反馈 |
| 工程影响 | 新增导航生命周期、草稿跨页与恢复测试 | 主要是呈现分层，复用已验证的数据与恢复流程 |

**选择方向二。** 决策依据是重复训练时的操作成本、现有横竖屏布局资产和对失败连续性的要求，不是已经进行过用户 A/B 实验。方向一的价值保留为以后复杂设备设置的局部引导，不做每次必经向导。

## 选定故事及边界

首页→确认计划→本组准备→相机辅助或手工训练→核对实际结果→保存本组与休息→下一组→总结→保存回执→首页/记录。

异常路线：看不清时保留已观察事实，手工完成；离开首页时暂停，返回同一组；反馈空白不冒充目标次数；保存失败留在原页，不显示成功；提前结束保留已完成与部分完成事实。

日常流程不需要打开视觉实验、生成试用草稿或填写软件问题。实验入口、诊断录像和原始观测仍可用，不删除它们。首页、实际摄像头比例、计数器、离心测量、存储格式均不改变。

## 验证方法

实施中的第二轮审查补充：

- 保存后截图发现手机历史条目的标题、日期、组数、状态被挤在同一横行。改为标题、日期、状态三层；真实保存/重开和条目高度检查通过。
- 连续四组故事发现 UI 临时选侧跨动作残留。仅调整 UI 选择的归属：绑定当前 set attempt，新组取计划默认侧，已有观测继续使用锁定侧；不改变侧别识别或计数算法。四组自动事实和保存重开随后通过。
- 可选反馈展开后字段可见，却无法按原 ID 找到。AX 证据确认 DisclosureGroup 的容器 ID 覆盖子字段 ID，移除容器 ID 后原三类输入、旋转和精确值断言通过。没有改为宽松查询来掩盖缺陷。
- 核对页允许滚动查看可选细节；不要求把三类长文字和诊断挤进首屏。固定保存栏上方必须真实可见后才点击，不能仅以 AX 的 isHittable 判定可达。

复用现有测试入口。截图采集按状态与键盘输入分成互不重复的两组，完整入口仍覆盖全部原场景与原输入断言。新增正常旅程、空次数/步进、保存后重开与失败回执检查。iPhone/iPad 串行，构建与原始记录分离。

已知 iPad 输入动画等待和 Duo 迁移问题仍是独立欠项，不以本轮无键盘旅程通过替代它们，不重启采集器。本轮不更新采集设备。最终执行结果见计划与本地回执，不把本文件的设计选择称为上架验收。

本轮方法结论：截图负责发现拥挤与信息主次，连续故事负责发现跨组选择残留、失败后的状态和保存后去路，契约测试负责保护事实。三个层次互相补足；截图好看不等于流程能用，完整流程通过也不等于陌生用户无需解释。下一次优先用真实首次使用反馈验证，而不是再发明一套 UI 审查工具。
