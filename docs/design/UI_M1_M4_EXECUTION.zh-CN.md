## M1 基线与选择

基线 `.tmp/design-review/m1-baseline-ipad`，源码指纹 `77b0d9cdb866f324d68dbb068a52b2e1ae83eb950b5b3b49c8ceab06cb676fee`。Xcode 结果包 1 项场景循环通过，实际导出 14 份观测与截图；不是 14 项独立业务测试。实际为 iPad Pro 11-inch (M5) 模拟器，不是真实 M4。手机另记实际模拟器，不冒充 iPhone 13 Pro Max。

已查看混合记录、辅助功能大字号和长图基线截图：空输入卡含独立照片行及禁用保存行，留白和视觉权重较大；长图被完整等比缩入 200 高预览，字与内容很难读。它们分别是设计权重取舍和媒体可读性风险，不把“没有溢出”当作已合理。

本轮选择紧凑空输入卡，将相机/相册/保存聚合到头部；输入按内容长高，失败状态和照片仍保留。瀑布流缓存已有卡片的列归属，输入变高不重选最短列；改变列数时才重新布局。卡片增加详情线索，长图摘要采用带「长图」标记的顶部预览，完整阅读交给 M2；原图不变。

原生采集入口 `npm run design:review -- --device ipad --group home`，也支持 `--device iphone`、`--group home-smoke`。报告只是观测，不含 AI 总分或业务正确性认证。几何分析反例单测 4 项通过；后续阶段将扩展 records/training 分组。

## M2 进行中的实现

基线的长图在 300 高框内缩成细条，多图位于留言之前；冲突时键盘仍在、恢复区位于表单较下方。新方案把登记/发生时间与留言放在照片前，照片按可用宽度显示，提供独立原生缩放/平移查看。只在查看时解码较大图，最长边限制 4096；原始附件和历史不改。

更正失败会收起键盘，冲突和恢复入口移至表单前部；取消/载入确认、乐观修订检查仍沿用原行为。备份仅区分导出和恢复，并明确不是设备同步，不改变文件协议。首页缺图摘要不再在整卡按钮里嵌套重试按钮，详情中仍可重试。

`.tmp/design-review/m2-candidate-iphone` 与 `m2-candidate-ipad` 各 2 项设计测试通过、7 份观测，含真实缩放按钮交互和返回后修订仍为 1。已查看长图、长文多图和冲突截图：留言先可见，长图不再挤成固定高细条，缩放另有入口，冲突恢复在键盘收起后可读。允许详情滚动，不要求全部原图一屏容纳。`.tmp/ui-m2-functional-iphone.log` 中 12 项功能 UI 和 27 项 App 测试通过。

## M3 只读训练投影

Home 直接读取与训练执行相同路径的真实档案，验证后投影计划、未结束训练、最近两次已确认回顾；缺档案不创建 starter，不伪造排期或 iPad 历史。计划标为「本机计划 · 开始前确认」，未排期不写「明天」。已确认卡片的完成/跳过分别按原状态统计。

不能用 `LocalTrainingRepository.init` 做首页读取，因为它可能恢复并写回活动会话。新增纯读取适配和独立可注入路径，卡片详情复用计划概览/SessionSummary；没有编辑、确认或启动副作用。原「训练」入口仍走既有执行层，返回首页刷新投影。

`.tmp/ui-m3-m4-app-tests.log` 中 31 项 App 测试通过，含新增 4 项：缺文件不创建、坏文件字节保留、活动训练重复读取仍为 active 且档案字节不变、已确认回顾按真实日期排序并保留 skipped。不是用样本渲染代替只读保证。

## M4 训练层级与复用

主要动作从可滚动控制区迁到 safe-area 底部：开始/取消就位、人工降级、完成/暂停、休息继续分别沿用原处理器；反馈保存与总结确认也有持续入口。窄屏训练阶段减少全局导航占高；标题/进度、计划组行和总结指标按可用空间换行，不整体缩字塞满。计数/时间保留显著字号，短窗口允许次要内容滚动。训练页仍沿用既有浅色方案，不声称新增训练深色主题。

观测区优先次数与用时；录像/诊断折叠为次要入口，反馈页仍能核对临时片段，核对后保留/丢弃语义不回退。本阶段未改计数、阈值、启动门禁、状态机、负重策略或新动作；仅对控制器添加诊断目录注入以隔离设计样本。M4 是 UI 里程碑名字，不与真实 M4 iPad 验收混淆。

可复用入口与后续清单见 [本地 UI 审查](LOCAL_UI_REVIEW.zh-CN.md)。几何反例和分组缺证据检测现有 5 项脚本单测，不增加自动 AI 美学红线。

首轮 `.tmp/design-review/m3-m4-candidate-iphone` 的两个投影测试通过，训练场景停在反馈页，整体不通过。第二轮 `m4-candidate2-iphone` 的截图证明保存按钮可见，AX 树却显示它的 ID 被外层 `design-scenario-ready` 覆盖；不是按钮消失。最终改为只给独立设计页脚加就绪 ID，不再给整个正式 View 加该属性。该项是采集工具误报/标识污染，不能算为发现了一个产品 UI 缺陷。之后全分组复查重新采集。

同时将设计宿主内两个视觉控制器的参数/报告也注入临时目录，不依赖其他 UI 测试留下的配置。普通应用的默认存储路径与启动行为不变。训练窄屏导航用单行首页/页面菜单/结束区，保留原导航去向，不把页面入口删掉来换空间。

`final-iphone` 的 7 项设计测试、29 份观测通过，但截图复查发现 `training-active-rotated` 的时间仍被短滚动区裁掉。按钮在窗口内不能代替主要信息可读，这是方法本轮发现的产品可用性问题，而不是把整页可滚动都判错。随后给短窗口加入紧凑的时间/次数/节奏同排展示，并把横屏时间及节奏标签完整落在观测滚动区内作为定向回归；辅助功能大字号继续纵向，不靠整体缩字。操作列按实际两/三项分配，避免宽屏只占左半留出空按钮位。待新一轮复查后收口。

`final-ipad` 的 7 项设计测试、40 份观测通过，包含全部 14 个 Home 场景；这是紧凑观测修正前的中间快照，不作最终修正版的全部证明。截图复查包含深色、键盘、大字号、只读回顾及训练等待/横屏等。深色下原品牌绿用于小图标/文字偏暗，因此另设自适应前景 accent；实心保存按钮保留深绿/白色，避免直接把浅色前景当填充后损失文字对比。最新候选再复查。

大字号的训练界面保留标题、用时和主要操作，节奏演示及次要目标可滚动，接受它不全在首屏的取舍；短窗口普通字号采用专门紧凑区，两者不混成一次全机型保证。录像状态在预览上轻量显示，不因诊断折叠而隐藏临时录像中/未保留的事实。

`final-iphone-after-fixes` 是完整功能复查中的失败快照：24 项 UI 中 4 失败，33 项 App 中 1 失败，不能当作全绿。Home/Journal 12 项、三个设计方法及暂停恢复等其余路径通过。失败分别为系统文件面板严格限定“取消”按钮、总结更正点击、横屏双侧反馈两条路径无法获得键盘焦点，以及隔离测试比较 URL 目录尾斜杠造成的不等（不是目录写错）。

已根据这些信息收紧反馈态的紧凑布局：手机横屏保留 44 高导航，移除重复的外部进度标题，减少垂直空白并保留保存入口；新增 `training-feedback-rotated` 和左右次数输入/键盘截图。总结更正扩大点击区域、标题使用 inline，自动化须将按钮滚入实际总结窗口再点，不把 exists 当作可操作。原系统文件导出逻辑不变，测试沿用已有 Journal 用例的 Save/保存及 Cancel/取消、任意 AX 角色匹配并保留原生面板证据。目录隔离单测比较结构化路径组件，不比较目录尾斜杠标记。新版本定向复查继续中。

只读回顾还补上“部分完成”组：样本目标 10/实际 8 的记录不能因为 completed 和 skipped 均为 0 而呈现成零活动。卡片和总结分别显示该原状态，没有更改训练档案或完成判定。

`phone-repair-pass` 中 33 项 App 和 6 项定向 UI 通过，仅诊断列表一项未通过（整体仍失败）；横屏双侧输入、完整四组/更正/重启及大字号/深色/投影已通过。`phone-final-diagnostics` 中总结更正重跑通过，诊断推进到文件面板关闭后状态未出现，仍不通过。模拟器实际有 10 个临时包、2 个已保留包；原列表将已保留区域放在临时区域之后，故改为有数量的「已保留 / 待核对」切换，不删除积累样本。

文件面板的 AX 树还证实“取消”是不可点击的 Other，事件返回 `{-1,-1}`；旧 Journal 用例只断言背后页面存在，曾出现假阳性。现为系统原生目录选择器提供独立 44 高的关闭栏，仍由系统完成选目录/导出副本；导入只在选择完成且面板关闭后进入原确认流程。回调只消费一次，取消不恢复或覆盖资料。测试要求关闭控件和系统保存控件都消失、返回界面可点、草稿/保留包仍在。

关闭导出面板只报告「已关闭导出面板，本机原件保留」，不声称外部副本已被撤销；只有系统成功回调才报告导出完成。没有对每个外部文件提供器、保存中关闭或实际成功导入/导出做全覆盖保证，核心目录往返与损坏拒绝测试另行保留。

`.tmp/ui-phone-picker-verified.log`：3 项加强后的手机文件面板测试通过、0 失败，含诊断分类/关闭与备份导入/导出关闭。`final-ipad-verified` 已锁定同一原生源码指纹 `773c848c59e9c42143bbfc9786d1b4ee4132bfb01bf6177f50fac201d9c9ffe4`，运行最终完整业务包和受影响设计场景；结果待完成后补记，不提前算通过。

`final-ipad-verified` 已结束：33 项 App 测试全部通过，37 项业务 UI 测试全部通过（Home 4、Journal 8、Native 3、Diagnostic 2、Vision 16、WorkoutVision 4）。6 项设计方法中 5 通过，训练方法在最后的横屏双侧输入失败，所以整个运行仍是失败，不写成“76 项一次全绿”。25 份设计观测及失败结果原样保留。

最终按证据组合验收：33 项 App、37 项业务 UI 的平板完整回归，加最后 5 项修正后的定向复查；手机既有设计、业务及加强后的文件面板结果另列于上文。不把重复执行相加成独立覆盖量。已复看最终平板活动横屏/暂停竖屏、手机深色、部分完成回顾和横屏输入；保留大字号下次要内容需要滚动的取舍。
