# Fox 本地 UI 审查

用正式 SwiftUI View 复现场景，比较同条件截图、可访问性树和几何事实，再做设计判断。它服务当前产品，不是一个自动审美评分平台。

## 日常入口

在仓库根目录运行，需要完整 Xcode、XcodeGen 和已有 iOS 模拟器，不需要连接或解锁真机：

```sh
npm run design:review -- --device iphone --group home-smoke
npm run design:review -- --device ipad --group records
npm run design:review -- --device ipad --group projections,training
npm run design:review -- --device ipad --group training-feedback
```

分组：`home` 为 14 个命名场景及输入增长的列归属检查；`home-smoke` 只跑混合、长图、大字号、深色及列归属；`records` 为详情、更正冲突、备份及缩放交互；`projections` 为本机计划、未结束、已确认、缺失、损坏及只读详情；`training` 为准备、等待、活动、暂停、休息、反馈、总结、诊断核对及横屏/大字号。它们是有限风险样本，不是全组合或全部设备的证明。

默认通过现有 `doctor` 和共享会话创建本次专属模拟器，固定通用运行时及对应型号；结束/取消只清理本次创建者。其他任务有活动实例则拒绝，不自动关闭。诊断需要借用已有目标时用 `FOX_IOS_SIMULATOR=<UUID>`，必须属于固定运行时，不会被删除。Duo 使用独立 `verify:duo`，不能按名称回退。当前 App 仍是全屏，未新增 iPad 分屏支持。

`training-feedback` 只复查横屏双侧反馈输入，便于修键盘问题时少跑其他状态；场景与完整 `training` 分组共用同一驱动。首次输入确认键盘出现，输入后另采截图/AX，再定位下一输入框并断言左右实际数值；切换输入框时不要求软件键盘始终存在，也不靠放宽完成次数来消除时序失败。

可加 `--output .tmp/design-review/<unique-name>`；不得复用已有回执/结果包。复用 `runSuite`，输出 `suite.json`、`design-ui.log`、`design-collect.log`、`source.json`、`result.xcresult`、`report.json`、`index.html` 和附件。suite 绑定完整仓库指纹/提交/环境/取消清理，scope 为 `diagnostic`；source.json 仅是额外原生源码指纹。报告保留实际设备、方向、字号/外观请求、控件几何、AX 原树及未知项。

`home` 包含 remaining+smoke 的不相交并集，`training` 包含 remaining+横屏双侧反馈；组合组也只选择每个方法一次。完整套件仍执行全部场景与原断言。必须精确执行选中方法并产出每个预期场景的截图，缺方法/skip/缺图/取消/清理失败均不能成功。不通过几何报告推断业务正确性。

中途失败保留原结果；只修相关问题后另建目录复查。只收集现有结果时使用 `node scripts/design-review.mjs collect --result <xcresult> --output <directory> --group <原分组>`；collect 不生成 suite 成功回执，没有事前 source.json 则源码未核对，也不能事后补指纹冒充构建证据。

## 每次改页面

1. 确定主要任务和真实数据来源，在 [页面意图](UI_INTENT_AND_REVIEW.zh-CN.md) 补充必要意图，不复制全部尺寸。
2. 先跑受影响场景，查看基线；修改正式 View，Preview 与 Debug 宿主不另画一套演示 UI。
3. 同设备、方向、字号和输入重跑，对照截图；frame 在屏内只说明几何边界，不能证明图片可读、文字无截断或按钮容易发现。
4. 将判断分别写为明确约束违反、可用性风险、设计取舍或证据不足；附输入、来源、源码指纹、截图/AX 及修正理由。无真值不报召回率，无用户实测不自报可用性分数。
5. 独立运行受影响功能回归。布局截图不能证明媒体字节、修订、取消、状态机和重启恢复正确。

问题记录建议：`ID / 意图来源 / 场景条件 / 事实 / 判断类别 / 修改或接受理由 / 同条件复查 / 尚未观测`。采用已有实施记录即可，不再增加任务平台或约束 DSL。

## 隔离与证据边界

运行场景须 `DEBUG + FOX_UI_TESTING=1 + FOX_DESIGN_SCENARIO=<id>`；Release 不进入宿主。记录、训练档案、诊断样本和视觉控制器参数/报告均注入 `tmp/FoxDesign/<scene>`，不借用普通测试或正式资料。照片均为合成图；媒体选择/拍照入口不执行，相机状态只用显式 fixture。普通首页仍连接正式本机资料。不要为了做截图把个人数据库、照片、视频或原始设备信息提交到公开仓库。

首页训练投影直接解码并校验训练档案，不构造会触发恢复写入的 `LocalTrainingRepository`；缺文件不造默认计划，损坏文件不修复覆盖。进入现有「训练」执行入口才允许沿用原恢复规则；打开只读卡片不等于开始训练。该功能不是同步、分析或另一套日志数据库。

自动化可验证主要操作在所测窗口可见/可点，并复查业务不变量；真实远看、触控、系统照片提供器、传感器负担和真人计数仍是另一个证据层。无需为静态设计变化重复安排一整轮人工操作，也不因此把 FIT-LIVE 改为通过。

## 本轮结论

M1–M4 已完成本地候选验收。这套小流程找到真实跨列跳动和横屏用时裁切，并用同条件复查守住；长图和冲突对照支持明确的阅读策略修改，功能测试还揭示了原系统文件面板关闭断言的假阳性。维护成本主要是命名场景和两类模拟器运行，不需要逐控件手写坐标。当前没有完整人工真值、独立用户耗时或长期误报统计，因此暂不抽取跨项目平台；继续在页面变更时使用这套轻量流程，收益不足再删减场景。
