# 阶段路线图

## 当前优先级（2026-10-17）

1. 记录与存储：独立本地核心接住文字、照片、时间、来源与修订；先用自动测试验证保存、恢复及故障边界。
2. 前端入口：已进入文字设计，采用圆角卡片瀑布流，记录入口也是卡片；iPhone 一列，iPad 探索两列/三列，比例与具体尺寸待草图确认。见 [Home 设计记录](design/HOME_CARD_FEED_V0.zh-CN.md)。
3. 分析与互联：仅登记后续计划；三个级别分别是记录照片交换、训练观察/交互协作、多摄或深度融合。云端是路径选项，不另算一级；外部测量和分析独立登记，均未启动。见 [后续任务台账](planning/LIFE_LOG_BACKLOG.zh-CN.md)。

第 1 步的独立库和本地自动验收已完成；不包含 App 界面接入或真机记录验收。详见 [记录与存储 v1](journal/RECORD_STORAGE_V1.zh-CN.md)。现有训练功能保持，未完成的真人验收仍保留，不把新存储测试当作旧目标完成。

会话内已提供三稿交互预览，尚未原生实现。下一轮建议保护旧训练基线，提前做 iPhone 配对/开发者模式准备，并行开发第一份手机兼容的 Fox；到真实签名/信任门槛后再继续本地记录与双尺寸验收，详见 [原生 Home 实施计划](planning/HOME_NATIVE_IMPLEMENTATION_V1.zh-CN.md)。本轮设备检查只有 iPad，未安装新 App。

训练方面新增 [成果、未复盘训练与四动作路线](fitness/FITNESS_VISION_BASELINE_AND_NEXT.zh-CN.md)：保留当前两动作，后续逐个探索高位下拉和卷腹，先用单机前置 RGB 摄像头；深度与多设备收益另验，不扩写旧 Part 1 的验收结论。

## 既有健身路线：D0–D3（2026-10-06）

Part 1 候选 Fox 0.4.0 / build 10 已安装：两个指定机位动作接入当前组、人工核对与离线记录，软件自动化通过；续审补修提前结束保存失败后的相机状态与错误提示。M4 真人相机和真实训练验收仍待完成；不等同 D1 / D2 全部验收。具体证据见 [Part 1 执行记录](fitness/REAL_EXERCISE_DAY_1_PART_1_EXECUTION.zh-CN.md)和[逐项审计](fitness/REAL_EXERCISE_DAY_1_PART_1_ACCEPTANCE_AUDIT.zh-CN.md)。Part 2 的独立质量评价和提醒后置，先保留真实训练数据。

目标是稳定的家庭训练助手：训练时少操作屏幕，训练后得到可信、可纠正的记录。

1. **D0 原生离线底座**：Fox 不再加载 Mac 网页。计划、训练、计时、反馈、总结、历史在 iPad 本地运行和保存。
2. **D1 动作与机位验证**：M4 本地二维关键点，已补足倾角、人工朝向和画面尺度记录；本轮回归侧身弯举并适配正面侧平举，分别记录次数与阶段时长，随后真人参考对照。
3. **D2 训练闭环**：观测结果进入实际组记录，用户可纠正；摄像头失效时可手动完成。
4. **D3 使用与复盘**：多次使用后评估准确性、节奏和操作负担，决定更多动作与语音价值。

规格与验收条件见 [D0–D3 计划](fitness/IPAD_LOCAL_MVP_D0_D3.zh-CN.md)。软件定期修订并测试后发布，不在训练中大改。核心训练不依赖 Linux 4090、大模型在线或实时语音通信。

## 历史路线

以下阶段记录此前 Web/API 原型的路径。

这份文档描述产品阶段。更细的工程执行顺序见 [开发路线图](development-roadmap.md)。

## Phase 1：文档设计

当前阶段。

目标：

- 明确 fox 总体愿景。
- 明确健身先行。
- 明确训练主持闭环。
- 明确 AI 与状态机边界。
- 明确下一阶段数据库和本地 Web Runtime UI 所需概念。

完成标志：

- 文档结构完整。
- JSON schema 可校验。
- 下一阶段可以直接设计数据库表和本地 Web Runtime UI 原型。

## Phase 2：数据库设计

目标：

- 把文档中的健身概念落成数据库草案。
- 设计 Entry 与 WorkoutSession 的关系。
- 明确事件日志模型。

范围：

- 不做 iPad。
- 不做 ASR/TTS。
- 不做姿态识别。

## Phase 3：本地 Web Runtime UI 原型

目标：

- 在本地浏览器完成一次训练。
- 支持计划、确认、动作执行、休息倒计时、反馈、调整、总结。
- 支持节奏动画、可视化倒计时、触控友好的反馈按钮。

最小界面：

- 今日状态 check-in
- 计划确认
- 主训练执行
- 组后反馈
- 休息倒计时
- 总结确认

## Phase 4：iPad App

目标：

- 把本地 Web Runtime UI 验证过的流程搬到 iPad。
- 优先大按钮、倒计时、当前动作、总结确认。

不做：

- 复杂 3D 形象。
- 自动姿态识别。
- 全自动语音控制。

## Phase 5：ASR/TTS

目标：

- 用语音降低训练中操作成本。
- ASR 输出结构化反馈事件。
- TTS 播放教练消息。

原则：

- 不复用旧实现。
- ASR/TTS 只做输入输出层。

## Phase 6：传感器与姿态识别

目标：

- 研究加速度计计数。
- 研究摄像头姿态估计。
- 对少数动作做辅助验证。

原则：

- 不影响手动反馈主流程。
- 准确率不足时只作为参考。
