# 通用记录与本地存储 v1

日期：2026-10-16。范围：记录、存储和自动验收；不决定前端入口，不引入分析或设备互联。

## 2026-10-28 同步扩展（当前契约）

下文 2026-10-16 的 v1 设计/验收为历史基线。新源码将 SQLite `user_version=1` 原子升级到 2，保留应用/设备身份、记录、全部修订及照片；未知版本仍拒绝打开。设备已安装版本尚未升级，不将源码迁移测试当作真实设备迁移。

- `FoxJournalCore` 仍无网络依赖；新增事务 outbox、远端事件/头、游标、删除墓碑及暂存照片引用。`FoxSyncCore` 只通过库接口编排，不直接修改 SQLite。
- 配对时按历史顺序建立不可变操作链；本地录入/修订/删除与 outbox 同事务提交。未配对删除保留原 v1 语义；配对后删除只隐藏当前记录，历史和照片继续保留。
- 拉取页必须连续、来源资料库一致、照片摘要完整；同事务写事件、投影与游标。已确认的新头不会被回填旧页降级。待上传/冲突/超限记录不被远端静默覆盖。
- 远端原始操作与本机展示修订分层保存；本机修订号不是全局事件号。冲突两侧均保留，只有取得服务器所指向的版本后才允许用户选择。
- 多照片逐张校验落盘；已暂存的照片在重启清理中受保护，未完整提交的页不推进游标。只保存已校验字节，不由缺失附件补造记录。
- 同步线限额为单张照片 25 MiB、操作帧约 64 KiB（包含元数据及凭据空间）。本地较宽限额保持不变；不能发送的历史链标记 blocked，不删除、不自动截断，也不阻塞其他记录和拉取。解除 blocked/分块修订后置，后续编辑不会暗中跳过原历史。
- 无同步证据的导出继续使用 `fox.journal.backup.v1`；有墓碑/同步证据时使用 v2，保存完整历史、墓碑、原始操作和其引用照片。两版共用 [Schema](../../schemas/journal-backup.schema.json)。不导出 Keychain 凭据、运行游标或资料库绑定。
- v1 恢复保持原有幂等/冲突规则，已配对库恢复新历史时同事务入队；v2 恢复只允许空且未配对的目标，避免隐式改写现有同步身份。恢复后可重新配对，原操作仅是保留的证据，不冒充新服务器已确认事件。

同步状态、原生 UI、验证和真机门槛见 [SYNC-3 执行记录](../planning/PERSONAL_SYNC_NATIVE_V1.zh-CN.md)。备份不是同步，也不是异地备份服务。

## 目标

同一套存储接住纯文字、纯照片或照片加留言。保存不等待 AI，不要求选择饮食、健康、消费等单一类型。买了和吃了仍是用户原文，不自动生成摄入、支出、诊断、库存、热量或建议。

新增独立 Swift Package `apps/ipad/FoxJournalCore`，兼容 iOS 16 / macOS 13 及以上。使用系统 SQLite、Foundation 和 CryptoKit，无网络依赖，不依赖训练核心。

不修改现有 `training-records.v1.json`、视觉报告、Mac 后台 SQLite 或 Fox Say。训练与生活记录的映射及旧档案迁移需单独设计；本轮不宣称两套数据已经统一。

## 契约

- `CaptureDraft`：调用方先生成并保留稳定 ID、记录时间；重试复用同一草稿。照片可为零张，文字可为空，但二者不能同时没有有效内容。
- `CaptureRecord`：通用记录及修订号，不强制业务分类；可选用户标签不是分析结果。用户原文和照片字节不经 AI 改写。
- `recordedAt`：实际登记时间；`occurred`：用户声明的发生时刻或区间，带时区和 exact / approximate / day 精度。未声明时保持空，不把保存时间冒充起床时间。
- `CaptureSource`：来源设备；外部来源预留 provider / sourceRecordID。只是来源描述，不是设备认证，也不是 HealthKit 接入。
- `PhotoAttachment`：稳定 ID、MIME、字节数、SHA-256 和受约束相对路径；不存数据库 BLOB，不依赖相册临时 URL。允许 JPEG、PNG、HEIC；本层保存不解释图片内容，不保证上传字节确实是有效图片。
- 修订显式提交 `expectedRevision`；过期修改拒绝。原输入和照片保留在修订历史，删除才移除整条记录的历史。更正不自动变成消费或健康事实。
- 录入 ID 重试：与首次输入一致时返回当前记录，不新增、不回退后续修订；同 ID 不同输入报冲突。
- 时间线默认按发生时间（若有）否则记录时间排序；同一时间以 ID 确定顺序。提供字面文本、标签、半开时间区间和分页查询。offset 分页不是跨修改的快照游标。

## 存储与故障

独占应用私有目录：`journal.sqlite`、`attachments/`、`staging/`。SQLite `user_version=1` 与应用标识用于识别格式；未知版本、其他数据库、损坏文件拒绝打开，不重建或清空。

SQLite 事务覆盖记录、修订和附件引用。照片先写临时文件、原子发布，才提交数据库。失败或进程终止前未提交的条目不可见；下次打开在排他写事务下清理孤立照片和临时文件，不以孤立附件补造记录。实例内串行访问、实例间用 SQLite 写锁和修订检查。

已验证的是进程在提交前终止后的恢复，不是实机断电或存储介质故障验收。

附件删除存在数据库与文件系统两阶段：先删除记录及引用，再清理已无引用的照片；删除失败要返回待清理 ID，不能声称照片已经完全删除。再次打开或显式 cleanup 重试。其他记录与历史引用的照片不能被清理。未识别文件不擅自删除。

沙盒目录限制和 iOS 系统数据保护用于本地隔离；本轮不自研加密。普通删除不承诺 SSD 取证级擦除，已导出的旧备份也不会自动删除。

## 本地备份，不是同步

完整备份目录包含 `manifest.json` 和所有仍被修订引用的原照片。manifest 格式 `fox.journal.backup.v1`；包含当前记录、历史、来源和附件摘要。日期使用 Unix 毫秒数，与 JSON Schema 一致。

- 导出使用数据库一致性锁和临时目录，全部成功后发布；目标存在则拒绝覆盖。
- 恢复先校验格式、限额、历史、引用、路径、照片长度及摘要，再原子提交。路径遍历、符号链接或缺失照片拒绝。
- 重复恢复相同记录幂等；本地已更改或同 ID 不同历史时整体冲突，不默默覆盖，也不导入半份备份。
- SHA-256 用于字节完整性，不是身份认证或备份签名。备份本身含敏感内容，不默认上传。
- 本地备份没有额外加密，应保存在受保护的位置；调低新输入或备份限额不能让已有记录无法读取或删除。

前端未来只需调用保存、修订、查询、删除和备份接口。表单、时间线、聊天或快捷入口均不属于本轮；不增加“同步成功”“AI 已处理”等尚不存在的状态。

## 自动验收

先写测试，再实现：文字/照片往返、时间与来源、稳定 ID 重试、修订与过期写入、字面搜索、删除及清理失败、附件/提交失败、真实子进程终止、备份恢复与重复导入、冲突与损坏、路径/符号链接、未知版本、双连接并发边界。

真实进程终止夹具仅运行在测试生成的临时目录中；不打开摄像头，不使用个人照片，不访问网络或真机档案。故障注入限定为 Swift Package 内部测试接口，正常客户端不启用。

本轮完成依据是磁盘状态和测试，不是界面演示；不会发布新 App 或把这层地基描述成已经可在手机上拍照记录。

### 运行方式

需要 macOS、完整 Xcode、Node.js 22+ 和 Python 3。JSON Schema 验证依赖单独声明，可在虚拟环境中安装后运行：

```bash
python3 -m venv .tmp/journal-venv
source .tmp/journal-venv/bin/activate
python3 -m pip install -r scripts/journal-schema-requirements.txt
npm run test:journal
```

`test:journal` 运行 Swift 测试、验证 Swift 实际导出的合成备份及 Schema 反例，再使用 iPhoneOS SDK 编译库目标。测试目录与个人档案隔离。一起回归旧训练核心使用 `npm run test:native:all`；工作区检查仍使用 `npm run verify`。GitHub Actions 的 macOS 原生核心任务已加入同一入口，远端 CI 需提交后另行确认。

### 调用边界示例

```swift
let repository = try LocalJournalRepository(directory: privateDirectory)
let draft = CaptureDraft(note: "起床了，感觉头疼")
let saved = try repository.record(draft)
let records = try repository.list()
```

调用方需保留 `draft` 才能安全重试；库接口为同步磁盘操作，未来界面层应在后台串行任务中调用，不阻塞主线程。这里不自动判断头痛开始时间，也不生成医疗结论。未来前端只需先满足这套调用契约，再讨论具体入口。
