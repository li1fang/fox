# 训练与视觉：保留基线及四动作路线

日期：2026-10-17。范围：整理现有成果、证据边界、未复盘训练与后续选择；本轮不修改 App、计数器或个人训练数据。

## 1. 当前决策

Fox 接下来优先把 Home 卡片和本地生活记录落地，不持续只开发健身视觉。既有训练作为独立功能保留，不因换首页而重写状态机、迁移档案或重新开始算法开发。

视觉继续以单台设备、本地前置摄像头的 RGB 画面和二维关键点为主。阶段候选是哑铃弯举、侧平举、高位下拉、卷腹四个动作，逐个验证，不一次承诺四个均可靠自动计数。深度和多设备协作是后续选择，不是本轮 Home 或正常手动训练的前提。

“前置摄像头”指设备镜头，不表示所有动作都正面对镜头；侧身弯举仍采用侧身机位，高位下拉可以从背面或其他经验证机位观察。设备可能发现 TrueDepth 镜头，但当前 `PoseCamera` 只接收视频画面，未配置深度数据输出，不据镜头名称宣称已经使用深度。

同日最新现场结论：用户恢复使用后反馈“功能存在，但不可用”；已取回 3 份新鲜 M4 弯举报告并重现 0/5/4 次，但没有人工次数，不以此宣布准确。启动困难、主体丢失锁定和未启动不落完整诊断仍需解决，不能仅保留“待真人验收”的旧状态。详见 [M4 现场复盘](M4_REAL_TRIAL_REVIEW_20261017.zh-CN.md)；本轮没有修改算法或另发候选。

### 开发视频与历史失败

同一开发视频的当前候选回放分别对应左弯举 10、右弯举 9、左右侧平举各 5 次，另检查额外事件、漏事件、跨循环合并、主体粗检查点和无意图动作窗口。旧 v3 左侧平举漏 1 次的失败结果继续保留，不能改绿或删除。

这不是独立泛化验收，也不是动作质量判定。用户曾观察到正面弯举遮挡、伸直时丢点、左右差异和侧平举闪烁；这些问题是边界和待补样本，不因开发视频回放通过就视为现场解决。正面弯举仍不作为已支持机位。

复盘仍按三类分开：信息补充、软件问题、训练反馈。软件漏计不等于身体无力或动作不标准；疲劳/无法完成与追踪失败不能自动互相推断。不要求为验收而额外运动。

## 5. 四个动作的本地摄像头路线

这是软件适配候选，不是训练处方；可用训练动作不应只限于视觉会数的四种，其他动作继续允许人工记录。

| 动作 | 当前状态 | 首选机位 / 下一步验证 |
|---|---|---|
| 哑铃弯举 | 已有专属几何、状态机与开发视频回放；当前候选未完成新鲜 M4 真人验收 | 侧身，所选臂靠近镜头；分别核对左右、放低遮挡、正常疲劳下的半程与早停 |
| 侧平举 | 已有正面二维算法与 v4 对侧躯干参照；现场稳定性仍需验证 | 正面；核对两侧、髋短缺失、顶峰/返回、静止和中断，不只看最终总数 |
| 高位下拉 | 未适配；代码中的 `VisionExercise` 目前没有该动作 | 用户曾提及背面录像，尚未导入本项目语料；先确认素材与可见关节，再选背面或其他单机机位，不先编阈值 |
| 卷腹 | 未适配；无动作专属算法或已接受语料 | 用户曾提及侧面录像，尚未导入；先验证肩、髋与躯干周期是否可观测，不把二维角度变化当作脊柱质量评判 |

实施顺序建议：先保留现有两动作并复盘正常使用，再一次引入高位下拉或卷腹中的一个，完成独立回放与负例后再考虑另一个。顺序可由素材可见性调整，不把“四个”变成一轮必须全交付的数量指标。

每个动作各自定义：可观测关节、支持机位、起始就位、收缩/顶峰/放松往返事件、最低计数门槛、短缺失与长中断规则、静止/半程/离场/路人负例，以及人工计数对照。最低计数门槛不是专业动作标准性评分；节奏、动作质量分别设计，不生成总分。

验收同时保留自动观测、逐次事件和人工参考次数。先检验主体选对，再检验动作事件；对总数相同但漏一误一的结果仍判有问题。无法观测或未适配时明确回退人工，不鼓励扭曲动作迎合软件。

## 6. 深度与多设备：需要收益依据再启动

- 先用 RGB 画面和合理机位验证四动作的实际可观测性；如果调整机位或参数足够，不为“更先进”而加深度。
- 两设备交互属于 [CON-02](../planning/LIFE_LOG_BACKLOG.zh-CN.md)：一台主持本地训练，另一台接收状态/发命令，不传实时视频；它不是深度融合，也不保证解决遮挡。
- 深度或多摄融合属于 CON-03，暂缓。必须先指出未解决的二维失败类型，比较同样动作和环境下的漏计/误计、时延、计算及操作负担；没有有意义收益就保留单机或人工方案。
- 不能把双机几何标定、时间同步、人体关联、深度坐标映射及隐私成本藏在一次“摄像头升级”中，也不把 iPad 上的验证直接外推到 iPhone。

## 7. 新 Home 如何保护旧训练

1. 训练逻辑保持模块边界：新首页负责导航和只读卡片投影，训练状态、计时器、`WorkoutVisionCoordinator` 和人工确认规则不为卡片重写。
2. 维持 `com.whipa.fox` 与 `Application Support/Fox/training-records.v1.json`、视觉报告、参数文件的语义；生活记录使用独立存储，不把训练文件改塞新数据库。本轮不迁移。
3. 大改前先做新的设备快照、源码/资源与旧构建保留。当前工作树有历史修改和未跟踪代码，需要整理基线，不能 `git reset`、批量丢弃或把“回滚代码”当作“恢复用户数据”。本轮没有自动提交或推送。
4. 新 Home 仍可继续未结束训练；切出、后台、相机与保存失败的原保护须回归。存在进行中训练时不部署替换候选，不替用户结束训练。
5. 首次新版本优先装到新 iPhone 验证记录入口；iPad 保持 build 10，直到兼容与旧训练回归通过。不得为清洁测试先卸载旧 App；安装同 Bundle ID 也需安装前后核对，不能无条件保证数据安全。
6. 新 App 中的训练卡来自真实可用来源；不能复制会话预览里的沙拉、6 组、明日计划等示例到正式档案。

具体阶段、人工操作点与真机测试选择见 [原生 Home 实施计划](../planning/HOME_NATIVE_IMPLEMENTATION_V1.zh-CN.md)。
