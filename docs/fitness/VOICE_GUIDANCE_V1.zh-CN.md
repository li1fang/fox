# 训练语音引导 V1：先让下次训练少看屏幕

日期：2026-10-23（Asia/Bangkok）。性质：**研究与设计基线，不是当前交付状态**。后续已有部分实现与自动测试；是否可试用以[执行记录](../planning/NEXT_TRAINING_TRIAL_EXECUTION_V1.zh-CN.md)及 A6 设备证据为准。

同日排期修订：用户不采用逐个 G1–G4 交付/批准的方式。最新执行入口是[三阶段集成路线图](../planning/NEXT_TRAINING_TRIAL_ROADMAP_V1.zh-CN.md)：下次试用前连续完成 A0–A6，合并语音、有限阶段引导、画面叠加、组间确认、诊断与模块化。本文保留语音研究及技术约束，G 编号仅作为能力分类，不再表示人工确认关卡。

## 1. 本轮决定

值得开始。首个交付目标不是一个持续说话的 AI 教练，而是：**在现有计数可信的边界内，用简短声音报告次数、准备与休息状态，让用户少看屏幕。**

能力依赖：报数/流程事实、鼓励、阶段引导、组间确认共用受控播放通道；专项纠错还需要对应测量证据。依赖不意味着每项独立发版或等待用户批准；准备、报数、节奏不能共用一个触发条件。

下次训练候选合并 G1、G2 的计划/可观察阶段引导与组后区间反馈、G3 的有限触控问答；不包括尚无依据的自动速度纠偏或 G4 姿势纠错。不增加 ASR、常开麦克风、LLM、Linux 服务或多设备链路。这里是功能设计，不是新的训练处方；是否继续、减重或结束由用户决定。

## 2. 研究告诉了我们什么

这是一次面向当前产品决策的定向检索，不是系统综述。以下优先引用原始研究，区分实验发现、研究范围和 Fox 的工程选择；不能把更多次数或更快向心速度等同于动作更安全。

| 原始研究 | 实际发现及边界 | Fox 的设计启示，非论文直接结论 |
| --- | --- | --- |
| [Radha 等，2020，家庭阻力训练的环境光/声音反馈](https://cardio.jmir.org/2020/1/e16354/) | 34 名参与者；Kinect 深度观测与环境光/声音组合改善了一些节奏/幅度指标，但摘要未显示优于人工语言指导；呼吸表现反而是无反馈条件最好。不是单独测试 TTS 或单目 RGB。 | 节奏反馈值得试，但不要同时塞入动作、节拍、呼吸三套指令，也不因这项实验改用深度。先验证一个输出目标。 |
| [Pérez-Castilla 等，2020，反馈频率](https://pubmed.ncbi.nlm.nih.gov/32998108/) | 15 名男性，在跳跃和卧推抛举任务中，每次重复后的速度反馈有利于急性速度输出。 | 不能笼统说“反馈越少越好”，也不能因此每次动作都催快。我们的目标是记录与可控节奏，不是最大爆发速度。 |
| [Marchant 等，2011，注意焦点与肌耐力](https://pubmed.ncbi.nlm.nih.gov/21957705/) | 23 人史密斯卧推、另 17 人自由卧推/深蹲实验，部分条件下指向器械运动结果的提示比指向身体部位更有利于重复次数；有训练经历的人群，非伤害预防研究。 | 优先一句可执行的短提示，如“控制哑铃放回去”，不连播多条关节术语；具体中文措辞仍需试听与使用验证。 |
| [Garner 等，2024，卧推动作声音化](https://pubmed.ncbi.nlm.nih.gov/39808805/) | 20 名男性，动作声音化、自选音乐和无声条件的最大重复次数未发现显著差异。脑活动变化不等于训练效果变好。 | 不以声音复杂或更有趣推断有效；先验证报数是否减少分心，暂不造连续音高/音乐系统。 |
| [Miras-Moreno 等，2025，反馈与音乐](https://pubmed.ncbi.nlm.nih.gov/39924649/) | 15 名有阻力训练经历男性的卧推实验，音乐及音乐加反馈有表现收益；作者强调个人偏好。不能推广为所有人、动作与提醒频率的最优方案。 | 保留只报数/带鼓励/关闭的偏好，兼容用户自己的音乐，不强行接管全部音频。 |

共同结论：有理由尝试听觉反馈，没有证据保证 Fox 的当前二维观测能可靠纠正姿势，也没有研究替我们确定中文提示频率、音色或延迟阈值。后文的阈值是可调整工程初值，不是医学或运动科学标准。

### 三动作不能混为一谈

| 动作 | 报数的事实时点 | 节奏提示的限制 |
| --- | --- | --- |
| 侧身弯举 | 一个周期完成，回到计数返回端点后 | 此时再说“现在慢慢放下”已经晚了；只能作下一次的建议，或另接真正的当前阶段事件。 |
| 正面侧平举 | 一个周期完成，回到计数返回端点后 | 同上；报数成立不代表没有耸肩或全身稳定。 |
| 背面高位下拉 | 持续到达收缩端点后 | 报数时不代表已经放回器械；前一次返回测量在下一峰才发布，不能用于指挥当前这一次。末次保留计数，不补造返回时长。 |

三份策略均为 `fullEccentricComparison=false`。当前下放量是可观察角度区间，不是完整生理离心阶段。[R2 执行记录](LIVE_RELIABILITY_R2_EXECUTION_20261023.zh-CN.md)中的四个开发样本有约 0.8 秒确认延迟与 0.5–0.6 秒起点不确定区间，不能直接包装成即时纠偏能力。

## 4. 把用户的五类建议变成可实现的提示

| 类型 | 试用前合并交付 | 后续能力与证据门槛 |
| --- | --- | --- |
| 计数与进度 | “一、二、三”；已确认计划下才说“七，计划还剩三次”“九，计划还剩一次”“十，计划次数已到”。 | 未知目标只报数；“最后一个”不能混淆正在做的和已经完成的，也不能变成必须完成的命令。 |
| 节奏 | 计划节奏、当前有效阶段的一般指引、组后返回区间；下拉使用“控制把手放回去”，不统一说“放下”。当前阶段提示须在 A2 因果/有效性回放中逐动作通过，否则该动作降级为组前/组后。 | 不把可见区间与完整目标硬评分。“稍微加快/你放得太快”暂不启用，慢可能来自疲劳、停顿或观察误差。 |
| 鼓励 | 可选、低频、非评价性：“加油，按自己的节奏来”；保存成功后“这一组记录好了”。 | “很平稳”是技术判断，不能随机播放；“今天快结束了”应改为有计划事实的“计划还剩一组”，且不把跳过当完成。 |
| 询问 | A4 合并重量、感受和继续休息的有限问答，复用原有输入/反馈，不做聊天界面。 | 更自由的对话后置；先问再等确认，未回答保持未知，不需接入常开 ASR，也不在承重过程中打断。 |
| 监督/纠错 | 先做系统状态：“准备开始”“追踪中断，已保留记录”，只在真实状态成立时播。 | G4 才试“再高一点、不要耸肩、站直”；需独立测量、机位适用范围、正负例和误报验收。识别到胳膊不足以作这些结论。 |

“稳住”容易被理解为额外持重停留，合并候选不把它当通用口头禅。“我能看清”改为具体状态，而不是全身动作安全保证。“不用看屏幕”是目标，不是无条件承诺：准备、恢复及记录异常仍可能需要用户确认。

### 合并候选的语音基本流程

1. 训练前点击扬声器开启并试听；默认中文、简洁、温和，不喊叫。组前一般指引在用户仍准备时播，不与倒计时争抢。
2. 用户表达开始意图，走回机位；真正进入准备倒计时才播“三、二、一”，开始保存成功后说“开始”。准备失败即取消旧语音，不自行继续数到一。
3. 每个新增、已保存的有效视觉次数报一次。计划目标已知时，剩余三次/一次的短语替代该次普通报数，不另排一段长话。计划或观察跟随的方块/阶段指引共用一份引导状态，失效即取消，不能挤压事实报数。
4. 瞬时缺点按现有算法恢复，语音保持安静；真到需重新就位状态才报一次追踪中断。声音不要求用户立刻拿着器械去碰屏幕，也不替状态机恢复。
5. 达到目标只报告“计划次数已到”，不自动结束、不说“放手”或“马上休息”。用户完成收尾后核对重量/感受、查看返回区间和保留诊断，成功确认后才跟随实际状态提示休息。
6. 休息时间到说“休息时间到了，准备好再开始”。允许继续休息，不由语音启动下一组。

非视觉训练可提供已确认的计划节奏，但不把计时器模拟节拍播成实际完成次数。独立视觉试验页没有计划时不造目标节奏或“今日还剩”。

## 5. 本地声音方案

选择：**合并候选使用系统 `AVSpeechSynthesizer`，优先设备上可用的中文声音**。它支持播报、停止及生命周期回调，不需要我们部署 TTS 服务；必须自己控制待播内容，因为系统默认会顺序排队，旧提示不会自然失效。[Apple 文档](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer)

本次不是音色供应商选型。系统声音是交付基线，不承诺达到豆包的自然度；准备阶段试听再决定是否接受。若不足，下一步优先比较一个固定短句音频包，离线随 App 分发，核对音源授权和商用范围；不因此恢复实时串流、语音克隆或模型服务运维。

音频约束：

- 枚举可用中文 voice，记录实际 identifier；资源缺失或调用失败就明确降级，不默默换语言。离线能力以目标设备断网试听验证，不由 API 存在推断。参见 [AVSpeechSynthesisVoice](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoice)。
- 评估 `.playback` + `.voicePrompt` 的短语音配置；音乐混合/临时降低音量须真机验证。不要默认启用打断其他口播的选项，也不要在整组静默期间持续压低音乐。参见 [voicePrompt](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/voiceprompt)。
- 静音立即停止当前话语并清空待播；系统中断、退出训练、App 后台也取消旧内容。恢复后只处理新事件，不补播旧次数。[停止语音](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/stopspeaking(at:))、[音频中断](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions)。
- 外放与耳机走同一体验，不要求用户先作选择、不另开蓝牙优化项目；耳机断开后暂停语音，不自动改成外放，避免意外泄露。阶段提示均检查当前有效性，而不是假设任一路由零延迟。参见 [音频路由变化](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes)。
- 不申请麦克风权限、不录音、不向第三方发送训练内容；现有诊断录像继续无声。VoiceOver 用户默认不叠加训练口播，显式开启时再验证两者共存。
- 仅在现有工具栏增加扬声器状态/静音、设置中的试听与“只报数/简短引导”选择，不重做训练布局；视听内容等价，音频失败不影响视觉记录。

## 6. 有限事件与调度，不另建一个训练引擎

```text
训练状态成功提交 / 新鲜视觉准备与追踪事件
  -> GuidancePolicy（纯函数：依据、文案、是否允许说）
  -> CueScheduler（去重、优先级、时效、取消）
  -> SpeechOutput（原生播放与回调）

语音无权调用计数器、改阈值、推进训练、保存反馈或修改计划。
```

### 6.1 事件边界

- 在既有协调器中追加旁听接入，不覆盖 `onCountingBegan/Updated/Paused`，不在 SwiftUI `body` 或每帧 `onChange` 直接调用 `speak`。
- 训练中计次事件晚于成功 `flush`。使用前后已提交状态差分，第一次订阅只建基线；历史恢复、人工改次数不自动重念旧报数。保存失败取消“已记录/完成”类提示并保留现有错误处理。
- `CurlRepetition` 目前没有 UUID。可用 `sessionID + setAttemptID + observationID + appendIndex` 作为新增语音事件键，不为了语音迁移老重复记录；总数取整组累计值，不能把新 observation 的局部数当整组数。
- 试验页使用 `trialID + segmentID + appendIndex` 隔离，语音只报告当前算法计数，不冒充已经保存的正式训练记录。训练与试验播放所有权互斥。
- 倒计时按 `PoseStartGate` 状态边沿与准备 generation 去重；重新准备可再次“三、二、一”，已过期的上一轮不能穿插。
- 媒体时间、控制器 uptime、墙钟分开记录。播放 deadline 用单调时钟；回放用受控时钟并显式换算原点，不能直接把视频秒当设备 uptime。

### 6.2 最小提示契约（设计字段，尚无运行时 Schema）

| 字段 | 含义 |
| --- | --- |
| `eventKey`, `generation`, `context` | 去重与会话/组/观察段绑定；准备、恢复或切组会使旧 generation 失效 |
| `kind`, `textKey`, `arguments` | 固定短句类型与参数；语言文案可调整，算法门槛仍由动作策略拥有 |
| `basis`, `evidenceRef` | `committed_count` / `session_state` / `planned_instruction` / `observed_interval`，不得把计划当实测 |
| `occurredAt`, `receivedAt`, `expiresAt` | 事件与调度时效；另存可选视频时间与原点映射 |
| `priority`, `cancelWhen` | 被什么状态取消，不能只有一串待播文字 |
| `guidanceVersion`, `strategyVersion` | 复现说什么、为什么说；声音实现可换，依据不能丢 |

### 6.3 调度初值

这些是合并候选的报数/调度初值，应通过离线回放和设备检查调整，不写入运动判定阈值；阶段引导另受当前有效性约束：

- 静音、退出、失效 context、音频中断是硬取消，不是队列里的高优先级台词。
- 其他候选优先级：真实状态切换/追踪中断 > 报数与准备倒计时 > 一般引导 > 鼓励。同一个事件只选一句，鼓励永远不能挡住报数。
- 最多一条正在播放、一条有效待播；新次数替换未开始的旧次数。每次启动播放前复核 context、状态与时效，不让系统 synthesizer 堆积多条。
- 普通报数的允许启动延迟初值为提交后 1 秒；倒计时只在当前秒/当前 generation 有效。超过时限丢弃并记原因，不赶着补报“一二三四”。开始提示必须仍处于该组 active。
- 开始新一组/恢复时可报告当前累计次数一次，但标明是状态摘要，不伪装成新的重复；重新进入页面默认不补播。
- 短暂缺点不说话；持续缺点的提醒按已有状态判断，一次状态转换最多一句。当前处于恢复宽限窗时，不谎称“计数已暂停”。
- “简短引导”每组最多一句非必要鼓励，只在不占用报数/准备的合适间隙；没有窗口就不说。不强行凑满配额，也不随机表扬技术质量。
- 正在播的旧语句若会与新状态冲突则取消；不要靠提高语速追赶积压。TTS 结束只代表软件完成播放，不代表用户听到或理解。

### 6.4 可追溯但不另建业务库

合并候选用版本化的小型文案资源和确定性 policy，调度初值集中配置；不造任意 JSON 规则解释器。动作策略仍是现有三份 JSON，不复制其参数，不改训练数据库结构。

测试/诊断可记录有上限的 `guidance-events.jsonl`：事件、选词键、依据、候选/丢弃/开始/结束/取消、单调时刻、原因与输出路由类别，不含录音或自由文本病史。保留诊断包时可一并导出；普通训练不永久堆积逐帧日志。

A4 把该可选文件纳入现有诊断包/`vision-evidence` 清单及 hash，不新建第二套运行档案或 SQLite。是否建语音统计表以出现真实查询需要为准，不以索引扩展为前置条件。

## 7. 先设计测试，再写播放代码

| 测试组 | 必须通过的行为 |
| --- | --- |
| 三动作事实契约 | 弯举/侧平举按完整周期，下拉按峰端；一条有效新增记录最多报一次。下拉最后峰保留报数，但没有终末返回时长、节奏评分或自动结束命令。 |
| 恢复与去重 | 短缺点、长丢失、重新准备、新 observation、切页、重载、重复回调、人工修订、切手动、试验/训练切换不重播历史、不串组、不按局部数归零。 |
| 计划与实测 | 目标未知不报剩余；越过目标仍可计数；目标达成不推进状态。非视觉训练不能报假次数。计划修改/提前结束使旧进度话语失效。 |
| 保存错误 | 注入磁盘满/写入失败：不报“记录好了”，不漏掉现有暂停/错误流程，不能为音频成功覆盖保存错误。 |
| 调度 | 假时钟 + 慢播放器模拟连续报数、倒计时取消、长句抢占、时钟变化、迟到事件；队列不积压、过期不启动、静音立即清空。 |
| 音频生命周期 | 假 SpeechOutput 注入无声音资源、播放失败、系统中断、耳机断开、后台；训练本身不受阻，恢复不补播，耳机断开不自动外放。 |
| 观察不可评估 | 低置信、缺点、只见部分阶段时无技术表扬/纠错；下拉上一轮返回不能被当作当前阶段发指令。 |
| 不退步 | 同一输入开/关语音，两动作和下拉的逐次时间、返回测量、弃权原因、重置次数及持久化语义一致；不能只比较最终总数。另做相机/诊断录像与声音同时运行的 smoke，比较帧间隔/掉帧，缓存一致不等于真实采集没有性能回归。 |
| 设备输出 | iPad 断开网络，现有短回放驱动真实 TTS；记录事件到 `didStart` 的 P50/P95、丢弃数、取消数与长尾，核对无麦克风权限请求、录像仍无音轨。正常速度用例的应播次数逐条核对，不能靠大量丢弃提示换取好看的延迟。 |
| UI / 使用 | 手机与平板原有首屏和旋转回归；扬声器状态可识别且可静音。正常运动中是否听清、烦不烦、是否减少看屏幕，仍由真人确认。 |

首个门槛：确定性用例零重复/跨组/禁用纠错，已有计数与阶段回放精确不变。正常速度回放无非预期漏播；故障/超载用例则要求按契约丢弃过期提示。设备回调延迟初始要求 P95 不超过上述 1 秒预算，超限不能算通过；可以先降级短句或更换离线音频实现。`didStart` 是应用回调延迟，不是扬声器出声或蓝牙到耳延迟，实际可听验证另记。

至少做一次短试听即可验证声音路线，不要求用户额外做一套健身来测试播放。既有视频可自动驱动决策和声音回放，批处理默认静音，只有显式音频 smoke 才启用；正常训练再评估分心和偏好，不虚构音频带来了技术改善。

## 8. 能力分类与新排期映射

| 原分类 / 台账 | 合并范围 | 实际排期与门槛 |
| --- | --- | --- |
| G0 / VOICE-00 | 本文、来源、边界与测试方案 | 本轮已完成设计；不等于代码已实现。 |
| G1 / VOICE-01 | 本地报数、真实准备/休息状态、鼓励、试听/静音 | A2–A3 实现，A5–A6 集成并发布，不单独等用户确认。 |
| G2 / VOICE-02 | 计划节奏、阶段跟随、组后区间；不含未经验证的完整离心评分 | A2–A3 实现及逐动作因果验收，A4 保存与展示；证据不足的阶段指令自动降级并记录。测量目标比较与纠偏留到 C 阶段决定。 |
| G3 / VOICE-03 | 重量/感受/休息的有限问答 | A4 接既有触控输入及显式确认，A5 覆盖取消、重复、失败；不要求 ASR，自由对话后置。 |
| G4 / VOICE-04 | 一种动作、一种可观察技术提示 | C 阶段后依新证据决定；单独标注、正负例与误报验收，不把计数通过翻译成“动作标准”。 |

试用前先使用既有录像，A0–A6 按测试连续推进，不逐个 G 编号发布。B 阶段只补针对性的自然训练片段；不为赶工放宽测量语义，也不把集成交付捆绑在监督、自由对话或新音色模型上。

## 9. 默认体验，不新增人工审批点

默认建议：**温和、简短的中文声音；只报数作为最低干扰模式，“简短引导”增加状态/组前提示及少量鼓励。** 真正必要的存储/追踪错误保持现有可见提示；语音关闭不妨碍使用。

外放/耳机不再是需先回答的问题。先采用系统音量/路由与温和中文默认值，提供运行时开关；试用时自然反馈音色和提示密度。下一轮按集成路线图连续实施，不必先讨论完整人格、长期语音供应商或为每个模块请求批准。
