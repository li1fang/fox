# 动作策略与运行档案 V1

日期：2026-10-23（Asia/Bangkok）。状态：软件/端侧缓存验证通过；见[执行记录](VISION_STRATEGY_EXECUTION_20261023.zh-CN.md)。不替代新真人训练验收。

## 目标与边界

用户认为 Fox 已迈过初步可用门槛，本轮从继续堆功能转向可维护、可解释、可回归。此判断不等于所有机位或所有动作均已验收。

按顺序实施：S1 收尾高位下拉；S2 三动作契约；S3 统一运行档案与可重建 SQLite 索引。保留旧记录、录像和历次回放，不迁移用户数据库，不变更弯举/侧平举算法，不做跨平台或大规模重构。卷腹/卧推等正常训练新录像后再评估。

## 职责与数据

- 代码：可执行状态机、类型校验；注释说明约束和原因，不复制阈值。
- 三动作 JSON：观察条件、关节需求、计次语义、缺点恢复、阶段测量及参数引用。复用现有 defaults 数值。契约版本、算法版本、数据格式版本分别记录。
- 运行档案：冻结运行所用策略、输入描述、配置和原报告；已有历史结果缺代码来源时写未知，不能用当前 checkout 冒充当时来源。
- SQLite：索引 runs/cases/metrics/artifacts，基于档案重建；不写到 journal.sqlite，不将私人录像加入 git。
- 大文件：保留原位置，以摘要关联。档案包含结果文件，不重复复制录像。标签缺失或仅有后期峰打点，不能计算离心准确率。

证据层级分别是合成测试、缓存经控制器回放、设备录像重新推理、真实训练。层级不是自动晋级；完成处理不是通过验收，计数不是动作标准评分，视觉角度返回区间不是完整肌肉离心真值。

## 开发操作

`npm run vision:batch -- run <job-folder> --replace-running` 完成后自动校验取回、归档和索引；失败/取消有可信任务回执时也归档，并保持命令失败。网络尚未取得可信回执时不能制造失败结果。

历史批次使用 `npm run vision:evidence -- capture <result-folder> --job <job-folder>`；`list --exercise latPulldown --build 23` 可筛选动作/版本，还支持 `--status`、`--kind`。`rebuild` 从所有 run 目录重建索引，原档案校验失败则保留旧索引。默认目录见当前入口，路径可用 `--runs` / `--db` 覆盖。

运行档案冻结 job/status/result/settings 的字节和摘要；原始视频、输入缓存保留原位置，仅通过输入摘要关联，档案不是完整素材备份。归档后仍可离线核对结果，但重做推理或回放需要原输入。新 App 结果带 bundle 内策略快照；旧结果没有该字段时为空，不用当前策略冒充旧策略。所有批次 `acceptance=not_assessed`：处理完成不自动证明准确，后期打点和人工复核仍需独立标签。

`execution.sourceSHA256=null` 表示现有构建尚未嵌入源码指纹，不能由当前 Git 状态补造；保留 app/build/controller/algorithm/config identity。索引面向单一开发写入流程，重建时不要同时启动另一导入命令，不作为网络共享数据库。用户训练/生活记录库未迁移。

修改策略时先改测试，保留旧算法行为；更新契约版本及解释，运行 `test:native`、`python3 scripts/validate-motion-contracts.py`、`test:scripts` 和实际控制器回放。JSON 是描述，不会自行启用新行为。旧动作已有的阈值阶段目标比较保持兼容，不宣称其为完整生理离心评分。
