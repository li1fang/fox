# M4 同视频实验：离线可以计数，现场链路仍待定位

日期：2026-10-17。状态：**真实 M4 iPad 已自动完成同视频处理与设备端 Fox 核心回放；不是模拟器，不是实时相机验收。**

结论：本录像在 Mac 和 M4 上都能完成既有逐次计数目标，未观察到“在 Mac 能算、换到 M4 就算不了”的现象。下一步优先定位实时采集、机位及主 App 控制器，不继续只对旧素材调角度，也不据此换模型或增加深度。

## 1. 实际执行范围

- 设备为已配对的 iPad Pro 13-inch (M4)，iPadOS 26.6.2 / Build 23G90，开发连接为 `localNetwork`。安装并启动独立 `com.whipa.foxposelab`，没有覆盖 Fox / Fox Say，没有要求用户重练或手动点训练。
- 输入为完整 200.366667 秒原 MOV，SHA-256 `48b5913c45da677819ca2e18791865b624518d351ce5592e2d3a051a6fde7d66`。视频通过本地开发通道送到诊断容器，App 内再次校验原文件哈希，不上传外部服务；不读取后期击掌音频。
- 与 Mac 使用同一 `FoxPoseExperimentKit`：10 Hz、精确取帧、原方向变换、最大边 1280、PNG 编解码、Vision revision 1。2004 帧覆盖 0–200.3 秒，尺寸均为 1280×720，时间与 Mac 样本逐帧对齐。
- 在 iPad 上运行现有主体选择、准备门禁及计数器；参数与原 Mac 冻结实验相同。另核对旧 build 10 包内默认参数文件 SHA 与当前源码一致，最新实测报告的参数及 Vision revision 也一致。本轮没有更改角度、时长、缺失容差和主体规则。
- 设备回执 `m4-reference-20261017-r1` 的状态为 `completed`、无 error；从启动处理至完成约 **141.65 秒**。这是整段离线处理耗时，不是实时延迟或实际训练帧率。
- 没有在 M4 上运行 MediaPipe 或 `HumanBodyActionCounter`；本轮只回答原生 Vision + Fox 的跨设备定位问题，不冒充三模型的 iOS 复测。

## 4. 证据边界与定位意义

### 同一坐标重算一致

取回 iPad 完整坐标缓存，在 Mac 再执行同一 Fox 核心。**全部片段的主体/几何诊断、启动状态、逐次事件及重置字段一致**，数值校验容差为 `1e-9`，不是只比较最终次数。这支持本次核心回放没有设备端与 Mac 端语义分叉。

### 同视频不等于已证明同像素

两平台 2004 个 PNG 编码哈希全部不同，可能涉及系统解码、色彩/元数据或 PNG 编码差异。本轮没有保存逐帧图片、也没有逐像素对齐验证，不能声称是“完全相同像素只换芯片”的严格对照。能确认的是原视频 SHA、取帧时刻、尺寸、共享预处理路径和配置一致。当前结果未显示这些平台差异造成计数退化。

### 没有复现现场失败

离线 `CGImage` 路径没有经过实时相机的 YUV `CVPixelBuffer`、采集丢帧、方向/镜像协调、主线程回调、看门狗、实际光线和新机位。最新真人现场仍是不通过；两次离线成功也不抹去用户的“不可用”反馈。

## 5. 下一步有限任务

建议做 **实时链路可观察性与受控对照**，不扩大动作集：

1. 从点击准备就记录诊断，而不是只从倒计时成功后开始存报告。显示/保存是主体未选中、肩肘未达门槛、倒计时重置，还是相机中断；失败也能保存。
2. 在不接真实相机的控制器测试中，把本轮 iPad 坐标按时间注入真实准备/计数控制路径；覆盖方向切换、主线程延迟、掉帧与看门狗，验证离线核心到 App 的接入层。
3. 如果控制器仍通过，下一次正常使用只需自愿留下短失败片段及当时参数/方向。对同一失败帧走实时输入与离线路径，定位机位、关节置信度或采集预处理；不要求为验收加练、摆奇怪姿势或重录整套。
4. 保持人工开始/计数回退可用。修复只在训练间隔进行，待新鲜相机证据后再判断是否换模型/增加深度。

这些是下一轮建议，本轮没有修改主 App、实现控制器注入或现场失败录像功能。
