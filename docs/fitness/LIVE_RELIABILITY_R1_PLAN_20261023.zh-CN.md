# FIT-LIVE-R1：两动作现场可靠性修复计划

日期：2026-10-23。状态：有限修复候选 0.6.3/build 18 已完成自动化验证，并在 iPad 安装、解锁后启动；现场效果待正常训练核对。范围：侧身哑铃弯举（左右臂分别观察）、正面侧平举（左右臂分别观察）；单设备、本地 RGB。任务入口见 [总台账](../planning/LIFE_LOG_BACKLOG.zh-CN.md)，实际修复及分层验收见 [实施记录](LIVE_RELIABILITY_R1_EXECUTION_20261023.zh-CN.md)。下文保留原计划与实施前证据，不将计划要求自动标为全部通过。

## 1. 下一轮要交付什么

用户点开始后能以该动作的正常观察姿态就位，完成 3/2/1；不必先正身再转身，不以双臂或全身可见为前提。可靠观测到完整循环才增加一次；短闪烁不清空已完成次数，长中断不拼接半次，恢复路径明确且不要求重建整组。任何视觉失败均可继续人工记录。

下一轮先交付可重复的控制器回归和一个有限修复候选。对实际相机、动作次数、阶段时长分别报告通过/失败/未验证，不能把安装或旧视频通过写成现场可用。离心节奏是目标的一部分：本轮先建立可信的阶段观测；基于实测的实时提示在 FIT-TEMPO-01 单独验收，不以计数达标推定节奏已达标。

不要求购入 Duo、重录整套标准视频或为了验收额外训练。当前没有 Duo 真机不阻塞本轮。折叠屏、多平台、新动作、深度、多机、ASR/TTS、数字人均不进入本轮实现。

## 2. 事实基线与当前缺口

以下为制定计划时的代码/文档只读快照，当时没有新执行算法实验或真人测试。彼时工程声明版本为 0.6.2/build 17，不据此推断设备当前安装状态；后续候选结果见实施记录。

| 环节 | 已核对的实现或历史结果 | 下一轮要验证的问题 |
|---|---|---|

## 3. 机位与跨设备的约束

**不设设备必须垂直的条件，也没有证据认为垂直更优。** 目标是在日常可放置、关键关节可见的一组机位下识别循环和阶段；支持范围由数据建立。

需要分清四件事：

1. 设备相对重力的倾角/镜头俯仰：现有 `VisionDevicePose` 已记录，传感器缺失为未知，不是零度。
2. 人相对镜头的朝向：弯举侧面、侧平举正面；现有字段是人工标注，不冒充自动测量。
3. 画面尺度、关节离边缘的距离与遮挡：以实际坐标和相机格式记录，不把它们换算成未经标定的米数。
4. 图像横竖方向、镜像及预览投影：属于坐标处理问题，与物理俯仰不同；预览裁切不应偷偷改变算法输入。

二维关节夹角使用身体线段而非屏幕竖线，有利于减少构图依赖，但透视与遮挡仍会改变投影。对坐标作平移/旋转/缩放的合成测试，只验证数学与软件不变性；把旧视频旋转或透视变形，不能视为取得了新机位真值。现有对侧躯干参照中的图像方向约束也须在方向测试中核对，不据此直接放开所有代理参照。

机位矩阵先登记实际观测到的镜头俯仰，并按较低/相近/较高的自然摆放条件分组比较，保存实测值和样本量；具体支持角度范围在有样本后填写，当前为空。旧参考视频没有倾角元数据，保持未知。不要求用户做精确角度校准，不为了测试故意扭曲动作。

算法、数据契约和回归用例可以跨设备复用；镜头、视场、曝光、采样、屏下成像及处理延迟的影响不能由此自动排除。Duo 模拟器布局通过可独立成立，其真实相机验收继续待设备，不阻塞现有 iPhone/iPad 主线，也不提前给 Duo 盖准确率结论。

## 4. 两动作的目标行为

| 项目 | 侧身弯举 | 正面侧平举 |
|---|---|---|
| 启动姿态 | 所选臂靠镜头，直接侧身就位；不要求对侧臂或腿 | 正面就位；不要求脚、膝、腕都可见 |
| 准备与测量分开 | 肩肘支持准备；腕短缺失不能被误称没检测到人，测角仍需新鲜腕点 | 肩肘支持准备；缺少可用躯干参照时明确无法测角，不误称需要全身 |
| 一次循环 | 可观察的放低 -> 上举 -> 顶峰 -> 返回放低；左右不串 | 可观察的放低 -> 外展顶峰 -> 返回放低；按所选侧计数，不把双侧相加 |
| 放低端点 | 初始获取与已观察顶峰后的返回分开；不要求人为锁死肘关节迎合阈值 | 不因放低时腕遮挡拒绝；髋参照不足时保留未知而非沿用旧点 |
| 恢复 | 新鲜的同侧坐标恢复后继续；未观测到顶峰不能补次 | 新鲜同主体躯干参照恢复后继续；代理参照的阶段时长标估计 |
| 疲劳/半程 | 保留半程或不可观察事件，不自动改为完成次数或判断体力 | 同左；不以节奏偏差取消一个已可靠观测的完整循环 |

启动采用现有“准备 -> 稳定 -> 3/2/1”交互。短缺失可以保留准备进度，但在没有新鲜可用输入时不能完成倒计时。必要提示直接说明“所选肩肘不清晰”“尚未锁定训练者”“等待放低”或“相机中断”，不让“骨架可见”代表所有环节已通过。

计数成立是最小可观测循环门槛，不是专业动作标准性或安全判定。`movementTooShort` 当前可能由可靠观测不足产生，不能直接提示“你做得太快”。

## 5. 实施里程碑

### R0：冻结基线，接通真实控制器回放

先记录源码/参数摘要、版本、输入哈希、来源与预期事件，复现现状；复用已有 `PoseFrame`、核心与诊断格式。在 `VisionLabController` 的真实帧处理路径提供最小测试接入及可控单调时钟，正式组通过 `WorkoutVisionCoordinator` 跑相同事件序列。测试入口必须隔离于正常使用，不能把注入数据写成 `source=camera`，不能只另写一份“类似控制器”的计数脚本。

输入分别覆盖合成数据、M4 离线全人体缓存、历史所选关节 trace，以及未来用户已保留的诊断包。只有含所有候选的输入才能测主体选择；仅有计数 trace 的旧报告不补造背景人或准备阶段。真实包消费用户命令/控制事件，离线视频假设的点击时刻单独标注。

分开控制采集 PTS、收到帧的单调时间和保存记录的 wall clock，注入主线程延迟、丢帧、无帧、乱序与旧 capture ID。输出逐条主体/门禁/计数/暂停/保存事件与第一次分歧，不只输出最终次数。测试独立目录不能触碰真人档案。

完成条件：能重现基线门禁与逐次事件，至少为一个已确认规则问题写出修复前会失败的用例；时间相同时结果可重复。若材料不足以复现真实根因，标明缺口，仍可完成合成反例和可观测性，不编造实测结论。

### R1：修首次获取与启动解释

候选规则：单一、满足所选动作准备点的候选不因肩部离开固定中心区域而永久拒绝；中心区域保留为多人时的选择偏好，不能成为隐形的“全身入镜”要求。多人歧义继续拒绝；远处路人、单人但不是训练者的限制须明确，不以单人等于身份正确。

为选择器/门禁输出结构化阻塞原因，区分没有候选、候选在旧获取区外、所选肩肘缺失、多个近似候选、帧不新鲜。新规则的获取范围、置信度、稳定时间和容差统一留在版本化策略中，组内冻结，不新增训练时反复调参的操作负担。

完成条件：左右侧身可直接进入倒计时；近景中只缺无关身体部位不阻塞；持续可用输入在策略规定的稳定时间 + 3 s + 一个采样周期内启动一次；长缺失重置有明确原因，缺失帧不触发开始。通过正式训练和独立视觉页两条入口。

### R2：修逐次计数与分级恢复

按真实分歧一次只改一个问题类别，不批量放宽所有置信度、端点或时长：

- 短关节闪烁：在既定时间窗内保持主体意图和动作阶段；不复用历史坐标计算当前角度，端点 dwell 只由新鲜观察建立，缺失不能满足最短运动时长。
- 已确认放低阶段的遮挡：保留已有专用恢复窗；与“采集根本没有帧”的硬中断分别测试，不承诺 1 s 容差覆盖任何类型的 1 s 空洞。
- 长丢失/多人歧义：丢弃未完成半次，保留已接受次数；提供明确“重新就位”路径，在同一组新建观察段并重新获取，不要求结束整组或重启 App。短窗内可按连续性恢复，长丢失不无限自动重绑路人。
- 相机中断/旋转/后台/旧回调：遵循显式暂停与恢复，不能自动当用户完成；恢复时不跨段拼次数，仍可人工继续。不要为追求无中断改掉已存在的训练保存规则。

动作参数只针对已定位的端点/几何问题变更，保留原配置比较。新语义有独立策略/算法版本与旧报告读取/重放路径，不能用新默认值改写旧报告解释。

完成条件：断点前后逐次事件可解释；恢复后的下一完整循环可计入；无新增跨人、跨臂、跨组、跨中断的拼次，已接受次数不因恢复减少。计数失败时人工更正保留自动原值。

### R3：建立机位对照与可信阶段时间

记录准备、计数和恢复期间的可用机位信息，复用诊断包已有 `devicePose`、`framing` 和 `cameraGeometry`。对同一输入比较修复前后，避免把好光线、换侧或换机位的收益归给算法。旧视频仍作回归，新角度没有数据时保留未验证。

先明确阶段事件语义：顶峰附近到开始持续下放的边界、下放到放低的边界、端点确认等待。现有阈值事件和新观测边界分别命名并版本化；不能悄悄把旧 `lowerSeconds` 改成另一种含义。端点 dwell 不计入动作时长，采集时间负责阶段时间，主线程收到时间只用于延迟/看门狗。

时长质量分为可测、估计、不可评估。遮挡跨越边界、代理躯干参照、追踪重置或采样不足时降级；不因计数正确就报告精确离心时间。先沿用现有保守降级，不为增加“可测”数量假造连续观测。

合成带精确阶段标记的输入，时长误差目标不超过两个输入采样周期；记录采样率与滤波影响。旧视频粗峰/完整循环标签只支持事件对应，不能验证精确离心时长。只在需要验证阶段时长时，对已有可见失败/对照片段补少量下降起止标记，不建专用标注 App，不要求用户标 COCO 关节。

完成条件：正常相位、缺失及控制延迟的时间语义有自动回归；对真实数据能明确“可比较哪些时段”和“哪些未知”。本轮可交付没有实时提示的计数修复候选；阶段时长未通过时 FIT-TEMPO-01 继续保持未启动。

### R4：有限候选与正常训练核对

软件门禁通过后保留构建/参数与数据快照，同 Bundle ID 覆盖更新选定测试设备。安装、启动、布局、真实计数四类结果分别记录；训练进行中不换版本、不调算法，不自动确认或结束用户训练。

不另设“测试保存录像”的人工门槛。用户下一次正常训练时选两动作中的实际计划动作，以自然支架角度使用；可在核对后保留失败或代表性成功片段，再通过已有 `vision:pull` 取回。左右及不同角度逐步积累，不要求一天补全矩阵或为软件多做组。

本地自动回归通过但缺新鲜相机证据时，交付状态为“软件候选通过，现场待核对”；某动作、某侧或某机位失败，按该条件保留失败，不能用其他组正确总数抵消。先接受一个有界改进，避免无限调参；真实问题无法复现时下一步只取最小失败窗口，不扩大到新模型、深度或多平台。

| G01 | 同一可见关节集的平移、等比缩放、图像旋转/镜像约定 | 数学与投影一致；不把此项记为物理倾角准确率 |
| G02 | 真实倾角有值/缺失、未知机位、旧素材 | 缺失保持未知；无“必须垂直”门禁；只对真实已测条件报告效果 |
| U01 | 独立视觉页及正式组，iPhone/iPad 横竖屏 | 状态原因、重新就位、人工继续及完成可用；保持相机完整等比、训练核心操作可达 |
| D01 | 参数冻结/语义版本、旧报告、保存失败、诊断核对 | 旧解释不漂移；失败不写成完成；临时录像事后保留流程不回退 |

现有公开自动化使用合成 fixture；私人视频、完整骨架、真实包和设备标识留在被忽略目录。私人矩阵未执行或素材缺失必须报告未执行，不能把跳过显示为通过。CLI 不覆盖旧输出，候选结果存入独立运行目录。

建议按风险执行已有命令：`npm run test:native`；对应 `FoxAppTests`、`FoxWorkoutVisionUITests` 与视觉 UI 用例使用 `FOX_IOS_UI_TEST` 定向执行 `npm run test:ipad:ui`；动到导入/Schema/脚本时再执行相关脚本回归与 `npm run verify`。私有视频用现有 `vision:video` / `vision:cycles` / `vision:check`，原数值报告用 `vision:replay`。完整控制器回放入口在 R0 实现，当前没有可声称已运行的新命令。

## 7. 交付与停点

每个里程碑保存输入/版本、改前问题、改后事件差异、已跑与未跑条件。R0 不为测试重写整个控制器，R1/R2 每次变更必须对应可复现的阻塞或退化。自动测试一旦覆盖本次修改并通过，就进入候选核对；不在无新证据时反复全量验证。
