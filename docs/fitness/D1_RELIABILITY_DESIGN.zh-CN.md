# D1 可靠性修复：参数、连续性与回放

日期：2026-10-05。范围仅为侧身弯举、正面侧平举；不扩展 D2、3D、通用速度识别或新模型。

本文保留 v2 修复与验收的历史设计。后续完整视频、独立主体选择及 v3 端点/就位策略见 [D1 视频回放](D1_VIDEO_REPLAY.zh-CN.md)；v2 回放路径不随 v3 默认策略漂移。

## 问题与证据

Fox 0.3.3 的真人报告：弯举自动 5 次、94 次计数中断，用户说明正常侧身不计数，异常姿势偶尔计入；因此不是 5 次正确识别。侧平举实际 5 次、自动 4 次，此后持续无法识别。约 10 Hz、Vision P95 约 13 ms，没有明显推理卡顿证据。旧 11 次案例不能作为当前版本验收。

已确认：单帧无效立即清空半次动作；侧平举依赖不参与肩角计算的腕部；固定门槛散在几何、计数、报告验证中；1 Hz 概况无法解释 100 ms 闪烁。未确认：正常侧身究竟缺哪个点、是否到达固定角度、误计的确切原因。不要凭这些汇总推导识别精确率或逐次漏计原因。

## 调研与取舍

- [MediaPipe iOS 官方指南](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/ios)：检测、存在性、追踪置信度分开配置，video/live-stream 使用时间戳和追踪。借鉴层次划分，不在本轮引入新的推理框架。
- [MediaPipe One Euro Filter 源码](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/util/filtering/one_euro_filter.h)：为抖动/延迟提供可调滤波参数。此轮仍用时间感知 EMA，先修丢点语义；有回放依据后才比较 One Euro，避免同时换滤波和计数。
- [flexible-rep-counter](https://github.com/aitrainerteam/flexible-rep-counter) 的 [配置](https://github.com/aitrainerteam/flexible-rep-counter/blob/main/rep_counter.toml) 和数学引擎：集中管理滞回、范围门槛、校准与调试事件。只借鉴配置/诊断结构，不复制其算法、远端推理地址、自动换关节或通用动作承诺。未在目标 iPad 验证该项目，不能称其精度优于 Fox。
- [QuickPose FitCount](https://github.com/quickpose/FitCount)：可参考原生运动计数交互，但示例依赖 QuickPose SDK/key，不等于完全开源的识别引擎，本轮不接入。

以上是源码/官方文档层面的借鉴，不是第三方精度测评，不下载或运行外部项目代码。

## 四层结构

1. `PoseCounterConfiguration`：版本化 JSON；公共追踪策略 + 两个动作的角度档案。默认文件为核心包资源，iPad 本地覆盖可验证、恢复、导入/导出；开始准备后冻结参数。没有通用插件图或脚本求值。
2. `PoseGeometry`：仅根据当前帧和档案产生角度、置信度、缺失关节/退化原因。弯举用肩肘腕；侧平举用肩肘髋，腕仅供诊断，不阻止肩角计数。绝不沿用旧坐标计算新角度。
3. `CurlTracker`：保留兼容名称。追踪状态 acquiring/tracking/grace/lost 与动作阶段独立。短暂丢点保留动作阶段；缺失时不推进端点确认，不用插值补次数。恢复需经过新鲜几何、位置/角度连续性校验；连续坏点超过窗口、多人、暂停/旋转/后台立即作废半次。
4. `PoseCounterDiagnostics` / `PoseReplay`：数值观测与控制中断进入有界记录，记录原因、原始/平滑角度、状态和次数；相同核心负责实时与离线回放，禁止独立的第二套计数代码。

## 参数与行为

初始候选：获取置信度 0.55、维持 0.45、短暂缺失 0.30 秒；按最后接受帧到恢复帧的总间隔判定，不按固定帧数。帧间断超过 0.40 秒仍硬重置。单帧角度/锚点尖峰先隔离，不立刻清空；持续尖峰超时后重置。运动角度和去抖默认沿用 v1，先不凭空放宽角度。

置信度滞回只在已有连续追踪时生效，新获取必须达到获取门槛。端点确认遇到缺失重新计时；上举/下放最短观测时长不能由缺失时间凑够。已跨越完整循环且存在短缺失时，报告单独保存 `trackingGapSeconds`，界面标记阶段时间约略，不能称为精确节奏。没有看到顶峰就不补一整次。

左右臂固定，不自动换臂。锚点连续性是位置校验，不宣称生物身份持续跟踪；同位置换人的不可辨识性仍是限制。不能靠扭曲动作迁就软件，更不把计数当动作安全判定。

## 诊断与数据

新增可选 `counterDiagnostics`，新算法绑定 `curl_2d_v2` / `lateral_raise_2d_v2`。原 v1 记录仍按原门槛读取，不重算或补写历史数据；档案容器仍为 v1。

只改参数值无需升算法版本，完整快照区分实验。以后改算法语义时，必须保留旧版本验证/回放路径，再增加新版本，不能直接改当前算法名使旧记录失效。配置增加字段也要保持旧配置解码或做显式版本迁移。本轮仅保证新应用读旧报告，不支持旧应用降级读取 v2 报告。

诊断默认启用，可在准备前关闭。只在用户保存报告时落库：所选侧肩/肘/腕/髋归一化坐标及置信度、图像尺寸、人数、相对时间、原始/平滑角度、动作/追踪状态、失败原因、累计次数、显式中断事件。不含人脸、视频、照片、音频或姓名，不上传。不保存另一侧或完整骨架。诊断数值仍属于个人运动数据，分享 JSON 会包含它们。

上限默认 6000 条，超过后累计 droppedSamples；截断记录不能作为完整回放验收。暂停/恢复必须写控制事件，回放不得跨越暂停拼出完整动作。算法版本和完整参数快照随报告保存；日后改默认文件不影响旧报告解释。旧 1 Hz 报告无法逐帧回放，明确报不支持，不能伪造输入。

## 可调试入口

iPad 参数图标打开参数表单：获取/维持置信度、容错窗口、动作端点角度、诊断开关，以及完整 JSON 编辑和导入/导出。应用前验证有限数值、范围、阈值顺序和时间约束；错误配置不覆盖当前配置或文件。训练/准备期间不可修改，报告保存后可以继续迭代。损坏覆盖文件保留并显示错误，不静默声称加载成功。

桌面 `npm run vision:replay -- <report-or-archive.json> [configuration.json]`，输出原次数、同配置回放次数、候选参数次数、重置原因及回放是否完整；不改原档案。仅更改配置不能证明动作安全或模型泛化，回放不等于新一轮真人验收。

## 验收矩阵

先写测试，再落实现：

- 理想轨迹、左右臂、横竖宽高修正、静止/半程/尖峰不误计。
- 单帧/两帧闪烁在上举、顶峰、下放和底端不立即丢弃整次；连续端点确认仍须新鲜观测。
- 超时缺失、多人、换位、暂停、旋转、重复/倒序时间不能跨段补数。
- 获取/维持置信度滞回；单点异常与持续异常；腕缺失不阻止侧平举，髋退化仍拒绝。
- 未观测到顶峰不补数，缺失不能替代最短运动时长；阈值时间全按秒。
- 参数合法性/保存失败/坏文件保护；报告参数冻结、旧报告兼容、来源隔离、数值记录容量及确定性回放。
- 原生 UI 参数应用/锁定/恢复、带闪烁的计数/保存/重开；训练主流程回归。

软件验证通过后才安装候选版本；真人在固定机位分别做弯举和侧平举、填写人工参考及漏计/误计备注。默认参数是待实测候选，不因自动化通过宣布正常侧身弯举已恢复。
