## 两条独立回放

### 主体选择

Mac 用 Apple Vision revision 1，以 10 Hz 提取 2004 个全画面样本，保留所有检测对象和当前坐标。按视频方向处理并等比缩放完整画面，横向素材为 1280×720；音轨不进入识别或计数。

`PoseSubjectSelector` 独立于角度计数：从可配置就位区域获取肩部锚点，之后按位置连续性及可用的躯干尺度匹配，不依赖每帧 observation 数组次序。白色骨架保留所有检测对象，绿色仅表示当前选择。

不明确时不选择。短暂缺失保留绑定意图，但不复用旧坐标；超过 1.2 秒进入 `lost`，必须人工“重新就位”，不把路人自动接入同一组。相机/后台中断暂停计数，不能隐式自动重新绑定。

本视频 A01/A03 全段保持绑定，A02 和退出段在主体离开后转为遮挡/丢失；两个负例窗口计数均为 0。7、30、60、90、120、133、150、180 秒的视觉复核肩部区域检查均对应前景训练者。

这是稀疏视觉检查点及负例测试，**不是逐帧身份真值**。位置/尺度匹配不是声纹、人脸或生物身份识别；同位置、近似体型的替换和严重交叉遮挡仍可能不可辨识。今后优先增加这种失败样本，而不是删除路人。

### 动作计数

同一帧缓存分别进入：未选主体的 v2、选主体后的 v2、选主体后的 v3；使用同一个 `CurlTracker` 核心。离线轨迹计数刻意绕过启动倒计时，单独记录 `firstReadyAt` 和 `countdownReadyAt`，避免把“录像第一下已开始”混成计数失败。

每次 v3 计数记录开始上举、首次顶峰、下放端点和完成确认时间。事件报告区分一个标签对应、未匹配预测事件、跨多个标签合并以及遗漏标签；全在原视频时间线上。阶段时间不等同击掌时间，也不自动纠正后期声音偏移。

主体选择测试使用所有人的全骨架缓存。计数测试使用所选人的新鲜坐标。iPad 正常保存的试验报告仍仅记录所选侧肩/肘/腕/髋数值，同时增加原始人数、当帧选择索引及绑定状态；不会突然保存人脸或相机视频。

## 候选修复及参数

- **启动**：点击后等待所选侧肩、肘稳定；不要求对侧手臂、腕和髋同时可靠才启动。3、2、1 中最多容忍 0.35 秒短缺失，不能在缺失帧完成倒计时；长缺失重新就位。允许开始不代表随后每一帧都可计数。
- **初始放低**：归一化底端容差 5°，弯举初始获取约 145°，侧平举约 25°。必须观测稳定端点，不允许从顶峰直接拼一次。
- **弯举下放**：从已观测顶峰返回时，额外容差 10°，约 135°；与初始获取分开。下放确认 0.10 秒，必须至少两个新鲜时间样本，不能用单帧尖峰成立。原顶峰确认仍为 0.18 秒。它是次数判断，不声称完整生理活动范围或动作规范。
- **遮挡恢复**：只有已确认放低且尚未开始新一轮上举时，最多保留阶段 1 秒；正在上举/顶峰/下放的缺失仍为 0.30 秒。不能用缺失时间满足最短运动时长，也不能补看不见的顶峰。
- **大中断**：帧间隔超过 0.40 秒、主体永久丢失、暂停/切后台会中止半次；保留已完成次数。明确重新就位后重新确认放低。

核心资源 `pose-runtime-defaults.json` 集中主体/启动/端点策略；原 `pose-counter-defaults.json` 仍描述基础几何与追踪。iPad 参数页支持这两类设置、完整 JSON 导入/导出和恢复默认；组合参数一次校验、一次原子保存到 `pose-session-settings.json`。旧 `pose-configuration.json` 作为首次迁移的读取来源，不改写旧文件。

参数在准备/训练期间锁定，每份 v3 报告冻结两类快照。改变语义后算法名为 `curl_2d_v3` / `lateral_raise_2d_v3`；v2 报告没有新 runtime policy 时仍走旧路径，不能以新默认重解释历史数据。

如果旧版自定义角度与新容差冲突，迁移时保留旧角度、将新容差设为 0 并明确提示，避免合法旧配置触发启动崩溃。修改后的组合参数不合法时拒绝应用，而不是偷偷夹紧角度。

## 开发复现

在项目根目录运行；提取需要 macOS Apple Vision 与完整 Xcode，私有视频不放入公共 CI：

```bash
# 新素材归档：校验过的草稿清单必须有来源哈希；已有素材不用再次移动
npm run vision:corpus -- --source /path/reference.mov --draft /path/review.json --id reference-02 --move

# 仅首次提取；输出已存在时拒绝覆盖，变更提取器须使用新缓存名
npm run vision:video -- extract .data/vision-corpus/20261005-fox-fitness-reference/manifest.json .data/vision-corpus/20261005-fox-fitness-reference/mac-vision-10hz.jsonl

# 重用缓存；可另传 configuration.json 和 runtime-policy.json 比较，不改原素材
npm run vision:video -- evaluate .data/vision-corpus/20261005-fox-fitness-reference/manifest.json .data/vision-corpus/20261005-fox-fitness-reference/mac-vision-10hz.jsonl .data/vision-corpus/20261005-fox-fitness-reference/replay-v3.json
npm run vision:check -- .data/vision-corpus/20261005-fox-fitness-reference/manifest.json .data/vision-corpus/20261005-fox-fitness-reference/replay-v3.json

# 原生、界面和工作区回归
npm run test:native
npm run test:ipad:ui
npm run verify
```

`vision:check` 的退出码：0 仅表示本素材的全部顶峰标签/事件门禁通过；2 表示部分未通过；1 表示缺失、错误来源或输入损坏。即使返回 0，也不是 M4 实时、动作质量或泛化验收。

回放绑定视频哈希，报告还记录缓存哈希、平台、Vision revision、采样率、参数快照及所有事件。拒绝重复/倒序时间、过大采样缺口、截断缓存、重复关节和错误哈希。缓存只从图片采样；击掌声音没有输入通道。

## 后续验收与边界

先用已安装 Fox 0.3.5 / build 8 在 M4 做固定机位、先就位后动作的短验证，分别填写人工次数与漏/误计位置。优先看 A03 左臂首次低置信度、底端遮挡；不建议增加重量或扭曲姿势让软件计数。需要补视频时只补失败窗口，不要求把第一份全部重录。

先稳定两个动作，再每次增加一个候选。视觉适配库、正常训练计划不是同一个集合：无法可靠追踪的动作仍可人工记录，不因此删除背、腿、胸或核心训练。

当前 M4 通过局域网完成设备查询、报告导出及安装；不要求日常开发一直插 USB 或解锁。写代码、构建、Mac 视频回放和模拟器测试不占用 iPad；安装/启动调试时按系统提示短暂解锁。已安装的 Fox 可独立离线运行。切后台/锁屏会暂停相机，不在看视频或其他应用后台继续计数。[Apple 无线运行说明](https://help.apple.com/xcode/mac/current/en.lproj/dev3e2f4ee6d.html)

建议视觉库先以 4–6 个有用且可靠的动作作为阶段目标，属于工程范围选择，不是完整健身处方。健身计划应覆盖主要肌群，而非只练“软件会数”的部位；成人肌力活动的一般建议为每周至少两天覆盖主要肌群。[CDC 成人活动建议](https://www.cdc.gov/physical-activity-basics/guidelines/adults.html)
