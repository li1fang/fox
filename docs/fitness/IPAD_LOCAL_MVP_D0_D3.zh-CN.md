## 产品目标

训练时少碰屏幕，训练后得到可信、可纠正的记录。目标设备为 iPad Pro M4，核心训练不依赖 Mac、Linux、互联网或大模型在线。

代码问题集中记录、定期修复和测试后发布。计划在几次训练后复盘调整；组间仍允许手工改重量、延长休息、跳过和结束。

## D0 实现规格

- Fox 使用 SwiftUI 原生界面；`com.whipa.fox` 启动不读取 `FOX_WEB_URL`，不实例化 WKWebView，不请求 LAN。
- Fox Say 保持独立 `com.whipa.foxsay`，现有语音实验入口不受这次迁移影响。
- 使用独立 Foundation/Swift package 保存可测试的模型、状态推进、时间计算和文件持久化。
- 计划可以手动编辑动作、组数、次数/时长、重量、休息；支持导入现有 `WorkoutPlan` JSON。内置模板需要用户确认，不调用 AI 自动处方。
- D0 仅人工确认次数；节奏动画是目标提示，不能作为完成次数。D1 后才出现视觉观测次数。
- 训练状态：`ready -> active -> feedback -> rest -> ready`，最后进入 `summary -> confirmed`；支持 `paused` 和提前结束。
- 实际时长通过时间戳计算。训练切入后台时暂停当前组，休息倒计时按截止时间继续计算；重开训练需明确继续。
- 每次状态变化原子保存到 Application Support。保存失败保持原状态并明确报错；损坏文件不能静默覆盖为空数据。
- 组记录包含计划目标、实际次数/重量/时长、反馈、计数来源、开始/结束时间；总结保留跳过和提前结束。
- 历史和未完成训练都在本机保存。总结确认前可更正组记录，实际计时不需手填。导出 JSON 通过系统分享面板交给用户。
- Mac 上原有 SQLite 记录保留；D0 不自动迁移历史、不重复生成服务器 Entry。原生导出使用独立版本号，后续同步需明确映射和去重。

## D1–D3 边界

视觉先由用户选动作，系统只计这个动作。先二维关键点，不做深度、LiDAR、多机视频传输或全动作自动分类。视觉性能和准确率由 M4 真机测量，不由芯片规格推断。

不从单视角判断重量、肌肉收缩或医学意义上的动作安全。目标节奏与实际观测节奏分别保存。丢失关键点时停止新增计数并显示状态，保留人工加减纠正。

语音和大模型在线对话暂缓；Fox Say 成果保留。后续优先短句提交与确认、固定播报、训练后复盘，不把实时通信加入核心训练依赖。
