# 视觉诊断录像与取回 V1

日期：2026-10-17。实施范围：Fox 临时无声录像、核对后保留、启动失败诊断、手动文件导出及本机开发通道取回。不做剪辑器、峰谷标注界面、通用同步、云上传或新计数算法。

本轮用户更正：0.5.2 的「开始前启用录像」不符合需求。改为 0.5.3：不要求事先预判是否出错，先临时缓存，完成/取消后核对，再决定保留或丢弃。下文以此更正后的流程为准。

## 使用与证据

普通预览不录像。点击视觉开始/就位时自动临时缓存，启动条件尚未满足也记录；相机不可用时可缓存零帧故障元数据。结束、取消、离开、后台、相机异常或达到上限均整理成临时片段，不伪造视频或训练组。没有每组开始前的录像开关。

核对训练结果时可打开「核对本次录像」，用普通播放器回看，然后选「保留诊断」「不保留」或稍后。保留才移到 Documents 的正式诊断目录、允许导出/开发取回；不保留只删临时片段，不改训练次数。成功的组也同样可以选择保留，不自动判断好坏。

每个 UUID 目录独立保存：

- `context.json`：时间、动作、观察侧、相机、声明朝向、App/设备、Vision revision、完整计数配置；不混入饮食、财务或其他训练历史。
- `video.mp4`：与 Vision 共用相机输出的未叠加画面，H.264、有损、无声音；不裁主体。不是逐像素原始视频，也不是屏幕录制。
- `frames.jsonl`：相机帧时间、编码接收/丢弃、尺寸；`poses.jsonl`：本次关键点、选择状态、启动状态、原始自动次数和方向。准备阶段也记录。
- `events.jsonl`：准备、开始、暂停、取消、看门狗、相机状态与结束原因，区分采集 PTS 与主机 uptime，不假装两个时钟完全相同。
- `manifest.json`：封存状态、文件尺寸/SHA-256、视频首帧采集 PTS、末帧 PTS、帧数和丢帧统计。新包含 `storagePolicy=temporary-until-review`；只有用户选择保留后才写入 `retainedAt` 并进入可导出目录。缺少保留决定的新包不可通过 Mac 导入校验。

视频时间以第一份被编码接收的采集 PTS 为零，姿态行保留采集 PTS 和对应视频秒数。解码重编码会影响像素，不以视频回放相同证明实时路径相同。诊断失败不改变原有训练状态/计数，不自动确认完成。

上限：5 分钟、200 MiB 媒体；起录前至少留 512 MiB 空间。临时目录位于 Library/Caches，系统也可能清理；App 在刷新时清理超过 24 小时、最近 10 段之外或总量超过 512 MiB 的临时片段，不清理已保留包。方向/尺寸变化停止该段并说明原因，不把两种画面几何混进一个视频。录像会增加处理负担，记录帧间隔、编码丢弃与 Vision 耗时；软件测试不替代 M4 正常相机下的负担评估。

## 导出与传递

手动：核对并保留后，在「已保留」列表选择「导出到文件」，复制整个 UUID 目录。用户可通过已有文件提供器传递；需要 AirDrop 时可在系统「文件」压缩目录后传递，Mac 解压后导入。取消导出不删除本机原件，删除必须明确操作。

开发通道：`npm run vision:pull` 从已配对 iPad 的 Fox 容器取回最近已保留包，不取临时目录；支持指定 ID。无需部署服务器，无后台监视、无自动外发，不申请局域网权限。它只是开发期显式拉取，不是 CON-01 增量同步，不承诺锁屏/断线仍可取回。

取回/手工导入均先验证清单、路径、尺寸和逐文件 SHA-256，再以 UUID 原子落到 `.data/vision-diagnostics/inbox`。重复包幂等，相同 ID 不同内容拒绝。传输中断只留下非正式暂存，不覆盖已接收包；首版重新拉取，不做大文件断点续传。原件不会因取回成功而自动删除。

下一步人工标记先只用现有视频工具标峰；标记应引用视频 SHA 和视频时间轴，算法输出不当成人工真值。谷的增益另行验证。

### 实际命令与人工交接

```sh
# Mac 在已配对 iPad 可访问时主动取回最近已保留包，不需 App 内手工发送。
npm run vision:pull
# 指定一份；失败不会删除设备原件。
npm run vision:pull -- --id <UUID>
# 通过「文件」/AirDrop 收到的目录（如为 ZIP，先解压）。
npm run vision:import -- /path/to/exported-UUID-folder
# 只有开发自测才使用，结果保持 fixture，绝不冒充相机样本。
npm run vision:pull -- --fixtures
```

成功输出 `received-and-verified`、本机目录、来源及有无完整视频；重复输出 `already-received`。目录为 `.data/vision-diagnostics/inbox/<UUID>`，可直接交给本机开发者读取。文件校验通过不等于真人计数正确；没有视频的失败包也可以接收，但明确标成 `videoAvailable=false`。

核对后点「保留诊断」，可以只告诉开发者“已保留”，由开发者执行取回；只结束录像但未决定保留时，Mac 不会取回它。这不是自动常驻监视，Mac 关机、未配对、断线或设备安全限制时仍需恢复连接。无需先完成 CON-01 的双向同步、账号、冲突解决与删除传播。

如使用外部工具标峰，请保留这份原包不改，把标记或带击掌的派生副本另存。沿用原视频时间轴；如裁切头部，需同时提供起点偏移。首版不要求人工重写关键点、补谷或凭记忆填写参考次数。

## 自动验收目标

1. 无开始前开关，视觉尝试自动临时缓存；未选择保留不进入导出目录。准备无法启动/零人物/零帧也能事后保留故障诊断。
2. 合成帧编码、首帧时间映射、无音轨、尺寸变化、后台结束、写入错误、重启残留都显式可观察。
3. 录像不会生成正式训练记录或更改计数参数；既有计数/人工回退测试保持通过。
4. 核对后保留、丢弃、临时过期清理不改训练数据；手动导出取消不丢原件。Mac 校验拒绝损坏、缺文件、路径穿越、符号链接、未封存及未保留的新包，重复导入不覆盖。旧版 v1 缺少保留字段时标为 legacy，不冒充核对后决定。
5. 真机先用明确标为 fixture 的无相机 smoke 验证编码/取回，不冒充真实相机、真人训练或性能验收。安装前备份既有训练档案，安装后核对。
